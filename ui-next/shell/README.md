# `ui-next/shell/`: the window frame

The shell's window header holds Back and Forward, the tab strip, the active page's optional scope faces, and window actions. Below it, the rail and sidebar sit beside the page island. The page host fills the island; the status bar sits below the frame. The shell is **plugin-agnostic**: registrations describe a page's scope and navigation, and the tab model supplies its tabs. It uses kit parts where available and local CSS Modules for the frame.

The New tab menu and All tabs menu are not built. Search opens the command palette (`ui-next/shell/palette`).

## The tab model and the strip

`core/tabs/` is the framework-free model (its own README): a tab is a route plus restorable state; the model decides where a destination opens, what a tab is called, a tab's history, which pages stay mounted. React only draws the answers: `tabs/` holds `TabStrip` and `Tab` (the strip), `PageHost`, `NavButtons`, the slice hooks (`hooks.ts`: one hook per consumer, so a tab's title changing renders that tab and nothing else; `renderCounts.test.tsx` is the guard) and the chords. `Shell` takes the store: `<Shell registration tabs renderPage empty onChoose onNewTab>`.

- **The strip** is a roving `tablist` "Open tabs" with one tab stop: arrows move the focus and select nothing (they wrap), Home and End jump, Enter and Space select, Delete and Backspace close and hand the focus to the neighbour; a middle click and the close control close; Command or Control with W closes the tab on screen, with 1 to 8 jumps, with 9 goes to the last, and Control Option does the same where a browser keeps the first for itself (S41, S47). Faces share the strip equally, 208 px at most, down to 96 px; then the scroller scrolls (wheel, trackpad) with no bar and no overflow menu. A resize reveals the focused tab, or the selected tab when focus is elsewhere. A face's width does not follow its title (S17a): the head gives way with an ellipsis, the tail keeps its end, and the tooltip names the whole identity. A tab says its scope only when another tab would read the same, using the shortest text that tells them apart. `probes/strip-probe.mjs` compares the unscoped strip to the baseline at 1, 2, 5, 6, 8, 12 and 30 tabs and checks the room for the selected tab with long scope values at 1440 x 900 and 1280 x 800.
- **The close control is the pointer's**: it is `aria-hidden` and not a tab stop, because a tablist owns tabs and nothing else (axe `aria-required-children` names a button inside it as not allowed). The keyboard and assistive technology close a tab with Delete, the chord, or the context menu.
- **The new-tab control** (`+`, 4 px after the last tab) opens a new tab at the home page of the plugin on screen (the host's answer). The mock's opens a menu of plugin entry points (S34); the menu is not built, so this is the simplest action that does what the control says.
- **Back and Forward** (30 px, a 20 px glyph) walk the history of the tab on screen (S50); `aria-disabled` with the reason when there is none. The mouse's side buttons, the chords and the list of the last ten titles are not built.
- **The page host** draws each mounted tab's page in a slot of the one `tabpanel` (labelled by the selected tab) inside React `Activity` (HSH-21, MNR-K1): a hidden page's effects are released (no timer, no subscription), its renders wait, the browser does no layout and no paint for it (`display: none`), and its state and DOM stay. The default policy is five pages, the one on screen and four hidden (`DEFAULT_KEEP_ALIVE`: a placeholder, not a measurement); a tab past the cap is unmounted and drawn from scratch when it is shown again. A page is drawn from scratch when its key changes and when its tab is reloaded: the key is the tab's place by default (`pageKey`, KL7: a new route is a new page), and a host whose page keeps part of its route in its own state gives a key without that part, so a change of it alone leaves the page mounted with what it keeps in state and gives `renderPage` the new location. Keep-alive is by tab (`state.mounted`) and the tab's page memory by tab and history entry, so neither depends on the key. A hidden page's own scrollers keep their offsets (measured, both engines); the tabpanel's own offset, shared by every tab of a `document` layout, is kept per tab by the host. `content-visibility: hidden` was measured too: it keeps offsets as well, but it does not release effects, so it is not used.
- **The status bar's path** is the model's breadcrumb for the tab on screen. A parent with a route opens through the tab model. Text-only parents and the current page are not controls.

## The registration: the seed of the contribution contract

A screen hands the shell plain data, `ShellRegistration` (`registration.ts`), as a prop. The shell reads it and never writes back; a plugin never reaches into the shell's DOM (ch16 S1). What a tab is called and where it sits (title, glyph, path) is not in it: it is the tab model's, which asks the plugin (`Contributions.describe`).

**Where the shape meets the plugin.** A plugin never imports the shell: its bundle exports plain data (`contributionV1`, `ui-next/plugins/contract/v1.ts`) and the host builds both the registration and the model's `Contributions` from it (`ui-next/plugins/host/`); a drift is a compile error there. The page's data hook runs in its tab's own component; what it returns as `frame` (tab, path, scope) is published for the tab's description and the lane. One data hook per page (docs/ui-next/optimisations.md MNR-T8).

## Layout shift

While a plugin loads, `pending` reserves its rail and sidebar, with the same busy `nav` the tree will occupy. Scope is different: the header mounts the group only when the page contributes faces. A scoped page, an unscoped page, and the loading state all start at the same top edge and use the same island height. Restoring a session shows its tabs in the first frame; the rail and sidebar remain `held` until every plugin has settled once. The strip probe samples the frame throughout these transitions, including a saved tab whose plugin never arrives.

## Regions

Every region is a landmark with a name, in reading order. `F6` and `Shift+F6` visit the regions that have something to focus; `Escape` from any other region returns the focus to the page (ch16 S12). The DOM says which: `data-shell-region` marks a region, `data-shell-focus` the element in it that takes the focus.

## The core

`core/` is framework-free and holds every decision a renderer would otherwise make; React only draws the answers. `tree.ts`: which rows are visible, which row holds the tree's one tab stop, what a key does (the WAI-ARIA tree view keys). `regions.ts`: where F6, Shift+F6 and Escape go. `chords.ts`: which key event is a tab chord. `title.ts`: where a long title is cut (head and tail, as the mock's strip does). `tabs/`: the tab and open model. Not built: type-ahead, PageUp and PageDown, windowing of a large tree, chunked expand-all (docs/ui-next/optimisations.md LIB-10 to LIB-15).

## Decisions to confirm

1. **The rail is the window's, one entry for each plugin that contributes** (S2a). The mock's chapter says the host has no rail and a plugin may bring one (S7, A11, L4a); the owner asked for a rail that reaches every plugin, so the 40 px track holds one entry for each plugin and a choice shows that plugin's sidebar. It closes no tab: tabs of several plugins stay open, and activating a tab makes its plugin current. The host's own entries (Home, Plugins, Settings, Developer Tools) have no destination yet and are not drawn; they would lead the rail. **A plugin that did not load has an entry too, after the others** (S3a: a window with nothing saved opens empty, and a failure that only a page names would never be seen): the error glyph, named `<name>, did not load`, the cause in its tip (`ShellRailEntry.problem`, shown by hover and by focus and read by a screen reader); it has no sidebar, so choosing it opens the plugin's page in a tab (the named failure and its Retry) and the current entry and the sidebar stay. The glyph is 20 px in a 30 x 30 face (ch12 section 4, the mock's AWS rail); the mock's rail on its first plugin screen draws 16 px (`H.ibtn small`), one of the disagreements for the errata pass.
2. **The top row keeps its leading 156 px and trailing 138 px** for window controls, navigation and window actions. An unscoped page leaves the entire intervening width to the strip and drag lane. In the native window the OS supplies the controls; the browser shows the inert stand-in (`core/native.ts`).
3. **Only scope faces with a picker are buttons.** Each keeps its own keyboard stop and opens a listbox; faces without a picker remain readable text.
4. **Choosing a tree entry tells the host which one** (`onChoose(id, event)`: a click, Enter or Space on an entry, never a group). The host opens it through the model: a plain click is a smart open (a tab that shows the page is shown; else the tab on screen is navigated when it is the same plugin and scope; else a new tab), Command or Control a background tab. The page that opens registers with that entry as `current`, and only then is it selected.
5. **The page's scroll owner is the `document` layout by default** (ch16 S15); a page that owns its scrolling declares `layout: 'pane'`.
6. **The page region is a tab stop** in the `document` layout (the tabs pattern, and axe's `scrollable-region-focusable`).
7. **No focus ring on the island**, as in the mock.
8. **A tree row is named by its text** ("Entry 89"), which axe's `label-content-name-mismatch` asks (WCAG 2.5.3).
9. **Window drag regions** (S5) are declared with `--wails-draggable`; the native drag is not verified (no native run of S1b).
10. **The sidebar is 244 px, fixed**: no splitter, no collapse.
11. **The window never writes the address.** `#/<plugin>/<page>?connection=<id>` is an input: a deep link at load (the window waits for its plugin; it opens no page of its own) and a hash typed later; each opens a tab through the model. Where the window is, is the tabs' (each has its own history).
12. **Keep-alive policy**: five pages, unsaved tabs exempt, `Activity` (see above). The old shell kept every shown tab mounted with no cap (HSH-21).

## The bottom panel

The panel is the window's fourth row: the grid is `40px minmax(0,1fr) 5px auto 32px` (top row, island, the splitter's 5 px gutter, the panel, the status bar). Its state is `core/panel/` (see its README); the UI is `panel/`, a reader of it. `Shell` takes an optional `panel: PanelBindings` (`panel/host.ts`): the store, how a session's body is drawn (`renderBody`), what its card says (`cardOf`), how a tool starts a session (`newSessionOf`), and how a resource link opens (`linkOf`). The shell knows no plugin and no address grammar; the product's `PluginHost` supplies all five from the plugins' contributions (`plugins/host/panel.ts`). With no `panel` the window has no region, no handle and no toggle.

- **The host draws the chrome** (tool tabs, session tabs with head and tail truncation, the close control, `+`, the empty states, the card); **the plugin draws the body** and says what the card says. A body is mounted when its session is first shown and stays mounted until the session closes or its plugin leaves; a hidden panel or a hidden session is `display: none`, so it lays out and paints nothing while its state and its streams go on.
- **Resizing** costs next to nothing by construction (`panel/splitter.ts`): a drag writes the panel element's own `block-size` once per animation frame, reads nothing per frame (the limits once, at pointer down), never writes a custom property or anything on the document root, marks the shell window (not `<html>`) with `data-resizing`, and commits the model once, on release. Escape or a cancelled pointer puts the size back. The committed size is one custom property, `--_size`, on the panel element; the stylesheet's `clamp()` is the twin of `core/panel/height.ts`. The keys are the splitter's: Up grows, Down shrinks (16 px, 64 with Shift), Home the minimum, End the maximum, Enter and a double click the default.
- **Keyboard**: the status-bar toggle (Cmd/Ctrl+J, or Ctrl+Alt+J in a browser tab) is a tab stop in the status bar's toolbar; hiding returns the focus to the page. The panel is the F6 / Escape region `panel` (`data-shell-region`); its tool strip is the one stop (`data-shell-focus`), then the session tabs and the body. Tool tabs and session tabs share the tab-list contract of the page-tab strip (`core/tablist.ts`, `tablist.ts`). Cmd+W (Ctrl+Shift+W elsewhere, Ctrl+Alt+W in a browser tab) closes the session when the focus is inside the panel; the panel listens in the capture phase so the page-tab close chord does not also fire.
- **The card** is the kit `HoverCard`: on hover and on focus of a session tab, in place of a tooltip. `Shell` mounts the one `HoverCardHost` per window, only with a panel. jsdom has no Popover API: `ui-next/test-setup.ts` gives it the two methods the host needs.
- **Short panels and long names.** Under 177 px of panel height (the minimum is 120) the empty state lies in one row instead of a column that would be cut in half. A session tab is cut where the mock cuts it: the last `/`, `:` or `-` when the tail from it is short, else the midpoint (`core/title.ts`, `SESSION_RULE`), so a generated suffix such as `-f8q4m` stays whole. Opening the panel makes the tool on screen the user's, so a tool a plugin registers later never takes the panel from them by sorting first.
- **Not built yet** (listed in `docs/ui-next/status/P1a.md`): maximize, the options and target menus, the vertical tool bar, badges, singleton tools, the key hint of a card the keyboard opened, (its saving and restoring are `session/`, wired by the host).

## The session

`session/` (its own README) saves the tabs, the rail's choice and the panel as one versioned document through the host's window service, and restores them before the window draws. **The window opens no page by itself** (decision A17, S3a): a saved session brings its tabs back, and with none the window is empty, with the home content and the plugins that can be opened. Not saved, on purpose: scroll positions, selection and search of a page, the sidebar's open groups, the closed-tab list, and the state and output of a panel session (a restored session is `ended`). The open groups are the window's for its life, though: a plugin that stops and is loaded again, or a rail that goes to another entry and returns, shows its sidebar as the user left it (`core/tree.ts` `TreeMemory`, held by `Shell`; S3, demo finding D5), and a restart of the window starts with the groups closed.

## The command palette

`core/palette/` (its own README) is the model; `palette/` draws it. The top row's Search control (`Search.tsx`, `⌘K` or `Ctrl+K`); the surface (`PaletteSurface.tsx`: a native `<dialog>` opened with `showModal()`, a combobox over a listbox with `aria-activedescendant`, the kinds, the chips of a narrowed search, the rows, the status band, the footer and a polite live region); the chord (`usePaletteChords.ts`, a capture listener on the window: the chord toggles it, and while it is open the tab and panel chords are its own); and where the focus goes (`focus.ts`: remembered when it opens and given back when it closes, unless a command sent it somewhere, as Toggle panel does). `Shell` takes an optional `palette` prop: without one the top row's actions are empty and there is no palette. The host's sources are `plugins/host/palette.ts`. A closed palette holds one listener (the chord's) and no timer; an open one commits once for a keystroke, and never draws more than 50 rows.

**The footer says only the keys that work.** Enter, Option Enter (here), Command Shift Enter (a new tab) and Command Enter (a background tab) are the tab model's own operations. New window is said, and Shift Enter opens one, only for a host that passes `windows: true` to the model, which the plugin host does where the app has native windows (a browser tab has one window: there the key is refused with the reason and nothing opens). The kinds are the mock's five, and one with no provider behind it (Settings, today) says "Nothing to show yet" and offers the plugin homes, as the mock does for an empty kind.

## Probes

`node ui-next/shell/probes/shell-probe.mjs` builds the fixture (the real `Shell` around invented registrations and invented tabs, `probes/fixture.tsx`), serves it, and measures every region against the mock's reference screen in WebKit and Chromium (`mock-shell.json`, made by `mock-measure.mjs`; viewports 1440 x 900 and 1030 x 720 until row N23). `node ui-next/shell/probes/strip-probe.mjs` reads the strip, the page host and the load at 1440 x 900 and 1280 x 800: the strip against `mock-strip.json` (made by `mock-strip-measure.mjs`), the keyboard path with real key presses, axe, exact counts (a tab is 12 DOM nodes; a switch is 3 commits), keep-alive and the switch time on the host fixture (`probes/host-fixture.tsx`: the product's `PluginHost` with invented plugins), and the load with plugins arriving after the first frame; and, since S3, four sections of the demo's findings: `names` (a sidebar label's room beside its count and the tooltip of a label that is cut, against the mock's own tree: `mock-sidebar.json`, `mock-sidebar-measure.mjs`, `names.mjs`), `titles` and `twins` (where a title is cut and what tells twin tabs apart, against the mock's own strip: `mock-strip-text.json`, `mock-strip-text-measure.mjs`, `strip-text-cases.mjs`) and `memory` (the sidebar's groups after a plugin's unload, on the host fixture with `?groups=2`), with their negative controls (`NEGATIVE_CONTROL=slot-wide|names-no-tip|title-cut|twin-lone|twin-hidden|memory-lost`; `ASSERTION_OFF=<control>` leaves that control's assertion out, and its perturbation must then pass). Neither opens a plugin's screen: the shell is plugin-agnostic and so are its probes. CI runs both (workflow "UI next kit probes"); both honour `FONT_DELAY_MS`.

`node ui-next/shell/probes/panel-probe.mjs` reads the bottom panel on the fixture (`?case=panel`: the real `Shell` over the real panel model with the mock's five host tools; `window.__panel` is the model the probe drives) and, for a tool that a plugin registers late, on the host fixture (`?panel=1`) at 1440 x 900 and 1280 x 800 against `mock-panel.json` (made by `mock-panel-measure.mjs` from the mock's own panel): the rectangles of the region, the splitter, the header, the tool tabs, every session tab and each part of it (glyph, name, head, tail, scope, close control), the status bar's toggle and the session card, within 1 px, in the hidden, empty, three-session, every-state and fourteen-session cases; what opening and a drag move (the frame's height by the panel's, nothing else); the paint of the parts, exactly; the roles and names; the keyboard path with real key presses (toggle, strip, session strip, `+`, Hide, the body's own control; the splitter's keys); axe; what a drag costs (a write to the region's style a frame at most, none at the document root, no React commit while the pointer moves); a late tool; and a session body that keeps running while it is hidden. `NEGATIVE_CONTROL=<name>` perturbs one measured value and exits 0 only when the probe saw it.

`node ui-next/shell/probes/rail-probe.mjs` reads the rail on the fixture at 1440 x 900 and 1280 x 800 against `mock-rail.json` (made by `mock-rail-measure.mjs` from the mock's two rails, MOCK_OPEN and MOCK_OPEN_RAIL in `packages/kit/probes/mock-screen.mjs`): the track, each entry's 37 x 40 target, 30 x 30 face and 20 px glyph (rectangles within 1 px; the glyph's centre is also the centre of the first screen's 16 px glyph), the tab stop and the tip that opens at once, and the paint, exactly, of the current entry and of another in six states (rest, hover, hover over the current entry, keyboard focus, the current entry focused, the current entry while the sidebar has the focus). Where the tip opens is not compared: the mock opens it to the right of the entry, the kit's tooltip host below it. The strip probe's load cases add two plugins, the second registering 700 ms late and sorting after the first or before it: no region and no entry of the rail moves. CI runs all three; all honour `FONT_DELAY_MS`.

**The count slot (Q2a).** An entry's row ends in a slot for its count (ch12 SB1: every collection row has one). The mock's tree draws the count as the last thing in the row, muted, 12 px, in tabular figures (`shell-widgets.css:201`) and groups the thousands of every collection count (`H.count`, `core.js:1874`); the shell draws the same, `~` before the digits for an approximate count and `about` in the row's name.
