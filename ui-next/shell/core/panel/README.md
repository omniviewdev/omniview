# The panel model

The bottom panel's state and its rules, as pure TypeScript: no React, no DOM, no timers of its own (`purity.test.ts` fails the build if one is imported). The UI (`../../panel/`) is a thin reader of it. Tests first: `store.test.ts` (behaviour), `labels.test.ts` (what a session tab draws), `persist.test.ts` (snapshot), `height.test.ts` (clamp), `invariants.test.ts` (the oracle sees each rule broken), `fuzz.test.ts` (150 seeds of 120 random operations: every invariant after every operation, the tabs of every strip, what it saves comes back whole, and a window that starts from it, its tools and plugins arriving in any order, is sound at every step and ends on the tool and the session the saved one showed).

## What it holds

| Part | What |
| --- | --- |
| `open` | Whether the panel is drawn. Closed is a 0 px row; its sessions and their state persist. |
| `height` | The height the user **chose** (`null`: the default). The drawn height is `resolveHeight(chosen, viewport)`, whose twin is the CSS `clamp()` in `Panel.module.css`, and a window that no longer fits it brings it within its limits for good (`fitHeight`, on load and on every resize: the mock's `panelClamp`, S103), so a window made small and large again keeps the smaller panel. |
| tools | A registry: tools of the host by plain id (`logs`), tools of a plugin by `plugin:local`. Each has a label, a glyph, an order. A plugin's tools leave with the plugin (`syncPlugins`). **The strip's order (R2, `visibleTools`)**: lowest `order` first, as the mock sorts them (`a.order - b.order`); a tie goes to the host's own tools, then to the plugins in the order the caller listed them in `syncPlugins` (the host lists them in the order of its rail), then to the order a plugin brought its own tools in. Nothing is ordered by the moment a plugin arrived: a plugin that loads late takes its place and is not appended. |
| sessions | Per tool: id, title (head and tail truncate in the strip), scope (the muted qualifier of its tab, drawn only when it tells twins apart: below), state (`starting` `running` `ended` `failed`), `since` (moves only with the state), cause, owning plugin, an optional route to the resource, and `held` (below). |
| `active` | The session on screen per tool; `tool` is the tool on screen. |
| `mounted` | Sessions whose body has been shown, in the order they were first shown, never reordered: a session moved in its strip keeps its body where it is in the document (`selectors.mounted` hands the list back as it is). A body stays mounted until its session closes or its plugin leaves (a streaming session keeps its buffer: HLT-32). |

## Rules

- **Close and end are different.** `closeSession` removes the tab and the body; the session on screen passes to the next one in the tool's strip, else the previous. `setSessionState` ends or fails a session and keeps it.
- **A session can be retitled.** `retitleSession(id, title)` gives a session another title once its owner knows more than it did at `openSession` (the name of the shell the host resolved, later a title the program set). The title is cut as an opened session's is; only the title changes (state, `since`, cause, route, place and choices stay), in one change that tells subscribers once. The same title changes nothing and tells nobody (`noop`); an unknown id is `missing`, an empty or non-string title `invalid`, a held session `held`. Tab names, twins, ordinals and the heard-as uniqueness are derived from the snapshot, so they follow a retitle with no code of their own (`labels.test.ts`, `invariants.test.ts`, and the fuzz draws it).
- **A plugin that goes away is gone in one transaction**: its tools, the sessions in them hidden, its running sessions ended with `UNLOADED_CAUSE`. They come back ended, never running, if the plugin returns (PO1, the mock's rule: a plugin that is off contributes nothing).
- **One deviation from PO1: a held session (A21, widened by the lead's ruling of 2026-11-20).** Every session a plugin has in a tool **of the host** (the Logs tool; a plugin's own tools are not) is marked `held` when the plugin leaves, **whatever its state**. A session that was starting or running ends in the same transaction with `UNLOADED_CAUSE`; one that had already ended or failed on its own is kept AS IT WAS, its own state, cause and time untouched (a failed log is the one being read). Held sessions stay listed and mounted until the user closes their tab, whether their plugin is off or has come back: the lines a person is reading are theirs. A held session never changes again: `setSessionState` refuses it (`reason: 'held'`), the plugin's return and its leaving again change nothing, and a new press of the command opens a new session beside it. Everything else follows PO1: every session of a tool the plugin brought is hidden with it, and so is a session of a tool that is not registered; a session restored from a saved window stays hidden until its plugin has loaded (and, once it has, is a session like any other, kept when the plugin leaves). The stream behind a held session is closed by the registry that owns it (`../../panel/logs/LogStreams.ts`) so the backend session is not leaked; this model knows nothing of streams.
- **A session never covers the page by itself.** `openSession` reveals the panel unless it is told not to (`reveal: false`: restored, adopted, retried). That is S116 as written: "Sessions restored at startup, adopted from another window, or re-created by Retry do not open it (today's quiet-tab rule)", *Why:* "a restored terminal must not cover the page". It is about a session. A panel the person left open is not one: it comes back open, as they left it (`restorePanel`, T2d, decision A23), and a restored session still never opens a panel that is closed.
- **A session that is already there is shown, not opened again.** `revealSession(id)` opens the panel, puts the session's tool on screen and makes it the tool's session, in one change with its body mounted, and does the same for a session that is already the one on screen by changing nothing. It moves no focus (the model has none: the mock's `Shell.panel.show(tool, { focus: false })`), and starts nothing. What decides that a press is for a session that is there is not this model's: it knows no target. The registry of the Logs tool does (`../../panel/logs/LogStreams.ts`): a session is its plugin's and its target's id, a target whose session is starting or running is shown (when the panel has no tool to show it in, `revealSession` refuses and the press answers the session all the same and starts nothing: a target never has two live sessions, a hidden one included), and a new press for a session that has ended, failed or is held opens a new session beside it, which leaves the old one readable (P1b-3d, A22).
- **What a session tab draws (SCT1, TI1; the mock's `labelParts`, shell-panel.js:207-221).** The title, an ordinal for the second and later session of one title and one scope (`(2)`), and the scope **only when it tells twins apart**: on a session whose title another listed session of the tool shares with another scope, and on that one too. A tab that has no such twin draws no scope, whatever scope its session has (`Session.scope` is still its own: the card and the saved panel read it). `SessionItem.name` is the words the tab draws, in the order it draws them (`title (2) · scope`), and the tab's accessible name is that and its state, so the name always holds the visible text (WCAG 2.5.3). Two tabs of a tool are never DRAWN alike and never HEARD alike, runs of white space counting as one space (`names.ts` `sameWords`): a tab is heard as its name and, when its session is not steady, its state (`task, ended`: `names.ts`, which the strip's words come from), so a number whose drawn name or whose sound another tab has (a title that looks like `a (2)` beside two sessions of `a`, or like another session's name and state, an ended `task` beside a running `task, ended`) is skipped, the later session being told another one. Only listed sessions count: a session hidden with its plugin is nobody's twin.
- **Size**: minimum 120 px, at most the window minus 312 px, default `min(400, max(240, 30%))`. A drag released below 80 px hides the panel and keeps the old height. `heightKey` maps Up/Down (16 px, 64 with Shift), Home (minimum), End (maximum), Enter (default).
- Every change is one `Step`: a new state (or the same object when nothing changed, so React bails out) and a result. `checkInvariants` is the test's oracle.

## The invariants, in words

`checkInvariants` returns a sentence for each rule a state breaks; the fuzz applies it after every operation. The rules: the order lists every session once; a session has a title, a tool and a plugin; a session that is not over has no cause; every session the strips choose is one of its tool's; a mounted body is mounted once, belongs to a session that is there, and is visible; the height is null or positive; a tool is sound and the host is never a live plugin. And, for A21:

> **Of a plugin that is off, the sessions that are listed (and so mounted) are the held ones, and nothing else of that plugin's is; a held session is a session of a tool of the host (its id has no colon) that is over, ended or failed; and it never changes until its tab closes.**

`checkInvariants` states the first two halves from `live` and `held` and not from `sessionVisible` (`s1 is mounted, its plugin is off and it is not held`, `the session s1 is held and is not over`, `... is held in acme:metrics, which is not a tool of the host`), so the rule is not checked against its own implementation; a held session may say no cause (it had ended on its own), so that is not a rule. The fuzz writes the listing rule out in the same words for the strips (a session is listed exactly when its tool is visible and its plugin is live or it is held) and checks the last half across operations (the same record, or none). `invariants.test.ts` breaks each rule by hand and expects its sentence.

And, for the tabs of a strip (`tabProblems` in `testing.ts`, which the fuzz applies after every operation to every visible tool, and `invariants.test.ts` breaks by hand):

> **A tab draws its scope exactly when its session has one and another listed session of its tool has the same title and another scope; the sessions of one title and one scope are numbered in the strip's order (the order they were opened in, until the user moves one: `reorderSession`), the first having none; a tab's name is its title, its ordinal and the scope it draws, in that order, and its head and tail are its title and ordinal; and no two tabs of a tool are drawn alike or heard alike, runs of white space counting as one space (a tab is heard as its name and, when its session is not running, its state).**

`tabProblems` is written from those sentences by a plain loop over the listed sessions and not from the selector (`selectors.ts` `facesOf`, which groups once), so the rule is not checked against its own implementation. It gives one sentence for each rule a strip breaks (`the tab of s3 draws the scope "north-yard", wanted "" (it has no twin of another scope)`). The registry's side of the identity rule, that a plugin's target has at most one session that is starting or running (an ended or failed tab does not count, and does not stop a press from starting a new stream beside it) and that a press starts a stream only for a target with no such session, is checked the same way against the real panel in `../../panel/logs/LogStreams.fuzz.test.ts`.

## Saved form

`serialise` writes `{ version, open, height, tool, active, sessions[] }`: identity and choices, never state or output (at most 50 sessions). `restorePanel` validates, repairs what it can (it reports `repaired`), drops a session that is not valid data and nothing else, makes every session `ended` with `RESTORED_CAUSE`, and brings the panel back **as it was left**: open when it was open, with its height, its tool and the session each tool was on, whatever sessions it holds (T2d, decision A23). S116 as written keeps a restored SESSION from opening the panel; the first build read it as "a panel that holds sessions stays closed", which left a terminal that is alive again after a reload waiting unseen behind a closed panel. Nothing is on screen before the tools are registered, so a restored open panel mounts no body until then; a tool or a session of a plugin that has not loaded is not shown, and the panel is on the first tool it has until the plugin has (`settle`, `shownOf`). A value it cannot read gives a closed panel with the tool and height it could read (the open flag opens for a yes and for nothing else). `MIGRATIONS` is empty at version 1; the chain is `../tabs/persist`'s `migrate`. `createPanelSaver` writes through the generic debounced saver (`../saver.ts`). The host restores and saves it together with the tabs and the rail's choice through `../../session/` (its README). **A held session is saved as every session is**, by its identity: `held` is a fact of this run and is never written, and a restored session is never held (a document that says it is, is not believed). It comes back ended with `RESTORED_CAUSE`, with no lines, hidden until its plugin has loaded, and from then on like any session of the host's tool: kept when its plugin leaves (A21: saved as ended without lines, not left out).
