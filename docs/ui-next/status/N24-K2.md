## 1. A probe's controls may run in another shard (the lead's ruling)

`checkTable` no longer says "a probe and its negative controls run together in one shard". It says, per script: at most ONE unit that runs the probe (`runs twice as a probe: the units "A" (shard 1) and "B" (shard 2)`) and at most ONE unit of its controls (`has two units of negative controls: ... list its controls in one unit, so that each runs exactly once`). A control listed twice in a unit, a unit name used twice, a probe in `BY_HAND` that a shard also runs, and a script in no shard are still errors (existing tests). `STEPS_AT_THE_SPLIT` still requires each of the 16 original steps in exactly one shard with its script, env and controls.

The job summary of a shard has the columns `Result | Seconds | Probe | Negative control | Step`: the probe script of every run, the control (empty for the probe itself) and the step that holds it. The error line is `::error title=Kit probe failed (shard 3)::Probe that the panel probe sees a panel that is wrong (toggle) [ui-next/shell/probes/panel-probe.mjs, negative control toggle] exited with code 1`, so a red control in a shard that does not hold its probe says which probe it is for. A run's result object carries `script` and `control` (a test reads the real runner for it).

## 4. `row-menu-probe`: the PROBE read too broadly; the product is right

It failed with 49 findings per engine and viewport (196 in all), each a variant of `aria-expanded on ["Actions for worker-1",null]` while a menu is open and `aria-expanded [null]` at rest. The `null` is not a menu trigger: `snapshot()` read `document.querySelectorAll('[aria-expanded="true"]')` on the whole parts page, and the parts page has other parts that carry the attribute; the element is the `TagList`'s toggle (`TagList/Expanded`: `<button ... aria-expanded="true" aria-controls="_r_4c_">Show fewer</button>`, no `aria-label`, so `null`). The TagList joined the page after the probe was written (7e4bd00f, 2026-11-17; the probe 2026-11-16).

What the kit's contract says, quoted: `RowMenuTrigger.tsx` "`aria-expanded` and `aria-controls` are not React's here: the handle writes them on the one trigger that is open"; `handle.test.ts:227` "sets aria-expanded and aria-controls on the one trigger that is open, and nowhere else"; `RowMenu.test.tsx:279` "writes aria-expanded and aria-controls on the one open trigger, by the handle, and they survive a render of that trigger". The kit's own tests pass (`vitest run src/components/RowMenu`: 4 files, 111 tests). In the page the trigger does carry it: the same findings list `"Actions for worker-1"` first, and `aria-controls on ["Actions for worker-1"]`.

Fix: the read is `button[aria-haspopup="menu"][aria-expanded="true"]` (the menu's triggers), and so is the one that picks the trigger of the row-removal case (`document.querySelector('[aria-expanded="true"]').closest('tr')` would have removed the TagList's row or thrown). Then the whole probe passes: both engines, both viewports, 24 openings each, `no failure`, exit 0, 23 s.

Negative controls (Chromium, 1440 x 900, the one opening that must see each: the top trigger by mouse; a control is detected only when the same opening agrees without the perturbation and every failure with it is the one named):

| Control | Perturbation | Detected as |
|---|---|---|
| `trigger-not-expanded` | the handle's `aria-expanded` is taken off the trigger the moment it is written | `top mouse: aria-expanded on [], aria-controls on ["Actions for worker-1"]` |
| `expanded-twice` | the next row's trigger carries it too | `aria-expanded on ["Actions for worker-1","Actions for worker-2"]` |

Rule 28, each: detected (exit 0); with its assertion removed (`ASSERTION_OFF='aria-expanded on'`) `NOT DETECTED (0 of the failures are the one named, 0 other failures)`, exit 1; with the unscoped read put back, `SETUP ERROR, the opening failed before the perturbation` (the baseline check catches the old defect), exit 1. On the runner they ran in 1 s each and printed `detected` (44860748108, shard 3). The probe itself is 22 s on the runner.
