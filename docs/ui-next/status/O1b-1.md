## The one real source: a failed command of a page header

- **Which source, and why this one.** The commands of a page's header (`PageHeaderCommand.onSelect`, list pages' `definition.commands` and detail pages' `DetailView.commands`) are the plugin's own callbacks: typed `() => void`, written `async`, with no place for their failure to go (a throw in an event handler ends at the window's error report, a rejection at an unhandled rejection). A failed LIST LOAD was the other candidate; it reaches the host as text only (`DetailState.failed.message`), not as the envelope, so it could not carry the class's title or the plugin's sentence, and the page already says it in its own words (a stale view with a Retry): it stays the page's, never a toast (S85: no toast for passive feedback).
- `ui-next/plugins/host/pageFailures.ts`: `guardCommands` wraps every `onSelect` (primary, secondary, danger, menu) where the host draws the header; a sync throw or a rejected promise is reported with the error, a way to run the same command again and its id and label; `useGuardedDefinition` (list) and `useGuardedSource` (detail) in `PluginHost.tsx`'s two contributions. A command that works is called through untouched. A reporter that throws never takes the click down.
- `ui-next/plugins/host/notices.ts`: `failureNotice(store, plugin, error, retry)` is `store.forSource(plugin).fromError(parseAppError(error), { actions: [Retry] })`: the runtime's one parser (R13) and the model's mapping: title the class's, detail the plugin's one sentence, FORBIDDEN/UNAUTHORIZED/INTERNAL/PROVIDER_ERROR keep the host's own text, anything that is not the envelope is "Operation failed" with **none of its text** (tested with a password in the message), a cancellation is none. **Retry** (id `again`, because `retry` is a reserved action kind; primary, `refresh` glyph) runs the same guarded command by the same path, so a second failure is a count on the one toast ("Timed out 2 times"). Its code is removed with its plugin (`removePlugin`), and Retry is then unavailable with the model's reason.
- The fixture plugin's detail page: **Restart** (secondary) rejects as the runtime's hooks do when `window.__fixtureDetail = { failure: 'timeout' | 'forbidden' | 'generic' | 'cancelled', runs: [] }` exists (`fixture/src/failure.ts`, tests in `failure.test.ts`); without it Restart does nothing, as it always did.
- Tests: `pageFailures.test.ts` (the guard), `notices.test.ts` (the source over the real tab model, palette and model: class words, password, cancellation, fold, Retry, the plugin gone, S85, S89a, route actions), `PluginHost.notices.test.tsx` (the whole host: click Scale, a toast, Retry, "Timed out 2 times", generic, cancellation, a command that works).

## Placement (ruling 7, the mock's P7), built in this step

The mock's rule, whole (`shell-notify.js`, header, "PLACEMENT"): the stack is HOME at the bottom right above the status bar, 420 px wide. A control is a visible native button, link, field, summary or interactive role (not a focusable table row or scroll area, not inside the toast layer or an inert subtree, not natively `disabled`; an `aria-disabled` one IS a control) that really answers at its centre (`elementsFromPoint`), so one clipped by a scroll area does not count. The stack CONFLICTS when any control is within 4 px of it. After every change to the stack, a resize, a scroll and a layout change (settled for 120 ms) it is decided again, first free wins: (1) home; (2) where it already stands (`data-place="moved"`); (3) the nearest spot, by distance from home, that is 8 px clear of every control, searched at 420, 360, 320, 280 and 240 px wide (a narrower stack wraps its text, one more line a toast for every 120 px) on the right edge, the centre, the left edge and beside every control; (4) YIELD: `data-place="yield"`, hidden and inert, none listed, one announcement, the records stay unread; it returns home as soon as home is clear. Constants `PLACE = { pad: 4, gap: 8, top: 8, edge: 12 }`.

- `placement.ts` is the rule as a pure function (no document, no timer). `placement.oracle.test.ts` copies the mock's own `meets`/`clearOf`/`slide`/`place` with the page reads taken out and replays them against it on **10,000 layouts** (seven window sizes, 0 to 40 controls, a third of them in the corner home is, every place the stack can be in): the same answer on every one. `placement.test.ts` has the hand-derived cases (4 px exactly is not a conflict, 3 is; the natural height of a stack that stands narrower; 280 wide beside two walls; yield).
- `usePlacement.ts` is the DOM side: it decides before paint after every change of the list of toasts, and watches (`ResizeObserver` on the stack, `window` resize, a captured scroll, a `MutationObserver` for elements added or removed and for `hidden`, `class`, `style`, `inert`, `open`, `aria-expanded`, none of it inside the layer) only while there is a toast, with ONE timer (120 ms, then a frame). With no toast it holds no observer, no listener and no timer (a test and the probe count them).
- The layer stays home (it is the live region and the box the stack comes home to); the stack inside it, the landmark, is the one that moves: `data-place="moved"` sets `--_x`, `--_y`, `--_w` (physical left and top from the window's corner: they do not mirror) and `position: fixed`; `yield` is `visibility: hidden`, `inert`, and not an F6 stop (`data-shell-region` is dropped).
- **Yield is told.** A toast that nobody can see has no live region, so the stack says so once when it yields, and again for a toast that arrives while it waits: the toast's own words ("Error: Timed out. The cluster did not complete the request in time."), or "N new notifications." Polite, or **assertive when one of them is an error the user caused** (the mock says polite; an error must not become quieter because there is no room). No centre is named: there is none yet.
- A modal (the palette) suspends the stack in the model (`hold('modal')`): no stack is drawn, so placement has nothing to place; the clocks are held (a toast of 8 s with the palette open for 20 s is still there when it closes, with its remaining time, at least two seconds); it comes back when the palette closes.
- **Yield holds the clocks** (ruling 5 above): `usePlacement` calls `hold('yield', true)` while `data-place="yield"` and lets go when the stack is drawn again or the window goes. The mock's clocks keep running; this deviates from it.
- **Yield gives the focus back** (ruling 6 above): `giveBack()` runs in a layout effect of the commit that made the stack inert, before the browser's own fixing of a focus that is in an inert subtree.
- **What a RESIZE and a SCROLL do to the placement (read from `usePlacement.ts`; NOT RUN IN A BROWSER: no probe scene has them, jsdom unit tests cover the 120 ms settle after a `resize` event and after a scroll, with the geometry given).** While there is a toast, `watch()` listens to `window` `resize` and to `scroll` on the document (capture, passive); either only arms ONE timer of 120 ms, then one frame, then `decide()` again, so a drag of the window or a scroll costs one decision after the page has been still for 120 ms and never one per event. `decide()` reads home again (the layer's box: its width is `min(420px, 100vw - 24px)` and its edges follow the window), every control's box in window coordinates and the window's width, and answers by the rule: home if clear, else where it stands if still clear, else the nearest clear spot, else yield. Between the event and the decision (at most 120 ms and a frame) a MOVED stack stays at its old physical box (`position: fixed` at `--_x`, `--_y`, `--_w`), so after a shrink it can overhang the new edge for that moment; a stack at home follows the window's corner by CSS at once. A scroll moves no toast (the stack is fixed); a control that scrolls under a stack is avoided once the scroll has settled. A `ResizeObserver` on the stack (its text changes) and a `MutationObserver` on the page (elements added or removed, `hidden`, `class`, `style`, `inert`, `open`, `aria-expanded`; nothing inside the layer) arm the same timer.
