## Decisions

- **Icon mechanism: inline `<svg>` + one `<path>` per paint, from a typed static registry** (`src/components/Icon/glyphs.ts`, `IconName` a closed union; no icon library, no namespace import, no lookup by an arbitrary string). Measured, vanilla DOM, 5,000 glyph instances, median of 9 (`/tmp` script, not committed): WebKit total 50 ms inline, 82 ms the mock's own markup, 84 ms sprite (`<use>`: layout 55 ms), 151 ms CSS mask (paint 141 ms); Chromium 33 / 50 / 49 / 33 ms (frame-bound). Elements per glyph: mock 4.6, inline 2.2, sprite 2.0, mask 1.0. The product's native engine is WebKit, where inline wins and masks and sprites lose. Also: a mask vanishes in forced-colors mode, a sprite needs a document-level mount and cannot be themed per instance, and plain data suits a later plugin-supplied glyph. Cost of inline: the path data repeats per instance (about 310 B of markup per glyph).
- **K4's "at most 2 elements per glyph" holds for 20 of 24 glyphs.** The four status glyphs (`status-success|warning|error|info`) have two paints (a disc and a mark) and cost 3; only a CSS mask with pseudo-elements gets two paints into one element. 1a.4c (`Status`) may draw them that way in table rows if its 4-element budget needs it.
- **Paints.** `ink` is `currentColor`; the chevron grey and the status colours are the roles the mock pins (`--ov-icon-chevron`, `-success`, `-error`, `-info`, `-warning`, `-warning-mark`), resolved in `Icon.module.css`; the white of a status mark and the Play fill `#253627` are literal artwork paints (the mock has no role for them; adding `icon-mark` and `icon-run` to the token glyph group would tokenize them: lead's call).
- **Button API (closed).** `variant` secondary | primary | ghost; `tone` neutral | danger; `size` standard (28 px, 12 px side) | compact (28 px, 8 px side: the mock's `small`) | row (the row target, 24 px, 22 in compact density); `icon`; `busy`; `disabledReason`; `onClick`; `children: string` (a face holds no status, count or timer, 13 M1). `IconButton` takes `icon` and a required `label` (the name; never taken from the glyph), the same variant, tone, `busy`, `disabledReason`, and size standard | row. Never natively disabled, never a submitter, no `title`.
- **Disabled with a reason (14 P2, V62, 04 DR1).** `disabledReason` is the only way to disable: `aria-disabled="true"`, focusable, painted with the disabled roles, no hover or pressed paint, the click does nothing (however it was made), and the reason is the button's accessible description (a hidden span, `aria-describedby`). The visible reason stays the view's (examples `DisabledWithVisibleReason`); an empty reason is no reason.
- **Busy (13 M2, 16 S76).** `busy` sets `aria-busy` at once; after one second the icon becomes the 16 px loader (a timer, one re-render), the label never changes, input is not blocked; no icon, nothing to replace; the loader holds still under reduced motion.
- **Examples.** Every part ships `<Part>.examples.tsx`; `src/examples.ts` collects them; the build emits `@omniviewdev/kit/examples` (examples import the kit by its public name, which stays external, so they render the same parts as the root entry). Root entry and its API report carry no example (`check-dist` fails if they do).

## Findings for the lead and the errata pass (N10)

- The mock's `button { font: inherit }` (`base.css:872`) outranks `:where(button) { font-size }` (line 969): a plain mock button takes its parent's font size, only `.small` pins 13 px. The kit pins 13/16 everywhere.
- The mock's `small` is a padding modifier (8 px against 12 px side), not a size; chapter 15 calls `sm` a deprecated alias of `md`. The kit names it `compact`. Chapter 15's 30 px shell size (top-row commands) is not built: no slice 1a screen draws it.
- The mock's primary button has no hover or pressed paint (accent stays). The kit follows the mock.
- Chapter 14 P2 lets any truthy `disabled` be a reason-less disabled button; the kit makes the reason required (04 DR1), and an empty string means available.
- The mock's loaders differ: `LuLoader` (spokes) for local busy and collection states, `LuLoaderCircle` (arc) for the progress status role. The registry has both (`loader`, `loader-circle`).
- Playwright's macOS WebKit does not Tab to buttons (Alt+Tab does). Whether the Wails WKWebView does depends on `tabFocusesLinks` and the system's keyboard navigation setting: the owner's native pass must check Tab to a button.
- Fonts are normalized in the probes (Inter is not delivered, R-9); widths match to 0.01 px with Helvetica, so real-font parity needs a rerun after 1a.4d.
- `axe-core` is not a repo dependency: the probes read it from a path (`AXE=`), here a temporary install of 4.14.1. A kit devDependency would make the jsdom matrix run it in CI: lead's call.
