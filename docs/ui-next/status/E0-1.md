# Status: E0-1 (a plugin's own error text reaches the UI; Backend catalog B-02)

- Agent: ErrorText
- Goal: the sentence a plugin wrote for an error (the Kubernetes plugin's "The cluster did not complete the request in time.") reaches the page, cleaned and bounded, instead of "resource operation failed". Two repos, the smallest fix, in this order: the plugin SDK carries the sentence in the gRPC status; the host's normaliser keeps it (after a text gate) and falls back to its class sentence. The agent (MCP) path must not receive it. The frontend is not touched.
- Worktrees: SDK `~/Repos/omniviewdev/worktrees/plugin-sdk-e0-1-error-text`; host (this file) `~/Repos/omniviewdev/worktrees/ui-next-e0-1-error-text`

- Base: SDK `origin/main` 1f5702f (= tag v0.20.0); host `origin/main` be06aa2d

## What was built

**SDK (PR #79, draft).** `pkg/resource/v2/plugin/codec.go`: the resource provider server adds a `LocalizedMessage{locale: "en", message}` detail beside the `ErrorInfo`, and `ResourceDomainError` restores it as `Message`; an older plugin's `Message` arrives empty, not the placeholder. Only for a reviewed class, only valid UTF-8, at most `MaxErrorMessageBytes` (2048, new exported constant). `Title`, `Suggestions` and `Err` never cross; the status text stays fixed. The shared `ResourceRPCError` (resource exec, host connections) and the errors the SDK raises itself still send the class only: `pkg/v1/hostconnections` pins that an owner's private text never reaches the plugin that borrows the connection.

- **No wire bump.** The detail is in the status (HTTP/2 trailers), not in a resource message; strict admission (`ValidateWire`) applies to message bodies and never sees it. No `.proto`, `WireVersion`, `wire.go` or `wire_contract.go` change; the strict-reader tests pass unchanged (names in the PR). Had this been false the plan was to stop and report a WIRE item; it was not.
- **Both directions**, in the package (frozen copies of the v0.20.0 reader and encoder) and across two real processes with the unmodified v0.20.0 module as the old side (`E0-1/interop-results.txt`):

| plugin built on | host built on | what the host's SDK client returns |
| --- | --- | --- |
| v0.20.0 | v0.20.0 | class, `Message = "resource operation failed"` (today) |
| PR #79 | v0.20.0 | the same; the extra detail is on the wire (2 details) and skipped cleanly |
| v0.20.0 | PR #79 | class, `Message = ""` |
| PR #79 | PR #79 | class, `Message` = the plugin's sentence |

**Host (this PR).**

- `backend/pkg/apperror/public_text.go`: `PublicText(value, maxRunes)`, the text gate (P5's E0-2, the part this step needs). Cleans: terminal escapes removed whole, control, format (bidi, zero-width, tag), private-use characters dropped, white space collapsed, cut to the bound with an ellipsis. Refuses: not UTF-8, over 4,096 bytes, no letter or digit left, a credential, a PEM block, a kubeconfig fragment, a long opaque run, a path under a home directory. The patterns run on the cleaned text, so a secret split by zero-width characters is still seen.
- **Existing redaction rules reused, not copied:** `internal/devdiag/devdiag.go:41-47` (`Redact`: URL userinfo and query, bearer, `key=value` secrets, GitHub/GitLab/Slack/AWS/JWT shapes; its patterns `:24-35`) is the detector. The long base64 and hex shapes follow `backend/pkg/plugin/manager.go:56-63` (`sensitivePattern`, unexported in a package that imports `apperror`, so the two regexps are repeated and the source named). PEM, kubeconfig keys and home paths (the running user's by value, `/Users/`, `/home/`, `C:\Users\`, `~/`, `$HOME`, `file://`) are new: nothing in the host had them.
- `backend/pkg/apperror/resource.go`: `ForResource` keeps the provider's sentence (now max 512 runes) for the classes that may show it, falls back to the class's own sentence when there is none or the gate refuses it, and keeps the class's title. FORBIDDEN, UNAUTHORIZED, INTERNAL, PROVIDER_ERROR and CANCELLED keep the host's fixed text (the existing C02 rule); so do the governance codes, which fall to INTERNAL (B-03, unchanged). Title and suggestions go through the same gate. The SDK's two placeholders ("resource operation failed", "action operation failed") are "no text", never a sentence.
- **Works with both SDK generations without a `go.mod` bump of the SDK.** With the SDK this host is pinned to (v0.20.0) the client sets the placeholder and keeps the status in `Err`; `ForResource` reads the `LocalizedMessage` from that status (`statusSentence`). With a client that restores the sentence (PR #79), `Message` carries it. The status reading is transitional: `TestPinnedSDKClientStillLeavesTheSentenceInTheStatus` fails the day the pin carries the new client and names the code to delete. `go.mod` only moves `google.golang.org/genproto/googleapis/rpc` from indirect to direct (same version); `go mod tidy` would also drop two stale `omniviewdev/registry v0.3.0` lines of `go.sum`, left alone.
- **A host-authored `AppError` detail meets the same gate** (it was never checked). Run over all 317 distinct Kubernetes plugin messages and 332 distinct host messages found in source, the gate refused none and changed five (trailing spaces of partial literals).

**The agent boundary (must not receive plugin text).** It is the relay's handler: `internal/mcprelay/server.go:988-1002`, where whatever the dispatch returns becomes a fixed string (the four governance strings or "tool invocation failed"). The SDK tools contract says the same (`plugin-sdk` `docs/tools.md:159`, `pkg/v1/tools/errors.go`). Two tests in `internal/mcprelay/agent_error_boundary_test.go`: `TestPluginErrorTextNeverReachesAnAgent` sends six kinds of plugin-text-bearing error (the normalised `AppError`, wrapped, the typed error, an older client's error with the status, a governance denial, a plain error) through a real MCP HTTP session and asserts a fixed string and no structured content; `TestErrorResultCarriesFixedTextOnly` pins the 37 `errorResult` call sites by syntax: only the four reviewed ones may pass an error's own text (three host argument validations, `listConnections`, whose errors come from admission only), and a new one fails the test. Both were made to fail by a deliberate leak.

## Evidence: what the TypeScript side receives, before and after (four cases)

(Full lines in `E0-1/evidence-after.txt`; the exact strings are also pinned by `TestKubernetesStyleErrorsReachTheUI`.) FORBIDDEN is the host's text by rule on every row: the plugin's forbidden sentence crosses the wire and is not shown. The real `parseAppError.ts` (only its navigator import stubbed; `E0-1/parse-probe.ts.txt`) turns each of the eight into the same `title` and `detail`, `recovery` unchanged: nothing the parser reads changes shape, only the text.

Not touched, and to know for the TypeScript work: `parseAppError` replaces a `detail` that starts with `"` or `{` or contains `: {` with "The operation could not be completed." (it scrapes `detail` for a nested JSON cause). Plugin prose is now in `detail`, so `"app" is not in this pod.` is flattened (checked with the real parser: `"\"app\" is not in this pod."` becomes the generic sentence). The Go gate does not refuse such text; the parser rule (P5 E0-4) should go.

## The release chain

1. **SDK PR #79 merges and is tagged.** It would be **v0.20.1** (additive detail, one exported constant, no removal, no wire change), or it rides the next cohort tag if plugin-sdk #78 lands first. Two SDK tags in a fortnight collide in `go.mod` (RT2 section 6.5).
2. **Plugins rebuild against that tag** to send the sentence: the Kubernetes plugin needs `go get github.com/omniviewdev/plugin-sdk@<tag>` and a release; no code change (its sentences are already written). A plugin that is not rebuilt keeps working and shows the host's class sentence.
3. **Host.** This PR is independent of that chain: merged today it already replaces the placeholder with the class sentence for every plugin, and the plugin's own sentence appears as soon as a rebuilt plugin is installed. The host's SDK pin bump is not needed for the text. When it happens, `TestPinnedSDKClientStillLeavesTheSentenceInTheStatus` fails; delete `statusSentence`, the status branch of `providerSentence`, the `"resource operation failed"` entry of `sdkPlaceholders` and that test (`"action operation failed"` stays: it comes from in-band events).

## Decisions for the lead

- **Plugin text now reaches the existing chrome as `detail`**, before a "secondary line behind Details" exists (RT2 section 6.2 asked for that order). The assignment asked for it; the cost is that K14 ("no arbitrary remote text in chrome") is not yet true on screen. The gate is the mitigation, not a proof.
- **FORBIDDEN, UNAUTHORIZED, PROVIDER_ERROR keep the host's words** (existing C02 rule, P5 3.5). The Kubernetes plugin's forbidden sentence is a fixed, harmless one; showing it would be one condition in `ForResource`. Recommended: no, until the owner decides.
- **SDK tag number** and whether to ride #78's cohort tag.
