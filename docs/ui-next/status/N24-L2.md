## New-changes mode (what a contributor sees)

The workflow lints a detached worktree of the merge commit with `--new-from-patch=<git diff base.sha HEAD> --new=false --new-from-rev= --new-from-merge-base=` (empty values switch the other new-code modes off, `only-new-issues: false`). The 11,799-issue backlog of N24-L1 is not reported: only issues on lines the patch adds or changes (every line of a new file). An issue on an unchanged line that a change elsewhere causes (for example a function left unused after its caller was deleted) is not reported. `lll` no longer reports anything.

A contributor sees: a red `Go lint` check; in the log, one line per finding, shown as an annotation on the PR's file and line:

```
##[error]internal/lintproof/finding/finding.go:8:10: Error return value of `os.Chmod` is not checked (errcheck)
        os.Chmod(name, 0o600)
                ^
1 issues:
* errcheck: 1
##[error]issues found
```

**Reproduce the CI lint locally, one command** (repo root; golangci-lint v2.15.0, `go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0`; commit first: `git diff` sees committed changes only):

```sh
git diff --no-ext-diff --no-color origin/main...HEAD > /tmp/changes.patch && GOWORK=off golangci-lint run --new=false --new-from-patch=/tmp/changes.patch --path-prefix=
```

Run locally (macOS arm64, v2.15.0): the three proof files below gave exactly the one errcheck finding; cold cache 1 min 42 s, warm 6 s. `--new-from-patch` needs the patch to hold the paths root-relative, as `git diff` writes them. `git diff origin/main HEAD` (two dots) is what CI runs against the base sha; with three dots you get the merge-base, the same when your branch is up to date.
