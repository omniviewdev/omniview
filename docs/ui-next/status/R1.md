## Signature a plugin calls

```ts
import { useResource, type HostGetRequest } from '@omniviewdev/runtime/ui/v1';

const { resource } = useResource({ pluginID?: string, request?: HostGetRequest, enabled?: boolean });
// resource: UseQueryResult<HostRecord, Error>  (data, isPending, isError, error, refetch, ...)
// request: { targetId, request: { route: { connection }, reference: { address: { provider, authority, type, scope, id }, incarnation? }, representation } }
```

`targetId` and the route come from `useResolvedResourceTarget` (`target.targetId`, `target.target.route`); the address is built from the resolved target's provider/authority/type and the object's identity (scope entries per `identityDimensions`, `id` the name).

## Is a single-object read live?

No. It is one-shot.

- `useResource` is a `useQuery` over one `Get` call: `packages/omniviewdev-runtime/src/hooks/resource/useResource.ts:49-56` (`retry: false`, no subscription, no source view). Nothing pushes to it.
- Only a mutation through the same hook (`useResource.ts:44-46`), a mutation or action elsewhere (`useResourceMutations.ts:20`, `useResourceActions.ts:58`) or a connection change (`hooks/connection/useConnection.tsx:43`) invalidates `resourceQueryKeys.all(pluginID)`. A change made by anyone else (the cluster, another tool) never reaches it. The host's QueryClient does not refetch on focus (`ui-next/queryClient.ts:13`).
- Go side: `controller.Get` (`backend/pkg/plugin/resource/finite_operations.go:130-208`) calls the provider's `Getter.Get` once and returns one `HostRecord`; the SDK interface is `Get(context.Context, GetRequest) (Record, error)` (`plugin-sdk@v0.20.0/pkg/resource/v2/domain.go:387-389`). No topic, no stream, no event.
- Deleted: there is no signal. The next `Get` fails (`resource.isError`; the error is whatever the provider answers, [INFERENCE] a not-found for a deleted object, not exercised), and until a refetch the old record stays.
- The only live reads are source views (`OpenSourceView`, `source_coordinator.go:663`; `useResources({ collection: true, live: true })`, `useResources.ts:19-20,52-58`). A source is keyed by a `ReadTarget` whose `scope` constrains only the type's declared QUERY dimensions (SDK `domain.go:60-74`: every declared dimension appears once, `any` or `oneOf`). A removal arrives as `removes` in the view's events (`HostSourceViewEvent.removes`, `sourceView.ts:158-160,226`) and the record leaves the map: that is the delete signal.
- Narrowing by name: NOT supported for the Kubernetes types. Its catalog declares one query and identity dimension, `namespace`, for namespaced kinds and none for cluster-scoped ones (`omniview-plugin-kubernetes@d06f24e pkg/plugin/resource/native_catalog.go:111-115,140-141`); the name is the record `id`, not a dimension. So the cheapest live interim is what the detail page does now: a live collection narrowed to the object's namespace (`scope: [{ dimension: 'namespace', match: 'oneOf', values: [ns] }]`), the record picked out of `resources.data.records` by `addressKey`/`reference.address.id`; for a cluster-scoped kind it is the whole kind.
- What the host would need for a live single object: (a) a name (identity) as a declared query dimension on the plugin's catalog, with a `sourceUpdates` capability scoped to it, which `OpenSourceView` already admits as an ordinary `ReadTarget` (no host change); or (b) a new host/SDK operation, a source view opened by reference (`HostSourceViewRequest` takes a `ReadTarget`, not a `GetRequest`) with an SDK capability that a provider can serve a one-record following session. (a) is a plugin-side catalog change with the host untouched; (b) is a contract change in the SDK, host and runtime. Not built here.

## Versioning

Additive minor under the rule in `src/ui/v1.ts` (header, rule 4, written in this PR; same reading as the contribution contract's rule at `ui-next/plugins/contract/v1.ts:36-45`): a new name and four new types, nothing removed, renamed or re-meant; a bundle built before it runs unchanged.
