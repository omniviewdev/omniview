## What was built

- **Strip** (`ui-next/shell/tabs/`): a roving `tablist` "Open tabs" in the top row, after Back and Forward (30 px, a 20 px glyph, `aria-disabled` with the reason): faces of equal width (208 px at most, 96 px at least, then the scroller scrolls, no bar, no overflow menu; the tab on screen is revealed), a glyph, the title cut in the middle (head and tail, as the mock), the qualifier that tells twins apart, a close control, `+` after the last tab. Keys: arrows (wrap, select nothing), Home, End, Enter, Space, Delete and Backspace (close, focus the neighbour), Command or Control with W, 1 to 8, 9, and the web alternates (Control Option). Middle click and the close control close. Each `Tab` reads its own slice of the model.
- **Page host**: one `tabpanel` labelled by the selected tab, a slot per mounted tab inside React `Activity` (the technique of HSH-21 and MNR-K1: effects released, renders deferred, `display: none`, so no layout and no paint for a hidden page). Default policy `{cap: 5, keepUnsaved: true}`.
- **Opening**: `PluginHost` builds the model's `Contributions` from the loaded plugins (`contributions.ts`), a published frame per mounted page (`published.ts`: the page's hook says its tab, path and scope; the tab and the lane follow), `onChoose` opens through `open` with the click's disposition, `+` opens a new tab at the plugin's home, the address (`#/<plugin>/<page>?connection=`) is an input and is never written. The status bar reads the model's breadcrumb.
- **Frame**: `ShellRegistration` lost `tab` and `path` (the model's) and gained `pending` (regions reserved while a plugin loads).
- **Kit**: glyphs `plus`, `arrow-left`, `arrow-right`; `IconSize` 20 (a 30 px toolbar face holds a 20 px glyph); `isIconName` (a plugin's glyph name is data from outside; a name the kit lacks draws `box`). API report updated.
- **CI**: the shell and strip probes run in the workflow "UI next kit probes" (the shell probe was run by hand before).

## The hiding technique, measured

Before the page host was written: in WebKit and Chromium, `display: none` on an ancestor (what `Activity` applies) keeps a hidden scroller's offset, in a flex layout too (900 px stayed 900); `content-visibility: hidden` keeps it as well and also skips layout and paint, but releases no effects; `visibility: hidden` keeps layout. So `Activity` it is: it is the only one that releases effects (MNR-K1), and it needs no scroll code for a page's own scrollers. The tabpanel itself is one element shared by every tab of a `document` layout, so its offset is stored per tab by the host.

## Decisions I took, for the lead to confirm

1. **`+` opens a new tab at the home page of the plugin on screen**, not the mock's menu of plugin entry points (S34): the menu is not built and a control that does nothing is a stub. Another plugin's page opens from the address (`#/<plugin>/<page>`, which opens a tab) until the menu and the palette exist; the real window has one plugin.
2. **The close control is `aria-hidden` and not a tab stop** (a tablist owns tabs only; axe fails a button inside it). Ruled by the lead, by the standing rule "where VS Code and JetBrains agree, follow them": a tab's close button is a Tab stop in neither, so this stays, as a stated exception to A14 (`decisions.md`: controls inside a composite widget with roving focus follow the widget's keyboard contract). A tab closes from the keyboard with Delete on the focused tab (the tab carries `aria-keyshortcuts="Delete"`, so a screen reader announces it), Command or Control W and, later, the tab's context menu. The mock's close button is a named button inside the tablist.
3. **The window reserves its frame while a plugin loads**: rail, sidebar (busy, empty) and a scope lane. The shape of a plugin's frame is unknown before it loads, so a frame without a lane moves the page once. The pinned Pods page declares no scope when its route names no connection (`podsFrame`), so on the real window the 40 px lane is reserved and given back once: a plugin-side fix (return the connection the page picked) or the saved frame shape removes it.
4. **The address is an input only**; the window no longer writes the hash on navigation (the seam check's assertion changed).
5. **The top row keeps the mock's 138 px for the window actions, empty**, so the strip has the width the mock gives it (budget `W - 374`).
6. **Keep-alive stays the model's placeholder** (`{cap: 5, keepUnsaved: true}`); the technique is chosen and measured, the number is not.
7. **The shell probe is now in CI**, with the strip probe. It was run by hand before, and the lead's note says CI runs it. Their Linux behaviour is not verified; the job is not required.
8. `react-dom/profiling` did not work as a drop-in for the Profiler in the fixture (a page error); the commit counts use React's development build of the same fixtures instead.
