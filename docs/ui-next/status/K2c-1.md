## The plugin

**PR [#278](https://github.com/omniviewdev/omniview-plugin-kubernetes/pull/278)** (two commits, `f211697bcb` and `650e4e56ed`; `ui/src/kinds/detail/**`, a `detail.ts` per kind, `hack/kinds-capture/`, `ui/scripts/kinds-capture.test.mjs`). `KindDefinition` gains `detail?: KindDetail`: `{ page, identity, overview?, commands? }`, all data and one function per question. `identity` is `['namespace', 'name']` or, for a kind that lives in no namespace (Node, Namespace), `['name']`: the catalog's own dimensions, so the read is `{ namespace oneOf, name oneOf }` or `{ name oneOf }` and the SDK refuses nothing. `detailPage(definition, resolve)` is the ONE detail contribution beside `listPage`; `useKindObject` is the Pod page's `usePod` generalised (the live single-record source); `detailView` draws the header (the state word and glyph from the kind's list row, so page and list never disagree; the identity line `Kind · Namespace · Age`; the commands), the summary line, the Details card, the Conditions, and the Labels and Annotations (a key that names a credential, and `last-applied-configuration`, show a mask: the value is never in the data). A reference to another object is a link only when the plugin has a page for its kind (`detailTarget`): a Job's owner CronJob and a StatefulSet's Service are links; a service account is text. A definition without a `detail` keeps its rows non-navigating: `cells.test.tsx` renders the name of EVERY kind that has none and asserts no anchor, `index.test.ts` holds the 29 kinds to the nine that have one plus the Pod's. The Pod page and `usePod` are untouched; the generic layer holds its own copy of the Conditions table and of the label and annotation rules, held to the Pod page's answers by parity tests (`metadata.test.ts`, `conditions.test.ts`): moving the Pod page onto it is the next step.

The states: loading (the host's skeleton, header and tabs in place), not found, in two sentences (the `empty` snapshot of the object's own narrowed source: `<Kind> <name> was deleted. It no longer exists in <where>.` when the page had the object and its source has since reported the deletion, `<Kind> <name> doesn't exist in <where>. It may have been deleted.` when it never loaded), `denied` with the plugin's sentence and no Retry, a failure with a Retry kept beside the object, a kind the cluster does not serve and a connection that is gone with no Retry.

**What the mock's pages hold that this step does not draw** (the lead's list: header, Details, Conditions, Labels, Annotations, related rows as links): the template's Containers, Init containers, Volumes, Config and secrets and Health checks; Requests and limits, Scheduling, Autoscaling, Disruption budget, Exposed by (the aside); a Service's Ports and Endpoints and its Ingresses; a ConfigMap's Keys and Used by; a Node's Capacity, Taints, Addresses, Usage and Pods; a Namespace's counts, quota and limit ranges; a Job's Pods; a CronJob's Recent Jobs; a StatefulSet's claims; the Related, Graph, Metrics and Editor tabs.

## What a definition could NOT express and needed code for

1. **A state that follows the object in a command's label** (Pause rollout or Resume rollout, Suspend or Resume, Cordon or Uncordon): `commands` is a function of the record, not a list.
2. **Time.** A moment (`Last schedule`, `Deleting since`, `Started`) and a running span (`Duration`) are instants the view keeps current on the page's age clock; the model carries no clock. The CronJob's `Next run in 12 min` needs a cron evaluator and a time zone database, and `Last run 3 min ago` needs a summary item driven by a clock, which the kit's `StatusSummary` does not have: the CronJob's summary is empty, and `Last schedule` is a row (K59 lists it; the mock's code has a `null` where it would be).
3. **A word that needs another kind.** A Service's `Ready`, `Partially ready` and `No endpoints` need its EndpointSlices; a Node's `14 Pods · 62% CPU requested` its Pods and their requests; a Namespace's counts the lists of its kinds. The header says no word and the summary is empty for those three: no word is made up from the spec alone.
4. **A row whose rule is not a field**: a strategy in words (`Rolling update · max surge 25%, max unavailable 25%`), a claim retention policy (`Removed on delete, kept on scale-down`), a selector as chips, a schedule in words (`describeCron`), a Node's Roles (the part after `node-role.kubernetes.io/` of each label), a Job's `Started` (only when it says more than the age: 60 s after creation, the Pod page's time-free rule). Each is one function in `detail/text.ts` or the kind's `detail.ts`.
5. **A reference to an object**: `ObjectRef` (kind, name, namespace) resolved by the registry (`detailTarget`), because a kind's file cannot import another kind's page without a cycle.
6. **The related objects**: see the Backend catalog; no definition can say them with the curated entry as it is.

## Related rows: links, and what is needed

A related row is a link where it is a reference to ONE object whose page exists: a Job's Owner (a CronJob link, proven live) and a StatefulSet's Service (a link). A related TABLE (a Deployment's ReplicaSets and Pods, a StatefulSet's Pods and claims, a DaemonSet's and a Job's Pods, a CronJob's Jobs, a Service's Endpoints and Ingresses, a ConfigMap's Used by, a Node's Pods, a Namespace's quota) is **not** built: the lead's rule is a link to an existing list with a filter the list already supports, and **no list supports a filter through its route**: the host's list page reads no route parameter (`RouteV1.params` is empty for a list, D1a; `ui-next/page/ListPage.tsx` has no `route`), and the quick filters and the search are the page's own state. So those rows are listed as needed (Backend catalog).

## Spec errata (for the errata pass, row N10; found here, not chosen silently)

- **E1 (mock, K61.3 `conditionRole`): a Namespace's deletion conditions are read inverted.** The mock's table has no pattern for `NamespaceDeletionDiscoveryFailure`, `NamespaceDeletionGroupVersionParsingFailure`, `NamespaceDeletionContentFailure`, `NamespaceContentRemaining` and `NamespaceFinalizersRemaining`, so a `False` failure is attention and a `True` remainder is healthy. **Ruling (lead, K2c-1): they follow their meaning**: a `...Failure` that is True is attention and False is healthy; a `...Remaining` that is True means the deletion is still in progress (the kit's `progress` role) and False is healthy. In the plugin: `ui/src/kinds/detail/conditions.ts` and its tests; the Pod page's table is unchanged (no Pod carries these types). On the kind cluster the terminating Namespace's five conditions are drawn `healthy`, `healthy`, `healthy`, `progress`, `progress` (A, both engines).
- **E2 (mock, `describeCron`): a schedule is said to be uniform when it is not.** `*/40 * * * *` runs at :00 and :40 and again twenty minutes later; `0 */5 * * *` at 0, 5, 10, 15 and 20 o'clock and again four hours later; the mock says `Every 40 minutes` and `Every 5 hours at :00`. `kubectl describe` prints the expression only. The plugin says words only where every gap is the one it says, and the expression otherwise (also for lists, ranges, steps over a range, values outside their field and the 29th to the 31st, which shorter months skip: `Monthly on day N` is for N up to 28).
- **E3 (mock, `OVERVIEW.<Kind>` summaries): `up to date` is computed from the counts alone.** A workload whose controller has not seen its last change (`status.observedGeneration` behind `metadata.generation`) still has the counts of the older template. The plugin says `update not observed yet` there, for a Deployment, a StatefulSet and a DaemonSet; proven with the controller manager stopped (G).
- **E4 (K59 and the mock's code disagree).** A Job's note is `Complete in 2 min 14 s` in K59 and `took 2 min 14 s` in the code (the plugin follows the code); a CronJob's facts include `Last schedule` in K59 and `null` there in the code (the plugin has the row).
- **E5 (mock and the contract): deleted and not found.** The mock titles a deleted object `<name> was deleted` and one that never was `<name> was not found`; the host's `not-found` state has one title and a message. The plugin says the two sentences in the message (ruling 3); the title is the host's for both.
- **E6 (mock): `N unavailable` is computed from the counts** (`desired − available`); the API reports `status.unavailableReplicas`, which `kubectl describe` prints; the plugin says the API's number (A19).
