  jobs      gh api "repos/omniviewdev/omniview/actions/runs/<run>/jobs?filter=all&per_page=100" --paginate --jq '.jobs[] | select(.name|test("^Kit probes shard")) | [.id,.name,.run_attempt,.started_at,.conclusion] | @tsv'

  log       gh api --allow-escape-sequences repos/omniviewdev/omniview/actions/jobs/<job>/logs
  in a log  the unit or control a line belongs to is the last `##[group]<unit name> (<control>)` line before it (the unit `terminal-data` has no `(control)`). A sample is a line that starts, after the timestamp, with
            `hidden chromium, 20 MB written while the panel was hidden:` (the two-space echo of "Last lines of its output" is not one): burst = `the burst took N ms of the page's task`, long tasks = `(the longest Y ms, Z long tasks)`,
            callbacks = `N callbacks ran in X ms`. A failure is a line that starts with `NEGATIVE CONTROL` and holds `the longest long task N ms`. The 2 MB lines and the WebKit lines are read the same way.
