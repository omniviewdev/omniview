2026-11-25 host change landed (backend/pkg/plugin/resource): a start that ANSWERS a failure status without an error is a failed start (agent ProblemsOperations.GoAnsweredStatus).
Before: only a start whose provider call RETURNED AN ERROR was kept and told (FAILED event with `error`, readiness FAILED + readinessError). An answered UNAUTHORIZED, FORBIDDEN, FAILED, ERROR... kept nothing, so the
class the window used to remember itself (outcomeOfStatus, ui-next/plugins/host/connections/words.ts) was lost from the list. Now:

Files: connection_start_failures.go (answeredFailureCode; publishAnsweredFailure; announceStartFailure, the one place that admits, keeps and emits, which publishStartFailure now also calls),
controller.go (the branch of StartConnection placed right after the provider call, the payload's doc comment, the comment at forgetStartFailure that says what the answers that are not failures do),
types.go (doc comment of ReadinessError), connection_start_failure_test.go (27 test functions, 134 subtests; the error path's tables now run for each way a start fails).

What a start that answers does (UNAUTHORIZED, FORBIDDEN, FAILED, ERROR, BAD_REQUEST, NOT_FOUND, and the SDK's TIMEOUT, UNAVAILABLE, REQUEST_ENTITY_TOO_LARGE):
  - one connection/status event: the status the provider answered, named as every answered start's event is (the connection the provider returned, else the id), and `error`;
  - `error` is the public error of the CLASS of the status, built through the same gate as the error path (apperror.ForResource(resource.NewError(code, ""), request.ID())), with no text of the status
    (its Error and Details are never read);
  - the failure is kept, under pluginsMu.RLock after the same re-admission as the error path (a retired generation, a caller that gave up, a route reconfigured meanwhile: nothing kept, nothing emitted, the
    refusal is the start's answer), before the event is emitted; a later failure replaces it; a later answer that is not a failure, a stop, a removal, a sync that drops the connection and a plugin
    init or unload clear it, as for the error path;
  - GetAllConnectionStates then reads FAILED + readinessError (the same error).
Classes: UNAUTHORIZED -> UNAUTHORIZED; FORBIDDEN -> FORBIDDEN; the rest -> INTERNAL, NOT PROVIDER_ERROR as the brief said: PROVIDER_ERROR is a 502, which classOf reads as `unreachable`
("Not responding"), and the brief's own acceptance is that the rest read `failed` (run with bun on stateOfReadiness: red-go-answered.txt). The three SDK failure words the brief did not list
(TIMEOUT, UNAVAILABLE, REQUEST_ENTITY_TOO_LARGE) are failures too: the window made `failed` of every answer but CONNECTED.
Not failures (no record, today's single event with no error key, and they end an older failure as every answered start does): CONNECTED, PENDING, DISCONNECTED, UNKNOWN, no status at all, and a word
this host does not know.
The status the caller of StartConnection is given is the provider's own answer, untouched, as before (the window's outcomeOfStatus and safeReason read it).
