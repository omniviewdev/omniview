## What was built

- **Contract (additive, versioned).** `contract/v1.ts`: `DetailPageV1` (`kind: 'detail'`, a static `definition`, one data hook `usePage` answering `{ scope?, source }`), `RouteV1.params` (the route's string parameters: the object's identity), the detail types re-exported. `admit.ts` refuses a bad detail definition by name, a `home` or a sidebar entry that is a detail page, and a list that is not a list page; `openable` drops a detail leaf. **Decision: a minor addition to `contributionV1`, not `contributionV2`.** The seam design's rule is that the export name is the contract of a generation of hosts and a second export exists so one archive can serve two generations that both exist in the field (`v1.ts` head, `n19-plugin-seam.md` 2.1). The detail page changes nothing that exists (a new page kind and a new member that older hooks ignore); every bundle written before it is admitted and drawn as before (`admit.test.ts` keeps a frozen one); a host that lacks it refuses a bundle that uses it by name at admission (`kind is "detail", and this version draws "list" pages`, the `contract` failure: R11's refusal on proof of mismatch), and V1 has no host in the field that updates apart from its plugins (the feature channel). A second export would make every plugin build and keep a list-only contribution for hosts that do not exist. The three conditions, and what would make it V2, are written at the head of `v1.ts`.
- **Host page.** `ui-next/page/DetailPage.tsx` over `detailDefinition.ts` (types), `detailView.ts` (the decisions, pure), `detailIdentity.ts` (name, `{name} · {Kind}`, facets). The header (kit `PageHeader`: tile, h1, state chip, at most four facts, commands in the one order, the operation slot, the back path from the route), the kit's `Tabs`, a `TabPanel`, and the Overview: a status line and `kv`, `table`, `tags` and `list` sections with `placement: main | aside` and `priority`, each absent when empty. Two columns that stack below 992 px of page width (the mock's `.readable-pair` rule). States use the kit's state bodies (`LoadingBody`, `EmptyBody`, `ErrorBody`, now exported from `DataView`). The Refresh is the page's, felt in the slot, as the list's is. **A read that fails while the object is on screen keeps the object and is said in the slot** (`Couldn't refresh <name>: <message>`, the plugin's Retry, Dismiss).
- **Tab, path, qualifier.** `describeDetail` (`plugins/host/contributions.ts`) builds the tab's face from the route and the definition alone: title `{name} · {Kind}`, glyph, path `Plugin › connection › list › name` with the list crumb a link back, scope, facets (the definition's parameters first, then the connection). It is the same before the hook has run and in a tab never shown. The sidebar keeps the list's entry selected; the registration says `document` for a detail page.
- **A list row links to a detail.** The kit `Link` in the host's `LinkProvider` (`plugins/host/links.ts`): a native `<a href>` whose address is the hash grammar (`#/<plugin>/<page>?connection=…&name=…`; `route.ts` reads and writes the object's parameters: `addressOf`, `HostRoute.params`). A plain click or Enter on the focused link is smart open (`tabs.open`, `how: smart`); Command or Control, or a middle click, opens a background tab; Command and Shift a new tab; Alt here. The page's connection goes with the link. A list page's hook is told no parameters (`RouteV1.params` is empty for a list).
- **Kit parts** (each in its own directory with examples, an a11y matrix and tests): `Link` (+ `LinkProvider`), `Tabs` (+ `TabPanel`, a tab stop of its own), `StatusSummary`, `KeyValue` (rows keyed by an optional `id`, else the label), `SectionCard`, `TagList`, `ListRows`; `DataView` exports its three state bodies. The parts' "writes nothing to the document root" tests share one guard, `packages/kit/scripts/rootWrites.ts`, with its own tests. API report updated.
- **Fixture plugin.** An Items list whose rows are links, and an `item` detail page, with one item in each data state: `orders-api` ready, `ledger-sync` loading for ever, `ghost-service` not found, `vault-keeper` denied, `flaky-gateway` error with a Retry that works; the ready one has a header with four commands, three tabs, a status line, a Details list, two tables, a section that has nothing to say (not drawn), recent warnings and labels in the aside.

## Decisions I took, for the lead to confirm

1. **Minor addition to V1** (above). If the lead prefers a V2, the change is the export name plus a second admission path, and the host would carry both.
2. **The header draws the back path (breadcrumb)**, as the mock's page-kit detail and PH3 do, and the status bar draws the same path (S61: "no breadcrumb repeats in the page header", ch 03:92). The mock disagrees with itself; I followed the acceptance reference, so the probe compares the whole header with no adjustment. Dropping the page's copy is one prop (`path`).
3. **`Link` and `LinkProvider` are public kit API.** A plugin's cell writes `<Link to={{ page, params }}>`; the host provides the handler. The link's address is the hash grammar, extended with the object's parameters, so a link nobody intercepts still goes where it says and a deep link opens a detail tab.
4. **The in-page tab is page state**, not part of the route: a restored tab opens on Overview. The model's `replace` and a `tab` parameter that the key leaves out are the design's way; not built.
5. **The state bodies of the data view are exported** (`LoadingBody`, `EmptyBody`, `ErrorBody`): "not found" is the one-line empty body, "denied" and "error" the notice, "loading" the skeleton, so no new state visual exists.
6. **A failure that follows a view keeps the view and is said in the header's slot** (the page's own acknowledgement path; moves nothing). The list page keeps its gap until 1a.8.
7. **Links in running text fail axe's `link-in-text-block`** unless underlined at rest; the mock's link has no rest underline, so `Link/InSentence` is laid out as separate boxes. Decide: underline at rest, or never put a link inside a sentence.
8. **Light theme**: the muted count on the selected tab's fill is 4.08:1 (the mock paints it the same way); the kit probe checks the default theme only.
9. **CI**: `ui-next-kit-probes.yml` gets a step for the detail probe and its timeout goes from 30 to 40 minutes (the last run took 29, 20 of them the cold install of the browsers).
10. A detail page's tab count badge arrives with the data: the faces after a counted tab move right by its width once (the probe tracks the strip and the first face, which do not move).
11. **The in-page panel is a Tab stop** (WAI-ARIA tabs pattern, A14): a panel whose first content is text could not be reached otherwise. A panel that starts with a control has one stop more than it needs.
