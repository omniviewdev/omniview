## 2. What this slice builds (decisions)

1. **A singleton host tool "Ports"** in the bottom panel (one registration line in the tool registry and a singleton body path in the panel body), not a per-session tool. It lists the forwards the host reports, live: `ListAllPortForwardSessions()` on mount and the two events afterwards.
2. **Rows come from the producer only.** Columns: Resource (the resource id, or the static address; the second line carries a stated reason), Mapping (`127.0.0.1:<local> → :<remote>/<protocol>`), Connection (the connection NAME, never the id), Status, Actions. No Namespace, bytes, errors or latency column: the producer does not state them (the mock's Namespace column is a Kubernetes provider column; the generic session has no namespace field).
3. **State words** follow the producer: `ACTIVE` "Running", `PAUSED` "Paused", `STOPPED` "Stopped", `FAILED` "Failed". Two states are the window's own and said as such: "Stopping" (after Stop was pressed and until `closed`), and a forward whose plugin stopped: the plugin lifecycle events the host already publishes name the plugin that stopped, and the session names its plugin, so the row says "Stopped" with the second line "Its plugin stopped." (two stated facts, no guess). A row the host stops listing after a re-read is dropped with its `closed` event or marked the same way.
4. **Actions, all real:** Stop (`ClosePortForwardSession`), Open in browser (the host's open-external call, `http://127.0.0.1:<local>`, only while Running and TCP), Copy address (the clipboard, `127.0.0.1:<local>`), and the same three in a row menu on the kit's unified menu host (right click, Shift+F10, the Menu key). **Restart is not drawn**: the host has no restart (a fresh start needs the original options). Open in browser is the lead's order; the mock has none (section 3).
5. **START has a real path through the plugin contract** (an additive optional member, see the contract note in the reply): `ctx.panel.ports.forward(request)` next to `ctx.panel.logs.open`: the page names the resource and the ports, the host fills the plugin and the connection from the page's scope, starts the forward through the typed `NetworkerClient` start and reveals the Ports tool. The fixture plugin gets a real Go TCP forwarder and a page with a button that uses it; the Kubernetes Pod page's enabled button is the plugin's next slice. The Ports tool itself draws no "Forward port…" button: there is no tool-level start (it needs a resource chooser, a later slice), so no dead control.
6. **Real data in the seam:** the fixture plugin forwards a local port to a fixture TCP server; the scenario starts it from the fixture page, sees the row, connects to the local port and reads bytes, presses Stop and sees the row end, and kills the plugin and sees the row say so.

### Decisions for the NEXT pull request (before any real consumer, the Kubernetes Pod page): S4 of the independent review

The contract says "call it from a user's action" and nothing enforces it: a forward started from the render of a page (no user activation) is accepted; there is no cap (1,000 forwards in 2.0 s: the plugin process held 1,001 listeners, 1,018 descriptors and 5,023 goroutines; with `ulimit -n 256`, 242 were made and the rest refused in generic words, leaving the plugin no descriptor for its own connections) and no bound on the request's strings (a 1 MiB `resourceId` is accepted and sits in every list answer). Tightening a gesture rule or adding a cap AFTER plugins ship breaks plugins that call from an effect or hold many forwards; loosening never does. **Options:** (A) record "no gesture, no cap" as the rule (a plugin is trusted code, R10); (B) require user activation (`navigator.userActivation.isActive` at the call, a typed refusal `FORBIDDEN` otherwise), cap forwards per (plugin, connection) at a documented number (a typed refusal `RESOURCE_LIMIT`), and bound `resourceId` (and the other strings) at the host (a typed refusal `INVALID_REQUEST`). **Recommendation: B**, with the cap at 64 per (plugin, connection) (generous for a person, far from the 242 descriptors a loaded plugin has) and `resourceId` at 1,024 characters; the gesture rule needs an owner decision because a palette command or a keyboard shortcut also counts as activation but a timer or a render does not. Not in this push.

**Settled in PF2 (the lead's ruling, 2026-11-25): B.** The numbers, the words and the measurements are in `PF2.md`.
