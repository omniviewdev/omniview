## Goal

Add the per-kind glyphs the Kubernetes plugin's lists and sidebar need, named by what they DEPICT (never by a kind: the vocabulary guard rejects kind words), from the set and version the kit already uses, cap 30 new.

## Source

Lucide, ISC (Feather's MIT notice for the glyphs it derives from), the same set the registry already carries: each entry is the design mock's own `LuXxx` artwork (`icons.js`, mock tree `c8e44a445bdbec07ad81d5ec036dd26cc0a8bef0`), which pins no Lucide version number; no dependency is added, `packages/kit/NOTICE` already holds the Lucide and Feather notices and is unchanged. Authored like every Lucide glyph before: shapes become path data, the shapes of one paint merge into one `<path>`, numbers keep at most three decimals, 24 artboard, stroke 2, round caps and joins (the same as `box`, `layers`, `server`, `scroll-text`).

## Decisions and findings for the lead

1. **The registry is not tree-shakeable per glyph, and is not meant to be.** `IconName` is a closed union and `Icon` reads `GLYPHS[name]` at run time, so any bundle that imports `Icon` or `GLYPHS` holds every glyph. Measured with the kit's own Vite (rolldown), minified: a bundle that imports `GLYPHS` and reads `rocket` contains the path data of `repeat`, `settings-2`, `activity` and `scroll-text` (all true); the same for a bundle of `Icon` with `name="rocket"`. The assignment's "a bundle importing one new icon does not contain another" cannot hold for this design and was not made true: per-glyph shaking needs one export per glyph and a different `Icon` contract (a glyph object instead of a name), which is a decision for the lead and also removes `isIconName` for wire names. Cost of the thirty glyphs, registry only, minified: 9,241 to 17,529 B (gzip 2,433 to 4,276; brotli 2,140 to 3,742), i.e. +8,288 B raw, +1,843 gzip, +1,602 brotli in every bundle that carries the registry. Registry byte budget test: 7,950 to 15,100 (the thirty add 7,060 B of registry data).
2. **`settings-2` has a digit.** The glyph-name test allowed lower-case words only; it now allows a word to end in a digit. Lucide's name is kept because the assignment names it; the alternative is `sliders-horizontal`-style renames, which the mock does not use.
3. **`key-round` costs three elements, not two.** Lucide draws the pin as a filled circle that is also stroked: one extra layer with a fill. The element-count test lists it with the two-tone status glyphs.
4. **`globe` was already a name in use**: the palette's "Search everywhere" row (`ui-next/shell/core/palette/compose.ts`) names `globe`, which was an unknown name until now and drew the fallback; it now draws the globe. Nothing else in `ui-next/` uses one of the thirty names.
5. **Mock key table is in `shell-kubernetes.js`** (`KIND_GLYPHS`, `GROUPS`, `CUSTOM_GLYPHS`), not in `k8s-resource-definitions.js`.
6. **Which thirty.** The eleven named in the assignment, then by order of need: the rest of the workloads, network and config lists (`repeat`, `layout-template`, `target`, `split`, `brick-wall`, `gauge`, `ruler`, `scaling`, `umbrella`, `arrow-up-wide-narrow`, `cpu`, `hourglass`), the Events row (`activity`), the six group icons the sidebar draws (`settings-2`, `network`, `database`, `shield`, `shield-check` with `layers` there), the first storage kinds (`hard-drive`, `hard-drive-download`) and the custom-resource kind (`blocks`). Say if the plugin's next lists want another thirty first.
7. **The kit probe's viewports are still 1440x900 and 1030x720** (row N23 moves them); the glyph geometry check does not depend on the viewport.

- **Each glyph is the mock's artwork.** Authoring check (not committed, see Dev tools): every one of the thirty rasterized beside the mock's own `LuXxx` markup at 12, 16, 20, 24 and 96 px, in WebKit and Chromium (150 rasters per engine). No pixel differs by more than 85/255 except four pixels at 113/255 in WebKit (`target` at 20 px); 9,565 of 317,760 pixels differ at all in WebKit and 5,184 in Chromium, all anti-aliasing at stroke edges (a circle element and an arc path are flattened differently). The check found a real bug on its first run (a moveto written `m10.6 15.7.3-.9` was read as one number: `server-cog` came out wrong); the script was fixed and the check passes. Negative control: with `globe`'s path moved by one unit the same script reports 10 of 150 rasters with pixels off by more than 96 (WebKit), 9 (Chromium); the same script with the unmutated glyph reports none.
- **Box and optical centre in both engines** (kit probe, new `glyphGeometry`, in the probe CI already runs): for every glyph of the registry (65) at 12, 16 and 20 px: the svg is exactly the size, the ink (path bounding box plus half a stroke) stays inside the artboard, and its centre is within the tolerance of the artboard's centre. Tolerance = the worst of the 35 glyphs that were there before: 1.0 on the 24 artboard (`case-sensitive`), 0.5 on the 16 one; the thirty new glyphs measure 0.85 at most (`file-cog`). Sizes are the kit's scale 12, 16 and 20 (the scale has no 14). Negative control: `target`'s outer ring moved 1.5 units (inside the artboard, so only the centre assertion can see it) is reported in WebKit at all three sizes; with the centre assertion removed the same probe run passes (3 failures to none). A committed control step in CI would need `.github/workflows/ui-next-kit-probes.yml`, which this step does not own.
