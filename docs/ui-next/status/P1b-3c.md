## The rule, and the deviation from the mock

The mock's PO1 (ch16 S114a; `sessionsOf` in `shell-panel.js`): a plugin that is off contributes nothing; its sessions are hidden, its running ones end, and they come back ended with the plugin. A21 deviates from it for the sessions of a tool owned by the HOST (today the Logs tool), **whatever their state** (the lead's ruling; the first version kept only what the unload ended): when their plugin is unloaded they stay listed and mounted until the user closes their tab. A running or starting one is ended with the cause `The plugin was unloaded.`; one that had already ended or failed stays AS IT WAS (its own state, cause and time untouched). Each keeps the lines its view had read; the host closes the stream (so the backend session is not leaked). Everything else keeps PO1:

| Session | At the unload | When the plugin returns |
| --- | --- | --- |
| host tool, running or starting (**held**) | ended with the cause, stays listed, body mounted, lines kept, stream closed once, link to the resource disabled with the reason | still ended, still held, link works again; a new press opens a new session beside it (a twin, `(2)`) |
| host tool, ended or failed on its own before (**held**) | stays as it was (state, cause, time), body mounted with its lines, stream closed once; its card says its own words, then `The plugin was unloaded.`; link disabled | unchanged; link works again |
| a tool the plugin brought | hidden (PO1) | back, ended |
| restored from a saved window | hidden until its plugin has loaded, then like any other | |

**The invariant, in words** (`core/panel/README.md`): of a plugin that is off, the sessions that are listed (and so mounted) are the held ones and nothing else of that plugin's; a held session is a session of a tool of the host (its id has no colon), is over (ended or failed), and never changes until its tab closes. A held session may carry no cause (it ended before on its own without one).

**Decision 2 (accepted by the lead): a kept session is saved as ended without lines.** `held` is a fact of this run: `serialise` never writes it (identity only, as for every session) and `restorePanel` never reads it, so after a restart the session comes back as every restored session does (ended with `RESTORED_CAUSE`, no lines, hidden until its plugin has loaded, then like any other). Tested: `persist.test.ts` and the fuzz (the document never contains `held`; a restored panel has no held session).
