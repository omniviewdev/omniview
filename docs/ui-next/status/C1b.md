## Decisions and deviations from the mock

- Native `<dialog>`: top layer and inert background for free. jsdom has no `showModal`, so the test support polyfills it.
- Focus: remembered when it opens, restored in a microtask when it closes, only if the focus is lost. A command that moved the focus (Toggle panel puts it in the panel) keeps what it did: found by the host provider's author, fixed test first in `focus.ts`. The Search control focuses itself on click (Safari does not focus a clicked button).
- A page row says whose it is, then the groups it sits in ("Plugin · Group › Subgroup", as the mock's destination rows do). The host's first version drew the groups alone; the seam scenario met two plugins with a group of the same name, which gave two rows that both read "Page: Crash, Things". Fixed test first in `host/palette.ts`. The seam fixture's two plugins are built from one source and carry one name inside their bundles (the rail's labels differ), so there the rows still read alike and the check takes the first, which is the rail's first.
- Home and End go to the first or last row only when the caret has nowhere to go. Hover moves the active row only when the pointer really moved.
- The refusal text of a row that cannot open is shown in the footer in place of the key hints (a live region alone gives a sighted user nothing).
- Placeholder colour is `--ov-fg-muted` (the mock leaves the browser's own colour); the input has no focus ring (as the mock).
- Forced colours: an outline on the active row only (the closed-scale lint forbids system colours). Not built beyond that.
- Chips are local to the palette (the kit's `Chip` is one mode at a time and has no glyph). The `tabpanel` role is on the results region because the kit's `Tabs` sets `aria-controls` to `<id>-panel`.
- Accessible names hold what a row shows (axe `label-content-name-mismatch`, WCAG 2.5.3): parts are spaced as words; a row's name carries its chord or its action word; the Search control is "Search ⌘K" (the visible hint is text, and the rule compares visible text, not `aria-hidden`); the `+N` button is "+2 more, show all 5 sources".
- Model change (test first, `async.test.ts`): a source row's accessible name said "Degraded" where the row says Searching…, Unavailable, Partial results or Showing N of M. `ownRow` now names the word the row shows. Nothing else in the model changed.
- Model change 2 (test first, `activate.test.ts` and `oracle.test.ts`): the footer says New window, and Shift+Enter opens one, only when the host passes `windows: true` (default off). The shell has no second window and the tab model answers `{ status: 'window' }`, so the palette used to close and do nothing. Now the footer says four keys, and Shift+Enter is refused with "This window cannot open another one yet." without calling the tab model. The probe fixture passes `windows: true`, so its footer has the mock's five keys for the geometry; the host's palette does not.
- The mock reference's query is neutral, and the reference file is not exempted: the kit's plugin-vocabulary guard (A13) allows plugin words only in `packages/kit/probes` and the fixture plugin. The first `mock-palette-measure.mjs` typed the mock's own page name into it and described the page by that name, so the guard refused the script and `mock-palette.json` (its note). Exempting the file would have meant editing the guard (the kit's, and not this step's) and widening the places a plugin word may stand in the host's tree, which is what the guard is there to stop; and the words were never needed: the query only has to draw two result groups, and the reference compares boxes and columns. So the script types `ods` and says "a connection's list page", and the reference was measured again from the same pinned tree. `MOCK_TREE` (`c8e44a44…`) in the script and `mockTree` in the JSON are unchanged, the lab's mock directory is still at that tree with no modified file, and `packages/kit` is untouched. What changed is the values of the query scene (10 rows, not 17), and the palette matches them at 0 px.
- Mock vocabulary stays out of `ui-next/`: fixtures use invented words.
- Keys are written for the platform, and that is the only thing that differs by platform: a Mac gets the signs (`⌘K`, `↵`, `⌥↵`, `⌘⇧↵`, `⌘↵`), Linux and Windows get words joined by plus (`Ctrl+K`, `Enter`, `Alt+Enter`, `Ctrl+Shift+Enter`, `Ctrl+Enter`), a screen reader gets them in words on both (`Command Enter`, `Control Enter`), the host's commands follow (`⌘W` and `⌘J`, `Ctrl+W` and `Ctrl+J`), and Close window is offered only on a Mac. The signs and the arrows come from the kit's bundled face on every platform. Windows is the same text as Linux (`platformOf` says `mac` or `other`) and is not probed: the CI runner is Ubuntu.

## Row-count bound (confirmed from the model, not changed)

At most 20 rows from one async provider (`LIMITS.rowsPerProvider`), at most 8 providers asked and 4 in flight, at most 50 rows on screen in total (`LIMITS.rows`), and at most 3 runs in the band (the rest fold into `+N`). A synchronous provider may hand back up to 50,000 candidates: the model ranks them and caps the result. So the list is never longer than 50 rows and there is no virtualiser.

- Both times are a proxy: no engine says when a frame reached the screen, so each ends at the second animation frame after the DOM shows what was asked for (open: the dialog; keystroke: the input's text and a list that is the model's rows, row for row). That is two frames at 60 Hz, which is why they sit near 21 to 28 ms and move little; the key's own cost is the third column. In Chromium the proxy reads about 10 ms above the engine's Event Timing. The first open of a page is the slow one (32 ms in every run: the p95 of WebKit 1440 x 900 is that sample).
- One React commit for a character, a Backspace and an ArrowDown, each (development build). 0 layout moves of any named region of the window or of the Search control from the chord on, and 0 layout shift in Chromium (WebKit has no layout-shift observer; the sampler's 0 moves is what it reads). Before the chord Chromium reads 3.7e-6 from the font swap at load (`shift.beforeTheChord`), which is the fonts' and not the palette's.
- A closed palette holds one listener (the chord's: 27 on `window` and `document` before the palette is used and 27 after it was opened, typed in and closed) and no timer, interval, frame or idle callback, before and after use; no callback runs in a second. Open, it adds 0 listeners and holds one timeout (the 450 ms announce). After 30 open and close cycles the DOM is unchanged, nothing is inert, and the focus is on the page.
- The empty query shows 0 rows on the perf fixture, and no query it types shows more than 17 rows, so the 50-row cap is not reached there.
- Not measured: real paint time; the timers of async providers (the runner's debounce, timeout and loader), since the fixture's providers are synchronous. The Linux `Control+K` branch ran on the runner (the keyboard section passed there). The perf section's own negative controls (11 faults: a leaked listener, timeout, interval, frame or idle tick, a moved Search control, a moved or removed region, a second commit per key, a DOM that differs from the model, a second chord listener) were run by hand once and all were seen; they are not in CI.

## Spec for C1c (plugin providers through `contributionV1`)

- A minor, optional `search` member beside `panel` on `contributionV1`: `{ match?(query, scope): Candidate[]; search?(query, scope, signal): Promise<{ rows, limited?, partial? }>; section?: { id, title }; supports?: kinds/scopes }`. `match` for small sets (ranked by the model), `search` for remote ones (the model debounces 150 ms, times out at 5 s, caps at 20 rows, one section each).
- Admission: an older host that does not know the member refuses by name; a plugin without it is unchanged. The host registers the provider when a plugin is admitted and calls `removePlugin(id)` when it unloads.
- Kubernetes-style resource search on demand: chips connection, then type, then resource; the plugin's `search` receives the chips as `scope` and does the query and the limit in its backend, so the palette never holds the full set. This needs `Into.kind: 'plugin'` (above) and a way to go from a host plugin home into the plugin.
- Icons: plugin candidates name glyphs from the kit's registry; unknown names fall back to `box`.
- Recents persist in the session slot through `createPaletteSaver` (the model has it; C1b does not wire it).
