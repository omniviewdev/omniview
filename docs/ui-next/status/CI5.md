## The channel mTLS tests

`TestCreateBackendEnablesChannelAuthentication`, `TestCreateBackendChannelIsMutuallyAuthenticated`, `TestCreateBackendRefusesPluginThatIgnoresChannelCertificate` and the three cases of `TestChannelRejectsClientWithoutHostCertificate` skip on Windows: `fixture uses a Unix executable wrapper` (`loader_channel_mtls_test.go:168`, `loader_channel_auth_test.go:22`). Why: `channelWrapperFor` writes `bin/plugin` as a `#!/bin/sh` script that runs the test binary as the plugin child (`-test.run=...`) after a shell preamble (the first test's preamble prints `PLUGIN_CLIENT_CERT` to a file), and it puts the child's socket under `/tmp`; `CreateProcess` cannot run a shebang script and the Windows host looks for `bin/plugin.exe`. **Can they run on Windows? Yes in principle, not by a skip edit:** the production path (go-plugin `AutoMTLS`, the host certificate in `PLUGIN_CLIENT_CERT`) is the same code on every OS (the transport is TCP loopback on Windows, a Unix socket elsewhere); what is missing is a fixture, for instance the test binary copied to `bin/plugin.exe` that picks its child test and records the certificate from Go and the environment instead of the wrapper's arguments and preamble. Until then **mutual authentication of the plugin channel is not tested on Windows at all.**
