## What a pull request that changes only per-unit files gets now

`scripts/ci/ci-scope.mjs --for probes` still answers `scope=pr` or `scope=full`, and now also `full_units=<ids>`: the units that get the full treatment on the pull request, **every negative control in both engines**. Every other unit runs as on any pull request (its probe in WebKit, no controls). The plan packs the pull-request probes and the full units together (`probe-shards.mjs --scope pr --full-units a,b plan`), a shard tells every unit but those the engine (`ENGINES=webkit`), and `Kit probes` requires the full units' controls too and prints, in its own line and summary, which units had the treatment and why (`scripts/ci/ci-scope-units.mjs` gives each file's reason).

What is attributed to a unit (`attribute`, `scripts/ci/ci-scope-units.mjs`), and nothing else:

| changed file | units that get the treatment |
|---|---|
| `scripts/ci/probe-units/<name>.mjs` (a name with no path and no import of any file) | the units of that file; a deleted file has none (the manifest holds the floor) |
| `scripts/ci/probe-units.manifest.json` | the units that run the scripts whose entry changed (the base and the head are compared entry by entry) |
| `scripts/ci/probe-shards.layout.json` | the units whose seconds changed (`note` is free; anything else is refused) |
| a probe script a unit runs, or a file only one probe script reads (its fixture) | the units that run that script and those of a script that reads it (a wrapper) |
| a file of a probes directory that is new and that no probe reads yet | none (the probe that reads it is a changed file of its own) |

FAIL CLOSED (the run is full, as before; each is a test with a forged diff, 64 cases in `ci-scope-units.test.mjs`): any other file of `scripts/ci`, a workflow, a dependency file, the scope code (`ci-scope*.mjs`), the engine and the packer; a unit file that imports anything (`import`, `export ... from`, `require(`, `import(`) or is not `scripts/ci/probe-units/<name>.mjs`; a manifest or layout that does not parse (either side) or changes more than a unit's seconds; a file of a probes directory that existed and that no probe reads, a deleted one, a file that more than one probe script reads (a shared helper: the kit's harness, `probe-lib.mjs`, `build-cache.mjs`, `lib.mjs`: 88 of the 163 files of the three probes directories), a script that more than two others read; a table of units that does not load. One shared file in a diff makes the whole run full, whatever else it holds.

What a unit that is NOT in `full_units` loses is only the controls and the second engine (its probe runs in WebKit as on every pull request), so the reading of "who reads this file" may over-include (a file's name found in the text of any file a probe reaches, a path written as an import or as a string) and never has to be exact. A probe that reaches a file by a name it builds at run time is not found; for such a file that existed, the run is full (nothing reads it, as far as the reader can see).

Also in this change: **the files that only the other workflow reads do not count** (`OTHER_WORKFLOWS`): the probes ignore `scripts/ci/seam-*`, `scripts/ci/main-red*` and `e2e` directories; the seam ignores every probes directory and the probe table, its manifest and the layout record. `plugins/fixture` (the probes read it) and `probe-shards.mjs`, `probe-pack.mjs` (the seam imports them) stay shared. So a pull request that adds a probe runs the seam as any pull request (4 jobs, WebKit) and one that changes a scenario runs the probes as any (3 shards).

## The seam: not attributed to a scenario

The seam's scenarios and their controls are functions of ONE 12,000-line file (`ui-next/plugins/e2e/seam.check.mjs`) that share its harness, its helpers and its tables, and a new scenario adds a phase to `PHASE_IDS`, a branch of the dispatch and a unit of `seam-units.mjs`: shared files, full by the rule above. A change inside one scenario's function could be attributed by line ranges, but that needs a map from scenario to its declarations that a test proves closed (no other declaration names them), and a reader of 12,000 lines at the top level of a file that has template literals with lines at column 0. That is a gate that must be right every time, for a pull request that touches a scenario in the middle of the file. It is not shipped on a guess: **the seam stays "the file changed: full seam"** (8 jobs, 3,500 runner-s). The sound split is one file per scenario (`seam/<phase>.mjs`, a table in `seam-units.mjs` that names its file, the same shape as `probe-units/`): a diff of one scenario file is then attributed by path with the same `attribute` rules (a file that imports a changed shared helper is full). That is a refactor of the check, not of the CI, and is proposed as N34.

## The `process` control's wait

`seam.check.mjs` (`checkProcess`): the recovery's attempts each tell the window `reloaded` then `failed` (`plugin/unloaded` frames); the host says that it gives up with its own event, `plugin/crash_recovery_failed` (`backend/pkg/plugin/health.go`, `beginRecoveryAttempt`, emitted after every attempt's frames), which reaches the window's frames (they keep every `plugin/*` event). N32's "6 s of quiet" is replaced by waiting for that frame (60 s): frames of one window come in the order the host emitted them, so what the window was told is final once it has come. **[INFERENCE until the seam run of this PR is read]**: that the seam host forwards the event to the page; the run's `process` phase and control are the proof.
