## 2. The four tripwires: what each protected, why the new behaviour is right

Each test failed on the pin as written, and each edit was made against the same SDK bytes the tag carries. The edits hold only with the bump (on `v0.20.0` the host would print the placeholder of the old client), so they are in the same pull request as the pin.

**T1. `TestPinnedSDKClientStillLeavesTheSentenceInTheStatus`** (`backend/pkg/apperror/resource_text_test.go`).
- *Protected:* the host read a plugin's error sentence in two generations. The SDK client of `v0.20.0` put the placeholder `"resource operation failed"` in `Message` and kept the status, with the plugin's `LocalizedMessage` if it sent one, in `Err`; `ForResource` then read the sentence back from the status (`statusSentence`, the status branch of `providerSentence`, the placeholder in `sdkPlaceholders`). The test is the tripwire for the day the pinned client restores the sentence itself, when that reading becomes a second pathway.
- *Why the new behaviour is right:* the client now restores the sentence into `Message` and leaves `Message` empty when there is none (no placeholder), for a reviewed class only, valid UTF-8, at most `MaxErrorMessageBytes` (2048); the first English sentence decides; `Title`, `Suggestions` and `Err` never cross; the status text stays fixed. The host's gate is unchanged and still decides what the user reads (`PublicText`; FORBIDDEN, UNAUTHORIZED, INTERNAL, PROVIDER_ERROR and CANCELLED keep the host's words). Reading the status as well would read what the SDK declined to carry (a sentence over 2048 bytes, text that is not UTF-8) and so bypass the bound at the producer: the producer decides, the consumer does not infer.
- *Edit:* `statusSentence`, the status branch of `providerSentence` and the placeholder `"resource operation failed"` are deleted (the `errdetails` import with them); `providerSentence(roe)` keeps one filter, `actionPlaceholder` (`"action operation failed"`, which the SDK still puts in `Message` for an in-band action event: `ancillary_stream.go:507`). The tests lose the emulation of the old client and of a "restoring" client: the real SDK client reads a status built the way each kind of plugin builds it (`TestKubernetesStyleErrorsReachTheUI`: a carrying plugin and an older one, the four classes' strings pinned); the tripwire is deleted.
- *Evidence:* the 2 x 2 matrix in section 5: for a plugin that carries the sentence and for one that does not, the envelope of the host without the workaround is identical to the envelope of the host with it, in 15 of 15 cases.

**T2. `TestPluginWithoutCarriedSentenceGetsTheHostsClassText`** (`backend/pkg/plugin/resource/error_text_transport_test.go`).
- *Protected:* that a plugin built on an SDK that does not carry the sentence, which is every plugin published until a rebuild, shows the host's class text and never the SDK's placeholder. The test ran the SDK's own server over a real gRPC pair, which sent the class only, so the plain pinned server stood for the old plugin; its twin `TestKubernetesStyleSentenceReachesTheUI` made a carrying plugin with an interceptor (`carryTheSentence`) that added the `LocalizedMessage` the pinned server did not.
- *Why the new behaviour is right:* the pinned server carries the sentence itself, so the plain server is now the new plugin, and the interceptor would add a second `LocalizedMessage` beside the real one. The compatibility is still a requirement: older plugins stay in the field until they are rebuilt.
- *Edit:* `carryTheSentence` is deleted and `TestKubernetesStyleSentenceReachesTheUI` runs the real server. The older plugin is made by `olderPlugin()`, a server interceptor that removes the `LocalizedMessage` from the status the SDK built, which leaves exactly what an older server sent (the `ErrorInfo`); `TestPluginWithoutCarriedSentenceGetsTheHostsClassText` keeps its name and assertions.

**T3. `TestL3_06_ErrorPropagationViaGRPC/typed`** (`backend/pkg/plugin/resource/grpc_integration_test.go`).
- *Protected:* that the provider's text does not leak through the transport: a typed FORBIDDEN error with Message `secret` and an untyped `errors.New("secret")` crossed a real gRPC pair and the client's error held no `secret`. The guarantee was the transport's.
- *Why the new behaviour is right:* by #79 the transport carries the sentence of a typed error of a reviewed class on purpose (the SDK contract says `Message` is public-safe); the untyped error's text is a native diagnostic and still never crosses. What the user reads is the host normaliser's to guarantee, and it already refuses provider text for host-owned classes. **That holds where `ForResource` is the door.** The graph observation was not behind it (it copied the restored error as it came, `Message` included): the first push of this pull request rewrote T3 to rely on the normaliser and left that path open; F1 closed it (section 8).
- *Edit:* the table gains `crosses` (typed: the sentence crosses; untyped: nothing does), asserted at the client, and the leak assertion moves to the boundary the user sees: `apperror.ForResource(err, ...)` carries no `secret` for either class. A transport that stopped carrying the sentence turns this test red too.

**T4. `TestPinnedSDKStillLeavesTheManifestOpen`** (`internal/pluginmeta/pluginmeta_test.go`, with `TestNoHostCodeCallsTheLeakingSDKLoaders` and the package).
- *Protected:* Windows refuses to rename or remove a directory that holds an open file. The SDK's `types.LoadPluginMetadata` never closed `plugin.yaml`, so until the garbage collector ran, an uninstall, update or reinstall of a plugin whose manifest the host had read failed with "Access is denied" and left the plugin staged (B-72, CI5-W1). `internal/pluginmeta.Load` was the host's copy that closes; a go/parser test kept every host read on it; the tripwire fired when the pinned SDK closed the file.
- *Why the new behaviour is right:* #81 closes `plugin.yaml` (and `README.md`) before the loaders return, on every path; a close failure is returned only when the read succeeded. The two readers are now the same code, so the host's copy is a second pathway. The 14 callers (16 sites) take `types.LoadPluginMetadata`; the package, its parity tests and the source scan are deleted.
- *What was kept for the host's own reads:* nothing of the package: the host's own readers of `plugin.yaml` (`copyPluginMeta` in `installer.go`, `parseMetadataFromPluginPath` in `utils.go`) already close with `defer`. The proof for Windows is the lifecycle tests #634 un-skipped (uninstall, reinstall, update, rollback, the channel tests; they fail with "Access is denied" if a reader leaves a handle), which now run on the SDK's loader; `./internal/pluginmeta` leaves the Windows job's package list (`pr-checks.yml`, one word), because that step would fail on a missing package.
- *A difference to know:* the SDK returns `error closing plugin config file` when a close fails after a successful decode; the host's copy ignored such a failure. A failing close of a read-only file is rare; the SDK's choice is taken, not worked round.

## 4. Who is refused by the moved floor, and what they do

## 5. Skew: does a host and a plugin on different SDKs matter at the wire?

**No change of the wire, one additive detail, and none of it breaks either direction.** Per commit, read from the diff `v0.20.0..ae56fb09` (21 files; no `.proto`, no generated file, no `WireVersion`, `go.mod` unchanged):

Only a hand-written server can send a crafted status, and such a plugin could always put the same text in the lanes' legacy statuses, stream events and payload fields.

Those legacy channels carry the plugin's own text, raw, to the page and to some logs, as they did before #79, and the pin does not widen them (host: exec `controller.go:202-210,650-652,685-870`; logs `controller.go:187-205,646-861`; networker `controller.go:333-645`; metric `controller.go:494-698`, `finite_observation.go:207-210,464,491`, `stream_state.go:175-247`, `configuration.go`; settings `controller.go:221-230,420-427`; `profiling.go:119-142`; an exec `StreamError`, a log error event, a metric `OperationError`, `Message` and `Warnings`, the profiling status `Error`). **None of them goes through the gate and no host test holds them.** Not a line or two (about 40 sites over six controllers), so not fixed here: SDK1-i, for the lead. The metric spans, logs and tools/MCP results of the same lanes are class-only or fixed text (A11, A12; `tools/controller.go:208-214,433-448`, `settings` commit errors `CommitError.Error()`).

*C. The errors the host makes itself, through the gate's ten sites (second review, R1).* The gate acts on a provider's typed error (`errors.As` finds a `*ResourceOperationError`) and on nothing else: an error without one comes back as the same value (`TestControllerFailureHandsBackEveryHostMadeErrorAsItIs`). What could be taken for a provider's sentence and is the host's own is a host-made `*ResourceOperationError`. Every production controller's start, stop and shutdown was read (resource, exec, logs, metric, networker, tools, settings): the tools controller's `GRANT_DENIED` was the only one of a class the gate words as its own (INTERNAL), and it is fixed at the producer; the resource controller's two host-made `INVALID_REQUEST` (`resource/controller.go:363,395`) are of a class that may show a sentence and arrive unchanged (`TestControllerFailureKeepsTheSentenceOfAHostMadeTypedErrorOfAClassThatMayShowOne`). The tools controller's `GRANT_DENIED` (`tools/controller.go:232`) was the one that came back through the gate, and `resource/controller.go:363,395` are the two `INVALID_REQUEST` above.
