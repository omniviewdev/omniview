# T1 — the host's Terminal panel tool, first slice

**Status: PR for review (ready, not draft).** Branch `ui-next/t1-terminal`, rebased on `origin/main` 77ce06f8 (PR #656 merged). Owner agent `TerminalTool`. One slice: a terminal on the host's OWN shell, end to end, in the panel, behind `OMNIVIEW_UI=next`. After this slice's first push the owner ruled (2026-11-22): "for the terminal you don't need to follow the mock exactly but it needs to be an exceptional functional terminal that does what you would expect in an ide". So the mock guides the placement, tokens and words of the chrome, and the bar for the emulator is VS Code's and JetBrains' integrated terminals: section 14 is what was checked on the real host against it, and `T-terminal-bar.md` is the plan of the slices that follow.

**Later: T2a (`docs/ui-next/status/T2a.md`) replaced three things below with the host's facts.** The 4 MiB hold-and-drop-oldest of the exec feed is gone (the page acknowledges what it parses and the host's 1 MiB credit is the bound: nothing is dropped); "Close asks while a process runs" asks when the host says something runs or cannot say (`IsBusy`) and not when it is idle (decision 3, and the "asks for every live shell" lines); the session tab is named after the shell the host started, not `Terminal`; and an ended session says its exit code, signal or who closed it from the typed close. This file stays as T1 was built; where it disagrees, T2a.md is current.

## 1. What this slice is, and is not

In: the Terminal tool (order 10, the first tool, the one the panel shows by default, as the mock) with session tabs on the panel's session model (identity, twins, state words, card); **New terminal** starts the account's login shell on a pty of this machine (`ExecClient.CreateTerminal`); input, output, resize, exit as an ENDED session that is kept (scrollback readable, input off, said in words), a FAILED state in the producer's words; **Close asks** while a process runs; copy and paste chords; toolbar Clear and Copy selection; the focus rules (A14); the emulator (xterm.js 6.0.0) in a lazy chunk that costs nothing until the first terminal; seam scenario `r`; a probe with negative controls; status, catalog and brief for the Go step.

Later slices (none built, nothing drawn that does nothing): ordered into five slices by user value, with the features of both products' terminals beside what this one has, in `T-terminal-bar.md`. In short: a shell in a container from the Kubernetes plugin with a container picker; reattach after reload or restart; split terminals; search (Find); links; profiles and shell choice; Rename; the Paste button; the toolbar's other items (Stop, Reconnect, Inspect, More); Restart on an exited session (Enter); the `▾` targets menu; the chord Ctrl+Shift+` and the palette command "New terminal"; "Terminate session" as the close button's name on the tab (needs a shell-owned hook); the Reconnecting and Expired states (the host has neither); the other eight themes in the probe.

## 3. Decisions for the lead

1. **Terminal at order 10, the default tool** (Main's ruling, as the mock). The existing tool-name lists changed ("Terminal" first), and nothing else of those tests.
2. **Local shell only; no A22 re-activation.** Two shells on one target are two processes (the mock's `openTerminal` always creates).
3. **Close of a RUNNING terminal asks "Terminate session?"; Cancel has the keyboard; buttons Cancel and "Terminate session"; body "This ends the terminal session. Programs it left running in the background may keep running."** Unknown = ask: the written rule (S115, L12) asks when a foreground process runs and the host cannot say (catalog item 1), so every running terminal asks; `closeQuestionOf` stops asking for a session whose producer says `foreground: false`. The body does not promise that every program stops: measured, `CloseSession` kills the shell and the foreground program but a background job survives (section 7, Q9). **Correction to the brief:** VS Code does NOT confirm by default for panel terminals (`terminal.integrated.confirmOnKill` defaults to `editor`: only terminals in the editor area confirm, and the docs say the terminal shows no warning when a process exits); JetBrains does ("close the tab ... and confirm the process termination"). The written rule decides.
4. **Escape never leaves the terminal; F6 and ⌘J do.** VS Code sends Escape to the shell; JetBrains' default moves focus to the editor; the lead ruled Escape stays. xterm's key handler returns false for F6 and the app chords so the window's listeners get them. A keyboard user can always leave: probed (`keys.f6`, `keys.toggle`) and in the seam.
5. **Copy and paste.** Mac: ⌘C copies, ⌘V pastes, Ctrl+C is the interrupt. Elsewhere: Ctrl+C copies only with a selection and otherwise interrupts; Ctrl+Shift+C and Ctrl+Shift+V always (VS Code on Windows and JetBrains agree; on Linux they disagree, so "elsewhere" follows Windows). `macOptionIsMeta` is false (both products' default). Paste is the browser's paste event on the emulator (no clipboard-read permission).
6. **Toolbar this slice: Clear and Copy selection only**, a vertical toolbar of 28 px buttons (the mock's column). Find, Paste, Rename, Stop, More are later.
7. **Scrollback 5,000 lines** (the library's terminal keeps 5,000; the mock keeps 2,000 rows; the old host took the emulator's 1,000). Proved exactly (`memory.cap`): after 1,000,000 lines the oldest line kept is the one a 5,000-line cap and 9 rows leave. Held output while hidden: 4 MiB per terminal, drop oldest, counted and said ("[N KB of output were skipped]"). Both are constants (`SCROLLBACK`, `HELD_BYTES`).
8. **The emulator's stylesheet is injected at runtime from the lazy chunk** (`xterm.css?inline` in `@layer ov.components`), not imported as a `.css` file: the ui-flavour test wants one stylesheet with every rule in a layer, and this way the entry stylesheet gains none of its rules and the host's overrides (`ov.shell`) win by layer.
9. **The glyph is the nearest the kit has** until the icons step: `chevron-right` (a prompt's caret). `tool.ts` asks for `square-terminal` and uses it by itself the day the registry knows the name; nothing else changes. Request for the icons step: `square-terminal` = mock `icons.js:253` (the same artwork as `LuTerminal`, `icons.js:192`).
10. **The transcript's own lines are muted by colour, not by the dim style** (SGR 90, the theme's muted text, not SGR 2): the dim style is half the opacity of any colour and axe fails it for contrast.
11. **The probe is registered** as the unit file `scripts/ci/probe-units/terminal.mjs` (PR #656 merged, the shard table is gone): four units (the probe, 370 s; its sixteen controls in three units of 250, 300 and 175 s, so that none is near a shard's 432 s) and the probe and its controls are in `scripts/ci/probe-units.manifest.json`. `node scripts/ci/probe-shards.mjs check` is green (39 units, 131 controls, 21 probe scripts) and the engine's own 204 tests pass. **The listed seconds are a guess:** the laptop's, times 2.5 (section 8; taken at a load of 5 to 25), so the first CI run corrects them and its numbers go to the lead before any bound is touched. **The probe's bounds that are times were made to hold on a runner about 4x slower:** the flood's frames are a COUNT (a tenth at most may be later than two frames; the laptop has none to one in 300), a key reaches the process in 50 ms idle and 100 ms under a flood where the laptop reads 1 ms, and a task is under 120 ms where the laptop's Chromium has none.

12. **The terminal's own code (not the emulator's) is in the entry chunk**: +29,149 B raw, +10,042 B gzip, measured against the same build without the two wiring lines (section 9). Making the body, the screen and the dialog lazy too is a measured option for a later slice; the registry and the guard must exist when the panel opens.
13. **Command K clears a focused terminal on a Mac, ahead of the palette: a deviation from two written rules for ONE chord, for the lead to rule.** VS Code's docs (Terminal Advanced): "On macOS, Cmd+K is a common keyboard shortcuts in terminals to clear the screen so VS Code also respects that, which means Cmd+K chords will not work"; JetBrains' (Terminal): "To clear the terminal screen, press ⌘ K" (JetBrains' own tracker has an issue that the terminal "intercepts Cmd+K and clears output instead of opening VCS tool window": it takes the key from a global chord on purpose). Both agree, so the repository's rule (follow them where they agree) is followed over S52 ("⌘ chords on macOS always reach the command registry") and S66 (the palette's chord works "from anywhere, a text field included"). Mechanism: `Terminals.takeKeys()`, ONE window listener in the capture phase, added by a layout effect in `PluginHost` (a layout effect runs before every passive one, so it is the window's first listener, ahead of the palette's), which takes the key only when it comes to a terminal screen and clears that screen. The palette still opens with ⌘K from anywhere else, and is reachable with the keyboard from a terminal by F6 then ⌘K (the seam asserts both). Windows and Linux: no chord (VS Code has none there; Ctrl+K is the shell's kill-line); the toolbar's Clear stays everywhere. Reverting is deleting the effect line and `takeKeys`.
14. **Mac IDE keys, and select all.** VS Code's macOS defaults (`workbench.action.terminal.sendSequence`): Option Left/Right send `ESC b` and `ESC f` (move by a word), Command Left/Right send Ctrl+A and Ctrl+E (the ends of the line), Option Backspace sends Ctrl+W, Command Backspace Ctrl+U: without them the arrows move one character whatever the modifier (`sequenceOf`, `keys.ts`; the seam reads the bytes the shell received). ⌘A selects the output on a Mac (VS Code binds it there only, "as it may conflict with shell hotkeys"), Ctrl+Shift+A elsewhere (GNOME Terminal, Windows Terminal). **Option as Meta: chosen OFF** (`macOptionIsMeta: false`, VS Code's default: Option types characters, so a layout's `{`, `|` and `@` work); no setting yet (T6 in `T-terminal-bar.md`).
15. **Unicode 11 widths: one new dependency, `@xterm/addon-unicode11` 0.9.0** (root `package.json` and `pnpm-lock.yaml`, loaded inside the lazy emulator chunk, so the entry chunk is unchanged). VS Code offers Unicode 6 and 11 (`terminal.integrated.unicodeVersion`, "should match the Unicode version used by the shell/OS") and defaults to 11. Measured before the addon, in the fixture with the cursor-position report: four CJK characters put the cursor in column 9 (8 cells, right), an emoji took 1 cell and a ZWJ family of three emoji 3, so the seam's text (4 CJK, an emoji, a family: 16 cells to the shell) put it in column 13, and every prompt after an emoji sat 4 columns left of where the shell thought. With the addon the column is 17 in both engines, equal to what the shell counts plus one (section 14). A combining accent takes no cell in either.
16. **A visual bell, never a sound:** the screen fades once (240 ms, 16% of the text colour over the plane, none under `prefers-reduced-motion`; two animation names alternate so each bell restarts it with no timer). VS Code shows a mark on the tab's name (`enableBell`, `bellDuration`); that mark and a setting are T2 and T6.
17. **Two facts from the SDK review (the lead, 2026-11-22); this tool already complies and says so.** (1) *A session id is unique for the life of the app and never reused:* each New terminal makes a UUID (`crypto.randomUUID()` in `execFeed.ts`; the registry's session ids in `TerminalSessions.ts` the same; without `crypto` the fallback is the clock, a counter and a random suffix, never an earlier id), so a close signal that arrives late, after a newer session was admitted, cannot reach it. (2) *A start that fails, `CONNECTION_ERROR` included, is not retried or reopened:* the session is FAILED in the producer's words and the person starts a new one with New terminal; nothing in `ui-next/shell/panel/terminal/` wraps a start in a retry (every press opens a NEW process, decision 2).
18. **A switch for screen reader mode, for the lead to rule on (the review of #660, `xtermEngine.ts:44`; section 16).** The emulator's printed output is not in the accessibility tree unless its `screenReaderMode` is on, and the mode costs work, so it is a person's choice and **off by default**. **One palette command, `Terminal: Toggle Screen Reader Mode`** (context Panel, no chord, the tool's glyph; VS Code's is `Toggle Screen Reader Accessibility Mode`), turns it on and off at run time for every open terminal and every terminal made later (a hidden one is out of the mode while hidden and takes the choice when shown, so a hidden panel stays no work). **The choice is kept in the window's session document** (`ui-next/shell/session`: the field `terminalScreenReader` beside the rail's choice, a value the host sets and the session listens to; the document is version 2 and its one migration, from the first release's version 1, adds the field off): saved one burst after a change, restored before the window draws, and off for a window saved before it existed. The terminal's input is named `Terminal input, <title>` and described by words that say, while the mode is off, that the output is not read aloud until it is on and how to turn it on (leave the terminal with F6, open the palette with ⌘K or Ctrl+K, run the command: inside the terminal ⌘K clears the screen and Ctrl+K is the shell's), and while it is on, that it is on, that the output is read aloud and how to turn it off. The result is announced once ('Terminal screen reader mode on.' or 'off.') through the shell's polite live region, one task after the palette has closed, because the palette is a modal dialog while the command runs and the region is outside the accessibility tree until it is gone. The Settings row comes with the terminal settings slice (T6), which becomes the place the choice is kept.

## 4. Renderer decision

**GPU (WebGL) only while the terminal is on screen; the DOM renderer otherwise and as the fallback on context loss.** Data: `renderer-bench.mjs.txt` (agent `RendererBench`, partial: WebKit mostly, Chromium partly, one or two reps; raw JSON in the notes folder `T1-assets/renderer-bench.json`) and this slice's own flood probe in a production build. xterm 6.0.0, addon-webgl 0.19.0, addon-fit 0.11.0 (already root dependencies).
- Flood (82 MB): DOM drains in 0.97 s, WebGL in 0.69 s (WebKit, 1 rep); with per-frame slices rAF p95 about 17.5 ms in both. xterm DISCARDS past 50 MB queued, so a pending cap is required: `FLOW.high` = 4 MiB.
- 16 live WebGL contexts at most per page (the 17th evicts the oldest); after a loss the canvas stays blank until `dispose()`, which restores the DOM renderer pixel-identically: the adapter does that. Load 3.5–9 ms, dispose 1.5–5 ms.
- A DOM-rendered terminal in `display:none` that receives a flood made 29,524 mutations (against about 1,500 visible): never write to a hidden terminal. The screen holds output in the feed while hidden (probed: 0 writes, 0 mutations).
- The GPU rounds the cell to 7 px (DOM 7.2): the host is measured again once the addon is in place. **Done and probed:** the page sends 187 columns, then 193 (`window.__pty.log.resizes`).
- `cursorBlink` is false (WebGL with focus and blink made 18 rAF in 5 s: idle must be 0).
- The row pitch is the mock's 18 px: the emulator's cell is the font's own height times `lineHeight`, rounded down, so the adapter finds the multiple that makes the row the pitch the theme asks for by looking at the row it made (`geometry.rows`: 18 px at 12 px, in both engines).
- Colours: tokens are read from swatches (`getComputedStyle`); `oklch()`, `color()` and `color-mix()` come back in their own syntax in both engines and are drawn on a 1x1 pixel (`normaliseColour`, unit tested; no token of the nine themes needs it today).
- **Not confirmed:** Playwright's WebKit is not the desktop's WKWebView; nothing was run in the native window.

## 6. Keyboard, focus, words (what the probe and the seam read)

The new terminal takes the keyboard when its process is up and the focus is nowhere in particular or in the panel (S116a); a restored or adopted terminal never does. Escape and Tab go to the shell (`keys.escape`, `keys.tab`); F6 leaves and is not sent (`keys.f6`, `keys.f6-not-sent`); Ctrl+C with no selection is the interrupt (`keys.interrupt`); the copy chord copies the selection (`keys.copy`) and is not sent to the shell; a paste event reaches the shell (`keys.paste`); on a Mac ⌘J hides the panel and the focus leaves the terminal (`keys.toggle`). The question: a modal (`close.modal`), Cancel focused (`close.cancel`), Escape and a press outside say no (`close.no`), Terminate session ends the process, the tool says "No terminals" and the focus is on the tool's tab (`close.yes`). Words: the empty tool, the toolbar and its names (Copy is `aria-disabled` with its reason when nothing is selected), the input named "Terminal input, Terminal" and described by "Escape and Tab go to the shell. Press F6 to move to the next part of the window, or ⌘J to hide the panel." (⌘J only on a Mac: elsewhere the toggle is shell-owned, section 11), the lane empty while running, "Ended" + "Input is off. Its output stays readable here." for an ended session with `[Process ended]` as the last line of the transcript (the host does not say the code, catalog item 3; "Exited with code N" and `[Process exited with code N]` the day it does), "Failed" + the producer's words, and nothing typed after the end reaches the process (`words.*`).

## 7. Backend facts, measured on the real host (agent `HostFacts`, all 12 questions; loads 11–35, each run records its own)

Data: `T1/host-facts.mjs.txt` (the script: builds `OMNIVIEW_UI=next task build:server`, clean env, own port, kills only its own children) and `T1-assets/host-facts.json`.
- **Create** answers `{created_at, labels, params, id, command: [], attached}`: no shell named. The login shell is the account's (`/bin/zsh -i -l`, `TERM=xterm-256color`, cwd = HOME). An explicit `/bin/bash` works; a program that is not a shell is refused (422). Create p50 18–28 ms, prompt ready about 40 ms later. A client-chosen id works: 30 sessions, 0 events lost before the caller had the id.
- **Initial pty size is 72 columns by 27 rows** and `SessionOptions` has no size (an unknown member is rejected 422). The first prompt is already laid out for 72 columns before any resize can arrive (zsh's first event is `%` plus 71 spaces and `\r \r`): visible with a right-hand or full-width prompt, so a **BLOCKER for the Go step**. The synthetic shell of the fixture starts at 72x27 as well.
- **Events:** only `core/exec/stream/stdout/<id>` (a pty has one stream); `{name, data}` with `data` a base64 string; a pty read returns at most 1,024 bytes: `yes | head -200000` (400 KB) is about 77,000 events averaging 8 bytes. Byte-exact (sha256); one of 17 repeats had one extra `\r`.
- **Exit:** the output, then ONE `signal/CLOSE` with the fixed text "Session terminated", on every path (`exit`, Ctrl+D, `kill -9`).
