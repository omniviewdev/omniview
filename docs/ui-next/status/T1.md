## 1. What this slice is

One end-to-end way to start a terminal: the host's LOCAL shell (`ExecClient.CreateTerminal`). A Terminal tool in the panel with session tabs that share the panel's session model (identity, twins, state words, cards), input, output, resize, exit as an ended session that is kept (scrollback readable, input off, said in words), Close with a running-process question, copy and paste chords, Clear, focus rules (A14), axe clean, performance by data, probes against the mock, seam scenario `r`. Pod exec from a plugin, reattach, split terminals, search, links, profiles and the rest are later slices (section 9).

## 4. Decisions for the lead

1. **Local shell, not a plugin target.** `ExecClient.CreateTerminal` exists and works (measured, section 6). Pod exec is a later slice.
2. **No A22 re-activation for terminals.** Two shells on one target are two processes; the mock's `openTerminal` always creates. Logs' rule (one stream per item) does not apply.
3. **Close of a RUNNING terminal asks: "Terminate session?"; body "This ends the terminal session. Programs it left running in the background may keep running."; buttons Cancel and "Terminate session".** The body does not promise that every program stops: measured, `CloseSession` kills the shell and the foreground program but a background job and a program that ignores SIGHUP survive (section 6, Q9; the Go fix is catalog item 7). The written rule (S115, L12) asks only when a foreground process runs; the host has no such fact (BLOCKER for the question's precision, section 7), so it asks for every running terminal, and `closeQuestionOf` stops asking for a session whose producer says `foreground: false`. A producer that names the program gets it named. **Correction to the brief:** VS Code does NOT confirm by default for panel terminals: `terminal.integrated.confirmOnKill` defaults to `editor` (enum never, editor, panel, always), so only terminals in the editor area confirm, and the docs say the terminal shows no warning when a process exits. JetBrains does confirm: "To terminate a running session, close the tab ... and confirm the process termination". So where they disagree the written rule decides, and it asks.
4. **Escape never leaves the terminal; F6 and the panel toggle (⌘J) do.** VS Code sends Escape to the shell; JetBrains' default moves focus to the editor with Escape. They disagree, the lead ruled Escape stays. xterm's custom key handler returns false for F6 and app chords so the document's listeners get them.
5. **Copy and paste.** Mac: ⌘C copy, ⌘V paste, Ctrl+C is the interrupt. Other: Ctrl+C copies only with a selection and otherwise interrupts, Ctrl+Shift+C and Ctrl+Shift+V always. VS Code (Windows) and JetBrains agree; on Linux VS Code uses Ctrl+Shift+C/V only and JetBrains' Ctrl+C-with-selection copies, so "other" follows Windows. `macOptionIsMeta` false (both products' default).
6. **Toolbar this slice: Clear and Copy selection only.** Paste is the chord (a button would need the clipboard-read permission, which WebKit does not give silently); Find, Rename, the targets menu are later.
7. **Scrollback 5,000 lines** (the library's terminal keeps 5,000, LIB-21; the old host took the emulator's 1,000; the mock keeps 2,000). Held output while hidden: 4 MiB per terminal, drop oldest, counted and said ("[N KB of output were skipped]"). Both are constants (`SCROLLBACK`, `HELD_BYTES`) and the memory data (section 8) decides them.
8. **The emulator's stylesheet is injected at runtime from the lazy chunk** (`@xterm/xterm/css/xterm.css?inline`, wrapped in `@layer ov.components`), not imported as a `.css` file: the ui-flavour test requires exactly one stylesheet with every rule in a layer, and this way the entry stylesheet gains 0 bytes and the host's overrides (`ov.shell`) win by layer. The host's own rules for the screen are in the CSS module.
9. **Tool order 10 changes existing tests.** Terminal becomes the first tool and the default, so tool-name lists gain "Terminal" at the front in `PluginHost.failedLoad.test.tsx` (~392-404), `PluginHost.order.test.tsx` (~245, 316, 326), `PluginHost.panel.test.tsx` (~89), `PluginHost.unload.test.tsx` (~310-319, 467) and in the seam (`ui-next/plugins/e2e/seam.check.mjs` ~679 and ~762). Not edited yet (the tool is not registered).
10. **Seam scenario letter: `r`** (Main ruled Terminal r, Settings s, Plugins t; p and q are taken). Not written.

## 5. Renderer: recommendation from PARTIAL data (agent `RendererBench`; WebKit mostly, Chromium partly; Playwright's WebKit is not the desktop's WKWebView, nothing was run in the native window)

Data: `docs/ui-next/status/T1/renderer-bench.mjs.txt` and `renderer-bench-page.txt` (the driver's header says how to run it), raw JSON `T1-assets/renderer-bench.json` (a `STATUS` field says what is partial), shots in `T1-assets/renderer-bench-shots/`. Run under load 12–29. Directional, not final: most items ran once or twice (B3 WebKit only, 1 rep; B4 after-dispose invalid; B6, B7, B8 WebKit only, B8 with 12 samples not 200; plain chromium B2–B8 and B10 not run).
- **Sizes (raw / min / gzip):** xterm chunk 411,682 / 329,294 / 82,698; WebGL addon 139,518 / 110,225 / 29,831; fit 1,420 / 1,214 / 505; `xterm.css` 7,112 / 3,596 / 993. The entry chunk pays 1,274 B once for vite's preload helper on the app's first dynamic `import()` (239 B for three more), so "0 bytes in the entry" means no xterm module, not no helper.
- **Cells:** `lineHeight` 1.0 gives a 16 px cell; DOM fits 186 columns at 1360 px (7.2 px cell); WebGL rounds the cell to 7 px, so a refit after the addon loads gives 192. **Fit again after the addon loads: NOT in the code yet** (`Engine.setRenderer` should resolve when the renderer is in place and `screen.ts` should measure then).
- **Flood:** W2 (82 MB) drains in 0.97 s DOM against 0.69 s WebGL (WebKit, 1 rep), rAF p95 about 17.5 ms and max about 19 ms in both with per-frame slices; concatenating a frame's chunks is worse (p95 40.9 ms, max 56 ms). xterm DISCARDS at 50 MB queued (`write()` throws; 1,562 of 4,004 chunks dropped when all of W2 was queued at once), so a pending cap is required: the code caps at `FLOW.high` 4 MiB (the bench suggests about 2 MB; both are far under 50 MB; the flood probe tunes it).
- **Memory:** about 2.6 KB per scrollback line at 186 columns; Chromium about 4 / 6.4 / 13.7 / 26 MB at 1,000 / 2,000 / 5,000 / 10,000 lines. WebKit RSS is GC-lazy (about 800 MB whatever the scrollback). 5,000 lines is about 14 MB: the cap stays 5,000.
- **WebGL contexts:** the 17th live context evicts the oldest in both engines (limit 16; the console warns); after a loss the canvas stays blank, with no automatic fallback; `addon.dispose()` restores the DOM renderer pixel-identically. Load costs 3.5–9 ms, dispose 1.5–5 ms. So at most 16 live, and GPU only while shown (as coded).
- **Hidden:** opening in `display:none` is fine for an explicitly sized host; a DOM-rendered terminal in `display:none` that receives a 20 MB flood made 29,524 mutations against about 1,500 visible. **Never write to a hidden DOM terminal**: the code holds output in the feed while hidden, which is exactly this. Opening before the font loaded gave a 14 px cell and 16 rows and `fit()` alone did not repair it: the screen waits for `document.fonts.load` before it makes the emulator (coded).
- **Idle:** 0 timers, 0 frames and 0 mutations in WebKit except WebGL with focus and `cursorBlink` (18 rAF in 5 s): `cursorBlink: false` (coded). Chromium idle not run.
- **Keys:** F6 with no handler is swallowed and sends `ESC[17~`; with the handler returning false it bubbles and is not prevented (coded). Escape, Tab and Ctrl+C go to the shell with `stopPropagation`. A capture-phase document listener runs before xterm (Ctrl+J sends LF; Meta+J sends nothing); if it stops propagation xterm never sees the key. Meta+C fires `copy` and xterm copies itself; a multi-line paste becomes `line1\rline2\rline3`, bracketed when the shell asked.
- **Colours:** `getComputedStyle` gives `rgb()`/`rgba()` for hex, rgb, hsl and names, but `oklch()`, `color()` and `color-mix()` come back in their own syntax and need a 1x1 canvas to normalise (NOT in `appearance.ts` yet: check whether any token of the nine themes is authored that way). xterm accepted computed values: 0 differing pixels against hex in both renderers.
- **Recommendation, and what the code does:** WebGL on both engines while visible and dropped on hide, DOM as the fallback on context loss, at most 16 contexts, a pending cap, scrollback 5,000, `cursorBlink` false, fit after the font and after the addon. xterm 6.0.0, addon-webgl 0.19.0, addon-fit 0.11.0 (already root dependencies).

## 6. Backend facts, measured on the real host (clean `OMNIVIEW_UI=next task build:server` host, agent `HostFacts`; all 12 questions measured, loads 11–35, each section records its own)

Data: `docs/ui-next/status/T1/host-facts.mjs.txt` (the script) and `/Users/joshuapare/Notes/omniview/ui-migration/status/T1-assets/host-facts.json` (all runs, checks, load).
- **Create answer** names no shell: `{created_at, labels:{}, params:{}, id, command:[], attached:false}`. The login shell is the account's (`/bin/zsh`, `TERM=xterm-256color`). Explicit `/bin/bash` works; a program that is not a shell is refused (422 "unsupported terminal shell"); a missing one 422 "shell executable unavailable".
- **Client-chosen id works:** 30 sessions, 0 events lost before the caller had the id (listeners registered before create).
- **Initial pty size is 72 columns by 27 rows** (`stty size` before any resize: `27 72`), and `SessionOptions` has no size member (an unknown member is rejected 422 "Unknown exec option member"). The shell's first prompt is already laid out for 72 columns before any resize can arrive: zsh's first event is `%` plus 71 spaces and `\r \r`. This is visible (a right-hand prompt or a full-width prompt on the first line is wrong until the next prompt), so it is a **BLOCKER for the Go step**, not TANGENTIAL.
- **Timings:** create call p50 27.7 ms, p95 136 ms; prompt ready p50 42.4 ms after create returns (n=20, load ~18).
- **Events:** only `core/exec/stream/stdout/<id>` (a pty has one stream: no stderr event for a local shell); frame `{name, data}`, `data` a base64 string in both engines; `Uint8Array.fromBase64` exists in the page.
- **Flood:** `yes | head -200000` (400,000 bytes) arrives byte-exact (sha256) but as about 77,000 events averaging 8 bytes (a pty read returns at most 1,024 of the 20,480-byte buffer); the 20 MB flood is about 25,000 events at 12–20 MB/s. One of 17 `yes` repeats had one extra `\r`. The host emits one event per pty read, uncoalesced; the page pays per event.
- **Exit:** `exit 3` gives the output, then ONE `signal/CLOSE` whose payload is the fixed text "Session terminated" (18 bytes) on every path. No exit code and no signal anywhere in the events; the code is only in the host's log (`error waiting for command ... exit status 3`). Exactly one CLOSE per ended session; none before `CloseSession`, one after.
- **Q4 output lost at exit:** 0 of 100 lost for the tail-only variant and 0 of 100 for a 200 KB variant; four harder variants lost 0. The race is in the code (`manager.go:209-214`, `:407`: the pty is closed after `cmd.Wait`) but never fired here. After `exit`, Ctrl+D or `kill -9` there is one CLOSE, after the last stdout; a call on an ended session returns 422 with an inner type `omniview:session/not-found` (status 404); `ListSessions` returns `[]`.
- **Q5 resize:** `stty size` gives `33 117` and `COLUMNS=117 LINES=33` after `ResizeSession(rows 33, cols 117)`: rows before columns is right. The shell sees it about 4 ms after the call returns; a resize emits no event of its own (the shell redraws its prompt); `0x0` is accepted. **50 UNAWAITED resizes end at the wrong size** in 3 of 20 runs from Node, 10 of 20 in Chromium and 2 of 20 in WebKit: the UI must serialise (`execFeed` keeps one in flight, newest wins).
- **Q6 attach:** `AttachSession` returns `[session, base64]`; after 3 MB the buffer is exactly the last 1,000,000 bytes and a second attach returns the same bytes. `DetachSession` does not stop events for a local session. An attach during a flood has no sequence number to join buffer and live events: they differed by about 370 lines (reattach is a later slice).
- **Q7 input:** a multibyte echo through `cat` is intact; a 100 KB write arrived in about 17 ms; **100 UNAWAITED writes were reordered** (4 inversions from Node, 5 in Chromium, 22 in WebKit), awaited writes stay in order (`execFeed` awaits). One-byte round trip p50: Node 0.69 ms, Chromium 0.9 ms, WebKit 2 ms (1 ms timer grain). 461 of 52,950 events ended inside a UTF-8 character: decode with a streaming decoder or write bytes (the engine takes bytes).
- **Q8 release (B-88):** closing or reloading a page does NOT release its session: it stays listed, the shell stays alive, a second page keeps receiving its events, still there after 60 s in both engines.
- **Q9 close:** `CloseSession` kills the shell and a foreground `sleep` within 1.7 ms, no zombie, and no event after the call returns during a flood. **A background `sleep 301 &` survives (reparented to launchd) and so does a foreground program that ignores SIGHUP**: the close question must not promise that every program stops.
- **Q10 foreground:** no backend call reports it. `ioctl TIOCGPGRP` on the pty master works on darwin (throwaway Go probe): it returns the foreground process group, which differs from the shell's pid while `sleep` runs.
- **Q11 page floor (50 MB flood, a counting handler):** Chromium 15k events/s and 11.6 MB/s, WebKit 23k events/s and 17.8 MB/s; rAF p50 and p95 stay at one frame, max 17–104 ms; per-event handler cost 0.1–3 microseconds, `atob` the largest (2.5–3 microseconds mean, 5.5% of main-thread time on the 50 MB flood). **Host RSS** grows from 68 MB to 0.75 GB over 2 x 50 MB floods even with a fast or no client, to about 4 GB with a stalled socket (Wails' unbounded per-client queue), and a page blocked for 5 s peaked at 1.4 GB. Not measured: a hidden tab (headless pages stay visible), the desktop's native event delivery (only the server-mode socket), and the attribution of the RSS growth between the 20 KB per-event read buffer and the SDK buffer.
- **Q12:** every event goes to every socket, byte-identical; the same id twice gives two shells and only the second is reachable; the shell's cwd is the host's HOME, `TERM=xterm-256color`, it runs as `/bin/zsh -i -l`; **the host's whole environment leaks into the shell** (`OMNIVIEW_*`, `GOWORK`; `LOGNAME=root` appeared and was not traced).

## 7. Backend catalog (the brief for the Go step, "T1-go"; nothing here is worked around in the UI)

The session model takes each as an OPTIONAL fact (`exit`, `foreground`, `program` in `TerminalFeedSnapshot`): when the host starts saying it, the transport sets it and nothing else changes.

1. **BLOCKER: no foreground-process fact.** Add `Manager.ForegroundPID` in `backend/pkg/terminal/manager.go` (`ioctl TIOCGPGRP` on the pty master compared with the shell's process group, measured working on darwin) and a method in `backend/pkg/plugin/exec/service_wrapper.go`; the UI then sets `foreground: false | {name}` and `closeQuestionOf` asks only when something runs (decision 3).
2. **BLOCKER: initial size and shell name.** `manager.go:29-30` (`InitialRows = 27`, `InitialCols = 72`) and `:150` (`pty.StartWithSize`) start the shell at 72x27 and `SessionOptions` has no size (sdk `exec/session.go:131-142`; `Session` at `:20-27` names no shell; `manager.go:165` returns `Command: opts.Command`, empty for the default). Add rows, cols and the resolved shell to the create options and answer; the UI then sends its measured size with create. Evidence: section 6 (the first prompt is laid out for 72 columns).
3. **BLOCKER: no exit code or signal.** `manager.go:249` emits CLOSE with the fixed text "Session terminated"; the status is known at `:210` (`cmd.Wait`) and only logged (at ERROR for a normal non-zero exit: downgrade, `:211`). Carry `{exit_code, signal}` on CLOSE (`plugin/exec/controller.go:189`, `dispatchOutput`) so the tab says "Exited with code N" and the transcript `[Process exited with code N]` (S116).
4. **BLOCKER: input and resize are unordered across unawaited calls** (`service_wrapper.go:101-109`; section 6, Q5 and Q7). The UI serialises, so the product is safe today; add a per-session sequence number, or document that callers must await.
5. **BLOCKER: no per-window release (B-88).** `controller.go`: a closed or reloaded page leaves its sessions alive and listed, so every reload leaks a shell, and the UI cannot safely sweep (no owner label). Add an owner (window id) on create and a window-close hook that closes or detaches its sessions.
6. **TANGENTIAL: events and buffers.** Each event pins the whole 20 KB read buffer (`manager.go:261`, `:286`): copy `buf[:read]` and coalesce reads for a few ms; the SDK buffer reallocates 1 MB on every append once full (`pkg/v1/exec/buffer.go:59-64`: use a ring); one forwarding goroutine and an unbuffered channel serve all local sessions (`controller.go:163-186`).
7. **TANGENTIAL: close leaves children.** Background jobs and SIGHUP-ignoring programs survive `CloseSession` (`manager.go:128`, `:407`): signal the whole process group.
8. **TANGENTIAL: a repeated session id** overwrites the first silently and orphans its shell (`manager.go:173`): reject the duplicate. `ResizeSession` accepts 0 rows or columns.
9. **WIRE: no backpressure; unbounded queues.** Events go to every window; Wails keeps an unbounded per-client queue (`websocket_server.go:114`, `internal/mailbox/mailbox.go`; not repo code: needs a cap or drop policy upstream), which is the stalled-client RSS growth (about 4 GB); `DetachSession` does not stop local emission (HGO-35). Add a pause or credit message the UI can send when its held queue is full.
10. **WIRE: attach has no byte offset** to join the replay buffer and live events (about 370 lines differed); return the buffer's end offset and number events (needed by the reattach slice).
11. **TANGENTIAL: environment and tab name.** The host's whole environment leaks into the shell (`OMNIVIEW_*`, `GOWORK`, `LOGNAME=root`); `Session.Command` and `Labels` are empty so the tab is the generic "Terminal" (twins get "(2)" from the strip).
12. **Panel-model gaps (shell-owned, not Go):** no retitle API for a session, no close-label hook (the tab's close button should be named "Terminate session" while a process runs, V17), `RefusedReason` has no "asked", and `PanelBindings` has no close-guard member (the guard wraps the store instead: `closeGuard.ts`).
