## 4. Decisions and deviations for the lead

1. **In-window modal sheet** (see section 1): reversible; the old window's size, the pages left and the page right.
2. **No Save, no Apply, no unsaved-changes question**: the written rule is apply-on-change (S125, quoted in FM1); the sheet closes by Escape or its Close at any moment and loses nothing. A scrim press does not close (04: a form's backdrop does not discard a draft on an accidental click).
3. **Not drawn in this slice** (each recorded in the adapter with its reason): `appearance.theme` and `terminal.nativeApplication` (their editors are pickers the old window registers, `ui/pages/settings/CoreSettingsPage.tsx`), a setting marked developer-only, the types multiselect, colour and date-time, a secret whose presence the host does not state. No sections (the host declares none), no status slot in the page heading, no page menu, no Copy key, no search, no Plugins group, no Notifications, AI Tools or Updates pages (the old window has the last two as custom pages). **Search** is not drawn because it is not built; it can be real over the model (labels, descriptions, ids).
4. **Nav without glyphs.** The host names glyphs as `LuSettings2`, `LuPaintbrush`, `LuSquareTerminal`, `LuCode`, `LuBeaker`, `LuActivity`; the kit has two of six, and a nav that draws two would look unfinished. Glyphs the icons step needs: `paintbrush`, `square-terminal`, `code`, `beaker` (the host's page glyphs, Lucide), `settings` (the mock's gear for the top row, `LuSettings`; `settings-2` is used now), `rotate-ccw` (the mock's reset, `LuRotateCcw`; the kit's `undo` is used now).
5. **Appearance, Editor, Terminal and General persist real values the new shell does not read yet** (its `ThemeProvider` takes props; the old shell reads them). They are the host's own settings and apply in the product that shells them; binding the new shell's theme, density and text size to them is the Appearance step.
6. **Palette over the sheet**: while the sheet is open the window's tab, panel and palette chords are taken from the page behind it (the sheet is a modal); the sheet's own Command K (focus its search) comes with the search.

## 5. Backend catalog (for `docs/ui-next/backend-catalog.md`)

- **TANGENTIAL** `backend/pkg/settings/service.go`, SDK `settings.Category`: no order and no sections (a Go map): the pages are in the design's table, rows alphabetical by id. A producer-side order or section member would let the sheet group as the mock does.
- **TANGENTIAL** SDK `settings.Setting`: no editor or display hint: `appearance.theme` and `terminal.nativeApplication` are `text` in the schema and pickers in the old shell; the sheet cannot tell them from free text, so two ids are listed in `adapter.ts` `NOT_DRAWN`.
- **TANGENTIAL** the snapshot does not say the settings store is unavailable (S128 "Settings can't be saved"); a failed save is said on its row, and `Commit` answers one fixed sentence for every refusal (`service.go:39-49`), so the host's own words reach the person only through `Validate`.
- **BLOCKER for the native app** `main.go:893-895`, `backend/menus/app_v3.go:78,88`: the native menu item Settings… with the accelerator Command comma opens the legacy `settings`-kind window (`OpenSettings`), which the new UI cannot draw, and AppKit takes the key equivalent before the webview sees it. The menu must emit an event the new shell listens for (or the Go side must not register the window for the new UI). Not run natively.
- `Service.Commit` rejects a nil value, so a secret is cleared by committing an empty text (St1Go).
