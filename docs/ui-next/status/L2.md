## (3) Order

Arrival order, never sorted: README of the part, the doc of `LogFeedBatch.lines`, a model test (a line with an earlier clock stays after the one before it) and the rule in `optimisations.md` HLT-13 (the old viewer's jump to a time assumed arrival order: "approximate by design"). **The fact**: the first real stream (P1b-3b, a Pod with two containers) had 110 of 2,225 rows with a clock earlier than the row above, because each container's lines are in its own clock order and the SDK merges them as they arrive. **The reference (A19)**: `kubectl logs --all-containers --timestamps` does not merge by clock either. In kubectl's own source (`k8s.io/kubectl@v0.35.0/pkg/cmd/logs/logs.go`, read from the module cache; the installed client is v1.33.0 and was not run against a cluster for this): `RunLogsContext` (`:373-398`) follows several requests with `parallelConsumeRequest` (`:400-429`, a goroutine per container writing whole lines into one pipe: arrival order) and otherwise reads them with `sequentialConsumeRequest` (`:431-444`, one container after the other, over a Go map, so the container order is not even specified); `--timestamps` (`:196`) only asks the API for the RFC 3339 prefix; nothing sorts. The source is NOT shown unless asked: `--prefix` (`:209`, `[pod/<pod>/<container>] ` from `addPrefixIfNeeded`, `:446-466`) and it is on by default only with a selector (`:271-273`). So the plugin shows what the API reports in arrival order (A19), and the mock's presentation (the Source column) is what the kit adds; no sort is built and the README says so.

## Decisions made here (for the lead to keep or reverse)

1. **Copy carries the source only while the column shows** (`clock LEVEL label  text`, the mock's `lineText` format with the level padded to five); with one source the copy is what it always was. The mock copies the label whenever a line has one, so for a one-source log it differs: following the mock to the letter is one condition in `LogViewModel.copyText` (and the one-source tests and the log probe's `copyLine` would change). Search does not match the source, as the mock's does not.
2. **The column shows when the view has heard of more than one source, from lines OR the feed's listing.** The mock's rule is the session's source list (`candidates(s).length > 1`); the assignment's is a second source that speaks. The union follows both; a listed source that never speaks still shows the column (as the mock's would), so the column more often exists before the first line than appears in the middle of a stream.
3. **A source is named by the label the feed's latest listing gives it, else its id.** For the real stream that is `pod/container` cut from its start (the container stays). A friendlier name needs the plugin to give one: Findings.
4. **No horizontal compensation.** A reader scrolled sideways in a long line sees the text move right by 168 px when the column appears (rare; vertical position, window and scroll commands are untouched, tested).
5. The kit and the host carry none of the Kubernetes words the vocabulary guard forbids: the ids in tests are `svc/app`, `orders-api/app`.
6. **The chip is the kit's own parts, no new one**: a `span` with the mock's `.chip` rules, the swatch a `::before`, the name a `MiddleEllipsis`. A static `Chip` part would have added a second element tree per row; the cost above is already the dearest part of a row.
