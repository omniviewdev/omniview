## Findings for the lead

1. **Row layout.** The rAF p95 cannot discriminate on this machine: S, A, R and the control all sit on the engine's frame cadence (Chromium 16.7 ms, WebKit 18.2 ms), because a table doing 2 ms of work in a 16.7 ms frame always meets it. The rule's tie-break (median frame work) also ties, so S wins by the rule's text. By Chromium's layout time S is 62.7% above A (27.0 against 16.6 ms in 5 s) and by the mean frame work A is 11.8% lower; neither reaches a frame. The 4x CPU cell is the one that can show a difference (report only). If the lead wants a decision on more than a tie, the rule needs a measure that is not capped by the display: frame work at 4x, or CPU time per scrolled row.
2. **B2a and trigger T1** are read in the baseline file; no cell that ran missed B2a, B2b or exceeded R. WebKit's idle page itself has p95 18.2 ms, so WebKit's B2a is the relative reading.
3. **Table defect found by the counts and fixed**: two commits for every window change in both engines, from a same-value `setScrolled` in the scroll handler (red test `042d5fde`, fix `54ba08bf`). Cost was a no-op render per window change (0 ms duration); the matrix ran on the page before the fix, S and A both carry it, R does not.
4. **B5 accuracy** (above): the sample under-measures rare long strings. The plan did not change because the planner held the readable floors at 1,117 and 707 px; with fewer columns it would.
5. **The shared row menu** (`createRowMenu`, `RowMenu`, `RowMenuTrigger`): one popup root however many rows (0 closed, 1 open), a trigger of 3 elements, equal listener counts at 0, 1, 60 and 5,025 triggers, 0 rows rendered by opening or closing, a popover in the top layer so that a transformed or clipped region does not cut it; owned, no Base UI. **Open: in WebKit, Tab inside the open menu leaves it open and the steps after it fail (5 failures of the probe; Chromium none).** Also: disabled items are skipped by the arrows (the mock keeps them in the order), no popup shadow token exists on main (the mock has `0 8px 24px #00000040`), the viewport margin is 4 px (the mock 8), type-ahead is not built, only 1440 x 900 was probed. A new `ellipsis` glyph was added to the Icon registry for the trigger (`67c6d7fa`; drop it and give the trigger its own glyph if the lead objects).
6. **The table parity probe** (`packages/kit/probes/table-probe.mjs`, fixtures `DataTable.parity.examples.tsx`): 36,956 measurements, 2,104 unexplained differences in 115 kinds, equal in both engines. Kit defects it found in `DataTable.module.css` and `TableFit`, mock value first: a command cell grows its row (24 px to 32 px; the mock's `td:has(> button)` takes the cell padding to 0) and the cell padding of command and 40 px cells differs; `.head, .cell` clip with `overflow: hidden` where the mock clips only flexible cells and never a header, which also cuts the sort button's focus ring to two bars; the sort arrow colour (mock `--ov-icon`, kit the muted foreground) in all nine themes; the sort button radius (4 px against 0); the checkbox mark (radius 4 against 2, unchecked edge `--ov-border-raised` against `--ov-border-control`, unchecked fill `--ov-bg-island` against transparent); in `cell-text` the Name column is 407 px (the 7 px a character estimate) against 328.75 in the mock, probably because the grow-only merge keeps the pre-layout estimate. **None fixed in this PR**; the probe is run by hand (it is not in CI). The middle-ellipsis halves are not compared (the atom is PR #516).
7. The selection column's header has `aria-label="Selection"` and no text: axe reports `empty-table-header` (minor). A visually hidden word would silence it.
8. The mock probes use Helvetica (the font step is #519); real Inter widths need a rerun.
