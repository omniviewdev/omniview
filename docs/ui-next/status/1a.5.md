### The registration (seed of the contribution contract)

```ts
type ShellRegistration = {
  plugin: { name: string };                       // names the landmarks: "<name> workspace", "<name> scope"
  tab: { title: string; icon: IconName };         // the page as the tab shows it (title: at most 3 words, ch16 S10)
  path: readonly string[];                        // status bar crumbs, root first; the last is the page
  rail?: true;                                    // a 40 px track for the plugin's tools; the tools are not in the contract yet
  sidebar?: { label: string; title: string; nodes: ShellTreeNode[]; open?: string[]; current?: string; accent?: ShellAccent };
  scope?: readonly { label: string; icon: IconName; text: string }[];   // the lane's faces, at most 2, text at most 24 characters
};
type ShellTreeNode = { id: string; label: string; icon: IconName; count?: number; children?: ShellTreeNode[] };   // children: a group
```

Plain data, passed as a prop, read-only for the shell. Plugin scaffolding imports nothing from the shell: the shell's type checks the object at the mount point. Values the page learns from its data reach the shell through the same object, built by the page's data owner (PR 1a.7).

## Decisions (each is in `ui-next/shell/README.md`, "Decisions to confirm"; the lead's call)

1. The rail's 40 px track is reserved and empty (`rail: true`): the plan's 1.1 lists the rail and every page rectangle after it assumes the track, while 1.2 cuts the rail's tools. Without it the island moves 40 px left.
2. The top row keeps its leading 156 px (safe area 84, Back and Forward 64, gap 8) so the tab sits at 156.
3. Scope faces are text with no chevron (a chevron promises a menu): 16 px narrower than the mock's, nothing else differs.
4. Choosing a tree entry does nothing; groups open and close. 5. The page's scroll owner is the `document` layout only; the `pane` layout comes with the first page that owns its scroll (`DataView`). 6. The page region is a tab stop (axe `scrollable-region-focusable`; the tabs pattern). 7. No focus ring on the island, as in the mock. 8. Tree rows are named by their text, not by an `aria-label` (axe `label-content-name-mismatch`). 9. Drag regions use `--wails-draggable` behind a local stylelint exception. 10. The sidebar is 244 px, fixed.

## Findings for the lead and the errata pass (N10)

- Plan 1.1 lists the rail and the exit test says "every region", while 1.2 cuts the rail's tools: decision 1 above. Likewise the one tab's row: the tab rectangle needs the leading 156 px.
- The mock's tree row has `aria-label="Pods, 89"` (fails axe `label-content-name-mismatch`) and its `#mainscroll` has `tabindex="-1"` (fails `scrollable-region-focusable` for a page of text); the shell differs from the mock on both on purpose (decisions 6 and 8).
- The mock draws no focus ring on the island (decision 7): F6 and Escape land there with no visible ring.
- `Text` needs a `truncate` prop (every clipped label, crumb and title here sits in a wrapper); a `VisuallyHidden` part would replace `.what` in the scope lane; the local parts and the kit parts they should become are listed in the README.
- The kit's stylelint closes custom properties to `--_name`; `--wails-draggable` (the Wails runtime reads it for the window's drag regions, S5) needs an exception: done as a local `stylelint-disable` on three lines; a config override is the lead's choice. The native drag is not verified.
- The mock's tab ring sits on an inner button 1 px inside the face; here the face is the button, so the ring offset is 3 px, not 2.
- Optimisation register items tagged for the shell frame and not taken here, none foreclosed: HSH-16 (the `GetState` boot chain), HSH-15 (the startup report), HSH-17 and HSH-17b (first-paint theme script and boot splash: nothing writes a theme key yet), HSH-8 and HSH-19 (kit in `dedupe` and in the dev `exclude` lists: `vite.config.ts` is not this PR's), HGO-43 (the heartbeat: the skeleton's `ActivityProvider` carries it), HSH-33/34/39/44 (listeners and polls: the frame has none: it sets no timer and no interval, and it adds one `keydown` listener on the document).
