### The dots

`ui-next/shell/TopRow.tsx` draws the three stand-in dots only when `isNativeWindow()` (`ui-next/shell/core/native.ts`) is false. **How native is detected**: the desktop app's web view carries the message handler the Wails runtime talks to the app through, `window.webkit.messageHandlers.external` (WKWebView, WebKitGTK) or `window.chrome.webview` (WebView2), and a browser (server mode, a Vite tab) has neither; the runtime picks its own transport by the same two properties (`@wailsio/runtime` `system.js`). The handler exists when the first script runs, so the frame needs no second paint. The 84 px safe area stays in both. Tests: 7 for the detection (browser with a `chrome` or `webkit` object of its own is false; both bridges true; a refusing read false) and 3 in `Shell.test.tsx`, red against the old `TopRow.tsx` (3 failures) and green with the change. The shell probe, which runs in browsers, still sees the dots (`dot1`, `dot3` targets) and passes.
