## Decisions

- **A new frame inside version 2, opt-in.** `0x8b marks`, sent only to a page whose attach says `"marks":1`. A v2 page that does not know the frame never asks, so it is never sent one (the page treats an unknown host frame as a broken stream, so an unasked frame WOULD break it); that is why `v` stays 2. The `ready` of a stream that carries marks says `"marks":1`. The attach reads the extra member as nothing on a host that is older. A page that asks for another number is sent none.
- **Marks are scanned where the output is appended.** The scanner of package marks (step 1) is fed by `replayRing.write`, in the step under the session's output lock that numbers the bytes, so a mark's `at` and `end` are the offsets of the output frames, and the marks are part of the ring: frozen with it for a terminal that ended, replayed with it. Only a session with a nonce (the shell integration is `on` or `unconfirmed`) has a scanner: with no integration nothing is read, whatever a program prints.
- **Delivery by offset.** The sender cuts output frames where the next unsent mark's sequence ends and sends the marks that end at or before its cursor after the bytes; so the page stands exactly at `end` when it takes the frame (a marker created in the handler is created at the offset: xterm.js #5214). A page that did not ask is not cut. `Mark` gained `EndOffset` and `Time` (the producer's clock at a start and an end) for this.
- **Replay.** The ring keeps the newest 1,024 marks, never more than 2,048 (cut back by half a list at a time, so a mark costs no copy). A stream that attaches by an offset the host has is sent the mark that ends AT that offset again (the stream may have cut after the bytes and before the frame); the page takes none that ends at or before the last one it took. A gap moves the cursor past the marks it skipped. The kept end of a terminal that ended by itself serves its marks the same way.
- **Trust.** The scanner's trust is per datum: only the command line (633;E) and the directory (633;P;Cwd) can carry the nonce. Every 133 mark is `unverified` (any program can print it). The host drops a `cwd` mark that is not `nonce` (OSC 7: anything can print it) instead of sending it with a lower trust; a command line and a directory with a wrong or no nonce are never in a frame, a record or a log. "A command is running" for the host is a start mark whose line the nonce vouched for, until an end mark. A forged start (no nonce'd line) does not make a terminal busy. A forged end mark can make a running command read idle (the end mark has no nonce: the scripts of steps 2 and 3 print plain 133;D); the process that holds the foreground is still asked, so a program that holds it stays busy. Making `D` carry the nonce is a change of the four scripts and is not done here. A prompt-start ends a running command only after a nonce-proven `633;P` with no other prompt or command mark between (the scanner's `ourPrompt`), which each of the four scripts prints before its `133;A`; a foreign or forged `133;A` (a nested shell's prompt framework, an ssh) ends nothing. A forged `133;D` still ends it.
- **B-106.** Closed for shells with the integration: a command that runs while the shell holds the foreground (a builtin loop, a long `ssh` that the shell is the parent of, any command) reads `busy` where `idle` was said, from `ChannelTerminalBusy`, `ready.busy` and the page's `busy` (the page answers from the marks without asking the host). NOT closed: a stopped job (the shell says its command ended when it takes the foreground back after Ctrl-Z) still reads `idle`; and terminals without the integration (skipped, off, failed) are as before.
- **The page asks the host nothing while the producer has said it.** `busy()` returns `{state: 'busy', name}` from a start mark with trust `nonce`; otherwise it asks the host, which also folds the marks in (the same fact from the same producer for a caller that has no stream). The page knows nothing of idle from marks (only the host combines it with the process group), and forgets what it knew at a `ready` that brings a fresh screen and at a `gap`.
- **The read call.** `ChannelTerminalCommands(capability)` (a capability call: one `not-found` for a capability that opens nothing; denied to remote audit browsers in `internal/auditgate/policy.json`). The record is read under the output lock, in one step with the length of the output.
- Not done on purpose: no UI, no gutter, no marker creation (step 5); the Settings opt-out and the tier (step 6); the events lane gets the fold of `Busy` and `attach` (`withMarks`) and no frame.
