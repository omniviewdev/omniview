## What the plugin says: the rules, each with its test

The count is of the selection of the read (its namespaces and names), not of the page. `exact` = the plugin holds them all; `estimate` = the API server's `remainingItemCount` (its documentation: "estimating the size of a collection"); `unknown` = never a guess, and a collection is never read to the end to count it. The wire has no "as of" beside a count but the page's `SourceRevision` (the List's resourceVersion) and `Consistency` (`bestEffort`); no wire field is added.

| Case | Count | Test (`native_count_test.go` unless named) |
|---|---|---|
| first page of an unfiltered List, one namespace or every namespace, with more to give | `estimate` = the page's records + `remainingItemCount` | `TestTheCountOfAChunkedList…`; `TestNativeEnumerateUsesBoundedSourcePagination` (`native_read_test.go`) |
| the page ends the read (one object read by a page of one; a collection that fits the page; a label query or a name read whose matches fit) | `exact` = the page's records | `TestTheCountOfAListThatEndsInThePage…`, `…OfALabelQuery…`, `…OfAReadNarrowedToNames…` |
| an empty collection, an empty namespace, a selection that selects nothing | `exact 0` (the last costs no request) | the same, subtests "an empty collection", "an empty namespace", "a selection of no namespace" |
| a cluster-scoped kind | as above (no namespace to narrow by) | `TestTheCountOfAClusterScopedKind` |
| a label or field selector with more than the page: the server does not count under one, and a server that says a number anyway is not believed | `unknown` | `TestTheCountOfALabelQueryIsExactOnlyWhen…` (the fake reports 999 under a selector) |
| `remainingItemCount` absent (an aggregated API, an older server) | `unknown`; no second read to count | `TestTheCountIsUnknownWhenTheServerDoesNotSay…` |
| a page that follows another | `unknown` (it does not know what the others held) | `TestTheCountOfAContinuedPageIsUnknown` |
| several namespaces, a page of one (it ends in the first) | `unknown`; `exact` when the page holds them all | `TestTheCountOfSeveralNamespaces…` |
| a server that ignores `limit` | the existing `RESOURCE_LIMIT`; never a count made by reading everything | `TestAServerThatIgnoresLimitIsNotReadToTheEndToCount` |
| a kind the user may not list (403) | the call fails with the existing `FORBIDDEN` (status 403): the consumer shows `unknown` with that cause, never a zero, and no other kind is affected; the failure is not kept | `TestAKindTheUserMayNotListIsForbidden…`, `TestAFailedCountReadIsNotKept` |
| a CRD (any discovered kind) | the same path; the tests' own kind is a custom resource, and row 5 counts a real CRD | `widgets` throughout; proof row 5 |
| a kind whose list is open (the plugin's source holds every object of the scope, synced, not narrowed to a name): whole namespaces only | `exact` from the source, live; never below the page's records (the wire rejects that, and the source may be a moment behind) | `TestTheCountOfAKindWhoseSourceIsOpenIsExactAndLive`, `…OfAClusterScopedKindWhoseSourceIsOpen…`, `TestAnOpenSourceCountsOnlyWhatItHolds`, `TestASourceThatIsNotTheWholeCollection…`, `TestACountFromTheSourceNeverFallsBelow…`; `clients/live_count_test.go` |

A **count read** is an `Enumerate` with `pageSize: 1` and no cursor (a page of one is how a list of kinds asks how many each has; the cursor of a read is bound to its page size, so nothing continues it). It is one `limit=1` List with no `resourceVersion`, which the storage serves and counts (the watch cache ignores `limit`), and it decodes one object, however large the kind (`TestACountReadIsOneListOfOne…` for 1, 2 and 300 objects). It runs through the connection's `CountReads` (`clients/count_reads.go`):

- **at most 4 at a time** (`CountConcurrency`; `TestThirteenCountReadsReachTheServerFourAtATime`: 13 kinds at once, the server sees 4); a read that waits for a turn, or for the identical read in flight, stops when its caller goes and never asks (`TestACountReadThatIsWaitingForARoom…`);
- **identical reads at once are made once** (`TestIdenticalCountReadsAtTheSameTimeAskOnce`), and a waiter is not given the cancellation of the read it waited for;
- an answer is **kept for 30 s** (`CountStaleness`, the Q0 number), as the wire holds it, so each reader gets a page of its own (`TestTheAnswerOfACountReadIsNotShared…`); at most 256 answers, none whose records exceed 64 KiB; a failure is never kept;
- the answers **end with the connection's clients** (`ShutdownInformers`, which `RefreshClient` and `DestroyClient` call): what old credentials were answered is never given to the new ones (`TestTheCountsOfAClientThatWasReplaced…`);
- a label query and a page of many are neither limited nor kept (`TestALabelQueryAndAPageOfManyAreNeitherLimitedNorKept`).

The count of an open kind is not read from a kept answer: it is the source's at the time of the read, so it moves while the kept page does not (row 9). The plugin polls nothing. A count read of an open kind still makes its one `limit=1` List when no answer is kept (the page's one record comes from it, once per 30 s per scope); only the count is the source's.

## What the plugin UI must call to show a count (for the next step)

Today, with no change to `ui/v1`: for each kind, `useResolvedResourceTarget({ pluginID: 'kubernetes', route: { connection }, type: kind.type, enabled })` gives `{ targetId, target }` (pass `scope: [{ dimension: 'namespace', match: 'oneOf', values: [...] }]` to count one namespace), then `useResources({ pluginID, request: { targetId, request: { target, pageSize: 1 } }, collection: false })` (the call the list's own first page makes with `pageSize: 256`; an explicit page is a plain query: `gcTime: 0`, `retry: false`, no poll, the caller refetches). The record shape the host hands back:

```ts
resources.data: HostSourcePage = {
  records: HostRecord[],                      // at most one: ignore it
  sourcePage: { count: Count, sourceRevision?: string, consistency: 'bestEffort', coverage, nextCursor? },
}
Count = { kind: 'exact' | 'estimate' | 'unknown'; value?: string }   // value: a canonical unsigned decimal string, "0", "326"; Number(value) is the sidebar node's `count`
resources.error: parseAppError(error).code === 'FORBIDDEN' (status 403, type 'omniview:resource/forbidden')   // this kind only: show nothing
```

`exact` and `estimate` are drawn as the number (whether an estimate wears a `~` is a design question: Q0 section 9); `unknown`, an error and a missing type draw nothing. Thirteen kinds at once is what the plugin is built for (4 at a time per connection); a refetch inside 30 s is answered from the plugin's memory, so the sidebar may refetch on its own clock (30 to 60 s) without asking the API server. For a kind whose list page is open, the same call is already exact and live. A plugin UI that wants no call at all can use the `count` that its own `useKindRows` returns (`ui/src/kinds/useKindRows.ts:139-140` at `4214d04`), and only as that hook gives it: `exact` (the rows) once the collection is `complete`, that is once its snapshot has finished, and until then `unknown` with the number `loaded` (A10's `N Pods loaded` wording). The rows of a collection that is still loading are a part of it, so while it loads the sidebar shows that wording or nothing, never `rows.length` as a total. It is not the host's `view.count`, which the same lines say is not kept live (an object added after the snapshot leaves it one short). A connection scoped to several namespaces gets `unknown` from one call: count each namespace and sum (at most 8, Q0), or draw nothing (Backend catalog). The host's `useResourceCounts` (Q2) is the planned wrapper; this is the call it will make.
