## Private package: what consumers need

```yaml

  contents: read
  packages: read
jobs:
  example:
    runs-on: ubuntu-24.04
    container:
      image: ghcr.io/omniviewdev/omniview-ci@sha256:<digest of .github/ci/image.lock>
      options: --init
      credentials:
        username: ${{ github.actor }}

      - name: Match checkout directory ownership to container user
```

## How versions and staleness work

- One home per version: Node `.tool-versions` (`nodejs`), pnpm `package.json` `packageManager`, Playwright `pnpm-lock.yaml` (the one version `playwright`, `playwright-core` and `@playwright/test` resolve to). These are Dockerfile build arguments **without a default**; `scripts/ci/check-image.mjs inputs --format docker-args` prints them. Go: `go.mod` is the floor (same series, patch at or above), the Dockerfile pins one exact patch (1.27.3, the patch five workflows already pin; 1.27.4 is current). kind, kubectl and golangci-lint are the Dockerfile's, checked against the copies the Pods workflow and PR Checks still carry (`tool-mirror-mismatch`); a Go pin elsewhere that differs is a warning (`go-pin-differs`).
- The lock records the hash of the inputs (Dockerfile bytes, Node, pnpm, Playwright, Go floor), the tag, the digest and the manifest the image reported. `check` fails when the lock is behind (`inputs-behind`), when the manifest holds another Playwright, Node, pnpm or Go than the repository (`*-mismatch`), when two digests are pinned (`digest-split`) or one that is not the lock's (`digest-mismatch`). Mutable tags are `mutable-pin` warnings until the consumers move (`--require-digest-pins` makes them errors). Negative controls (44 tests, red first; mutating each rule away fails exactly its test): two digests, a Playwright mismatch (also alone, with the hash agreeing), Go below and above the floor, another Node, another pnpm, an edited Dockerfile, a missing or unreadable lock, a mirror that disagrees, a manifest without a browser, an image built from other inputs, a lock written for an image that does not match.
- Rebuild: weekly (Monday 05:17 UTC) always; on a push to main when the guard says the lock is behind; on a pull request when the inputs moved or an image file changed (build and smoke, no push); `workflow_dispatch` with `publish: true` from any ref. A path filter cannot see "the Playwright line changed", so the workflow runs on `pnpm-lock.yaml`, `package.json`, `go.mod`, `.tool-versions` and every workflow change, and the guard decides.
- Tags: `ubuntu24-<yyyymmdd>-<sha7>`, never overwritten (a second run of the same sha on the same day reuses the tag). `ubuntu24-v1`, the mutable tag the five consumers pull today (`pr.yml`, `pr-checks.yml` x2, `e2e-runner.yml`, `desktop-build.yml`), is **no longer rebuilt**: it stays what the last Monday build made it until B4 moves them to the digest. The docs that call it "refreshed weekly" (`docs/development-native-toolchain.md:33,176`, `docs/development-workspaces.md:715`) are wrong from the merge; B4 rewrites them.
- No BuildKit layer cache is used: a 2 to 3 GB cache would compete with the browser and Go caches in a repository cache that is already over its 10 GB limit (11.2 GB, 34 caches on 2026-11-20).
