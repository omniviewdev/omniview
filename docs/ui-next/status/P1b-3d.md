## The rule, as built (A22)

A session is identified by (plugin id, target descriptor `id`); the title, the scope and the resource are presentation. `LogStreams.open` (after validation) asks `sessionOf(plugin, id)`: a session of that plugin and id that is STARTING or RUNNING is SHOWN (`store.revealSession`: the panel opens, the Logs tool is chosen, the session is its tab; one change; no focus moves) and answered, and the plugin's `open` is NOT called, so no second stream starts. A session that has ENDED (the lead's ruling: the host has no Reconnect, so showing a dead tab again traps the user), FAILED, is KEPT by the plugin's unload (A21), or was restored from the last run (the registry never held it) gets a NEW session beside it; the old one stays as it was, readable, its stream still the session's, until its tab closes. Of several live ones the newest (there is at most one). A session the panel cannot show (its tool is gone) is still the target's one live session: the press answers it, starts nothing, and the tool brings it back (CodeRabbit found the first version opening a second, hidden stream there: #609).

**Ended + new, same title and scope.** The new session is `title (2)`, the ended one keeps `title` and its ended glyph; the accessible names are `title, ended` and `title (2)`. Tests: `LogStreams.test.ts` "opens a NEW session beside one whose stream has ended on its own" (names and states), `PluginHost.logs.test.tsx` "opens a new session when the stream of the session it has has ended" (names, drawn text, the lead slot's `data-state`), and `Panel.test.tsx` / `labels.test.ts` (names never alike).

**The Kubernetes plugin** already sends a stable id per Pod (`podLogTargetId`, `pod/<connection>/<namespace>/<name>`): NO plugin change. What a user of that plugin sees now when pressing Logs twice on a running Pod: the first press opens the tab and the panel; the second shows the same tab (the panel opens if it was hidden, Logs is chosen, that tab is active, focus stays where it was) and starts no second stream (the SDK's `ListSessions` stays at 1). If that Pod's stream had ended (a finished Pod, a deleted one, a crash) or failed, the second press opens a new tab `name (2)` beside the old tab, which stays readable. Two Pods of one name in two connections are two targets: two tabs of one title, each drawing its connection. Two Pods of one name in two namespaces of ONE connection have different ids but the same title and scope (the plugin's scope is the connection): `name` and `name (2)`, told apart by the card (Namespace is the plugin's fact).

## The tab

`core/panel/selectors.ts` `facesOf`: the scope is drawn only on a session whose title another listed session of the tool shares with another scope (and on that one), the ordinal only for the same title and scope; `SessionItem.name` is the words the tab draws (`title (2) · scope`); no two tabs of a tool share a name (a title that looks like `a (2)` beside two sessions of `a` is told the next number). `SessionTabs.tsx` keeps the name and the scope apart in the DOM with a space the flex row does not draw, so the text a tool reads off the tab is `title scope`: the axe finding of P1b-3c (`aria-label` `zsh · north`, visible `zsh` and `north` run together) was the DOM's, not the name's. Reproduced red in jsdom first (`the tab draws "orders-api/appnorth-yard" and is named "orders-api/app · north-yard"`), green after; the real engines' axe case is in the panel and logs probes. The Log region's name keeps the session's own scope (`Log, title · scope`): it is not a tab. The card keeps its own facts (the plugin's Connection and Namespace); a lone session of a plugin that gives no facts no longer shows its scope anywhere but that region's name.

## Spec errata (for the errata pass, row N10; found here, not chosen silently)

1. **A failed start: RM1 says a retry reuses the failed slot, "never a second session beside the failed one"; the mock's `openLogsFor` code opens a NEW session beside a failed one (`:2565`).** Built as the mock's code does, A22. (The host has no Retry; when it has one it should reuse the slot, as RM1 says.)
2. **The mock re-activates only its own runner targets (`:2564`); the mock's plugin-produced targets (its Kubernetes logs) twin on every press.** A22 deviates on purpose for plugin targets (VS Code and JetBrains focus what is already open).
3. **The mock's accessible names do not tell ordinal twins apart** (`sessionName` never carries the ordinal: two `(2)` twins both read `Logs · Connection: north-yard · Item orders-api, failed`), while TI1/SCT1 and KA-055 say the ordinal and the qualifier are in the aria-label.
4. **The mock drops a trailing `/container` from a session tab's name unless another session differs by it (`tabParts` `:234-238`, SCT1); the host keeps the whole title** (P1b-3b decision 3: the plugin writes the container last, after a slash).
5. **`openLogsFor` finds only the OLDEST session of a target** (`.find`): with [failed, running] of one target a press opens a third. The host looks at all of them.

## The Pods cluster check (found by the CI of #609, run 44835033957)

**Decision: the accessible name carries the state of EVERY session that is not running, alone or in a twin, not only where it tells twins apart.** The mock does the same for a single exited session: `shell-widgets.js:264` gives the strip's tab `aria-label="<name>, exited"` (`i.ariaLabel + (st ? ', ' + st[1] : '')`), and the glyph that shows the state is `aria-hidden` (`:263`); SCT1 says the accessible name is the whole name and the state. A suffix only for twins, with the ended state left to the glyph, would hide from a person who cannot see the strip that a lone session ended, which the strip must still say. So the name stays `title[ (n)][ · scope][, state]`, the HOST is unchanged, and the check is changed on purpose: it asserts the exact name `<pod>, ended`, both parts (`compareTabName`; its controls in `logs.test.mjs` are the old `<pod> · <connection>` name, an ended session named without its state, a running one named with it, another Pod and no tab).
