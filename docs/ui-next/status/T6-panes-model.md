## Decisions

1. **Shape.** `PanelState.panes: Record<ToolId, PaneGroup>`; `PaneGroup = { axis: 'row' | 'column', panes: { id, session }[], ratios: number[], active: PaneId, seq }`. A flat list with an axis, not a tree: stacked panes are `axis: 'column'` (no saved-form change), nesting is a later change to `PaneGroup`. A tool with no group shows one session (`active[tool]`), exactly as before. `paneLayout(state, tool)` is the one thing a body reads: it gives one pane of ratio 1 for a tool with no group.
2. **`active[tool]` stays the one source of the tool's session**, and it is the session of the active pane. `settle` reconciles it after every operation (a session chosen or opened that no pane shows takes the active pane; the displaced session stays a tab). So `activateSession`, `revealSession`, `openSession` and `closeSession` need no pane code and a single-pane panel behaves as today.
3. **Split is a NEW session**: `splitPane(tool, input, { extent })` makes the session itself (id from the model; an id that exists is `taken`), inserts the pane after the active one, equalises, focuses the new pane, opens the panel. A tool with no session just opens one. Refused `full` when `(n + 1) * 80 > extent`.
4. **Close**: closing a pane's session removes the pane, hands its share to the others in proportion, moves the focus to the next pane else the previous, dissolves the group at one pane. The last session leaves the tool empty as today.
5. **Minimum**: `PANE_MIN_PX = 80` and `minRatio(extent, count)` (never more than `1/count`). The model does not know pixels: every operation takes the `extent` and ends with shares within the minimum for it (`splitPane`, `moveSash`, `equalisePanes`, `fitPanes`). The invariants that need no extent (sum 1, above zero, one per pane) are in `checkInvariants`; the minimum is checked by the fuzz per operation.
6. **Saved**: optional `layout` (`{ version: 1, tools: { [tool]: { axis, sessions, ratios, active } } }`) with a version of its own. **The panel's `PANEL_VERSION` stays 1 and `MIGRATIONS` stays empty**: the issue asks for "a version or migration"; existing tests (unchanged) pin `version: 1`, a serialised document's exact keys and "no step at version 1", so a bump or a step would break them. A document with no `layout` is every panel saved before panes: it reads as one session per tool, with nothing repaired, and saves back as the identical document (a panel with no group writes no `layout` key). A layout of another version, or damaged, costs the layout only (`repaired`, a problem sentence starting `the layout`); shares that are not shares become equal; a pane whose session is not saved, is another tool's, or is in a pane already is dropped; fewer than two panes is no group.
7. **Hidden sessions**: stored panes keep their sessions when a plugin leaves; `paneLayout` leaves out panes whose session is hidden and shares their space in proportion (stored shares untouched, so they come back with the plugin).
8. Closed refusal reason `full` added to `RefusedReason`. No consumer switches on it.

## The controls (negative controls, both halves)

Script: `docs/ui-next/status/T6-panes-model/controls.sh.txt`. Run whole from the worktree root: `bash docs/ui-next/status/T6-panes-model/controls.sh.txt` (about 3 minutes; exit 0 when every control is caught by the test named for it). It copies the model to a scratch directory, puts one fault in, runs vitest on the copy, and lists the failing tests; then skips the named tests (the assertion removed) and reports what is still red. A baseline run of the copy comes first and must be green. 14 controls: a split that copies a session; ratios that do not sum to 1; an old saved state rejected; a pane below the minimum; no room check on split; closing the active pane keeps it active; closing leaves the pane; a group of one kept; the active session not kept in the active pane; saved shares not renormalised; a panel with no group saving a layout; the panel version moved; equalise that does nothing; a hidden pane keeping its share in the drawing.

Result of the last whole run: `BASELINE ... exit 0`, 14 of 14 RED by the test named for each, `ALL CONTROLS CAUGHT BY THEIR TEST`, exit 0. With the named tests skipped, 2 faults go undetected (the active pane's focus passing on close; the document's renormalised shares: each is guarded by that one assertion) and 12 are still caught by the fuzz or another test as well. Two controls were first found NOT caught and fixed: "saved shares not renormalised" was an equivalent mutant (restore renormalises anyway) until a test read the document itself; the script's skip did not skip until it matched the test title alone (vitest matches the name pattern against a joined name a "full name" does not equal).

- The panel's `activateSession` for a session no pane shows replaces the active pane's session. That is the model's rule (decision 2); whether the layout should offer another gesture for it is the layout's call.
- The older `fuzz.test.ts` at the default 5 s timeout under load: not green here, green with a longer timeout; not changed by this work.
- The controls' second half (assertion removed) is by skipping the named tests, not by editing the assertion line: it shows what else catches the fault, not that the assertion alone was the cause.
