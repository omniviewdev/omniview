# Status: Q2 (the Kubernetes plugin's sidebar draws counts: the proof on a real cluster)

- Agent: SidebarCounts (the proof harness and the first run: SidebarCounts.ProofHarness; the rerun for the refusal rule: SidebarCounts.ProofRerun)
- Goal: step Q2 of the Q0 proposal (backend catalog B-30, the display half): the plugin's sidebar draws the number of objects of each kind beside its entry: `exact` as the number, `estimate` as `~` and the number (named "about"), nothing for a count it does not have (not read yet, unknown, a kind the user may not list). It asks for the kinds of the top level and of the groups that are open, and for no others: the host tells the plugin which groups are open (`SidebarContextV1.open`) and not which rows are scrolled into view, so the unit is the group, and the kinds of an open group whose rows are below the fold are read too (difference 8). A count read the user may not make is asked once and not again on a timer (the rules below). The host half is the Q2a PR (the tree's count slot and the open groups a plugin's sidebar hook is told: `omniviewdev/omniview#598`, merged as `15f67c4b`); the plugin half is `omniview-plugin-kubernetes#273`. This file is the proof of both, on a real kind cluster, in the real host, in WebKit and Chromium: every visible count against `kubectl`, what the counts cost the API server (read from its own audit log), the open kind's live count, a user limited by RBAC and what his refusals cost, no layout shift, and the mock beside. It is not a proof of a rule that follows the sidebar's viewport: the plugin has none. The tools that ran are in `docs/ui-next/status/Q2/` (`.txt`; drop the suffix to use one).
- Worktrees: host pin (this file and the tools beside it) `~/Repos/omniviewdev/worktrees/ui-next-q2-status`; the host the proof ran against `~/Repos/omniviewdev/worktrees/ui-next-q2-proof-host` (detached at `15f67c4b`); plugin under test `~/Repos/omniviewdev/worktrees/kubernetes-ui-next-q2-proof-new` (detached at `6f8a78d4`, the PR head); the control, the plugin before the change, `~/Repos/omniviewdev/worktrees/kubernetes-ui-next-q2-proof-base` (detached at `46f66f4b`)

## What the sidebar says: the rules, each with the check that holds it

The host draws a row from the plugin's node (`Tree.tsx`, `core/count.ts`); the plugin makes the node from what the backend says of a page of one (`ui/src/sidebar/count.ts`). One row, in each state:

| The plugin's count | The row's accessible name | The slot draws | Check |
|---|---|---|---|
| `exact` n (0 or 1 objects; the kind whose list is open; the kind whose list was left a moment ago, whose source the host keeps for a while) | `<Label> <n>`, thousands grouped by commas (`Pods 1,234`) | `<n>` | `A:` per kind; the name is parsed by `parseName` (controls: `Pods 50`, `Deployments about 11`, `ConfigMaps about 1,326`, `PodDisruptionBudgets 0` pass; `ConfigMaps ~`, `Pods 1234`, `Pods about` and 14 more are invalid) |
| `estimate` n (the API server's `remainingItemCount` + 1, for 2 objects or more) | `<Label> about <n>` | `~<n>` (the tilde is hidden from assistive technology, which hears "about") | `A:`; `sameAsDrawn` holds the drawing to the name |
| no count: not read yet, `unknown`, a read that failed or was refused, a value that is not a safe whole number | `<Label>` alone | a slot that is there and empty (`[data-shell-part="count"]`, 32.5 px at a 13 px base), never a dash and never a zero | `S:` (skeleton), `F:` (27 refused rows) |
| a group | `<Label>` alone | no slot | `B:` |

What a count costs (`ui/src/sidebar/store.ts`, `useSidebarCounts.ts`; each line is a check of the `window` section or, for a refusal, of the `limited` section, read in the audit log of the API server and in the calls the page makes to the host):

- Wanted: the kinds of the top level (Nodes, Namespaces) and of the groups the host says are open (`SidebarContextV1.open`), while the connection is connected, for the kinds the catalog serves, and never for a kind whose list is open (the list speaks for it, live, from its own source). Collapsing a group stops its reads and keeps its answers for the refresh interval.
- One read is one `Enumerate` with a page of one: one `limit=1` List at the API server, with no selector, no continue and no resourceVersion (`C:`). The first round with every group open is 28 of the 29 kinds; the 29th, Pods, is the open list.
- At most four in flight (the backend's `CountConcurrency`): in the page's calls and at the server (`C:`, `G:`).
- A count is read again once it is 60 s old and not before (`R:`), and the backend answers a read inside 30 s from its memory (`M:`). A user who opens the page and does nothing causes no repeat (`I:`).
- A group opened again inside the minute asks for nothing (`G:`); after more than a minute it reads exactly its own kinds, once each.
- A count read the user may not make (a 403, `FORBIDDEN`) draws nothing and is **not asked again on a timer**. It is asked again only (1) when its group is opened again (collapsed, then expanded), (2) when the connection changes, (3) when the namespaces counted change (a kind that lives in no namespace is not asked again for that), or (4) when its list was open and is left (the user visited it: while a list is open the sidebar does not read that kind). A kind that failed some other way is still asked again at the refresh interval, like any other. An ask of a refused kind is one List at the API server and the plugin's backend keeps no failure, so every ask reaches it (`F:`, row 8: read from the audit log for the limited user, at first sight, in a window left alone, when a group is opened again and when a list is left; cases 2 and 3 are not driven by the proof, see Not verified).

The refusal (`ui/src/kinds/source.ts`): the list of a kind the user may not list says `You do not have permission to list <Kinds> in all namespaces.` (for a kind that lives in no namespace, `... in this cluster.`) under the host's heading `Couldn't load <Kinds>`, with no Retry and never the host's fixed sentence (`F:`, all 27 refused kinds: 21 namespaced, 6 cluster-scoped).
