## What a definition could NOT express and needed code for

A definition is data plus one function per question; these needed code, and each is shared or per kind, never in the generic page:

1. **The state word.** Pods: kubectl's `printPod` (the existing 100-line port). Deployments, StatefulSets, DaemonSets: a rule over four counts (`kinds/workload.ts`, shared; each kind reads its own counts: `status.*Replicas`, `status.*NumberScheduled`). Jobs: kubectl's `printJob` (conditions, then a deletion in progress). A definition cannot say "the state is the first true condition" or "a rule over three counts": it names a function, and a test holds the words to the roles of the ONE table (K61.3, `kinds/status.ts`).
2. **Reading the object.** The API omits a count that is zero (`omitempty`): a Deployment's `status` holds no `readyReplicas` when none is ready (the real `scaled-zero` and `bad-image` objects show it), while a DaemonSet's `desiredNumberScheduled` and `numberReady` are never omitted. So an absent count is the API's zero once the object has a status for the first kind of field and unknown for the second; a Job's absent `completions` is one. That is knowledge of the API per field, not a column path.
3. **Cells that read two fields or the clock.** Ready on a Deployment or StatefulSet is a watched ratio (the mock's `watch`: below the wanted count it is an `attention` state with a tip). Completions follows kubectl's rule (`2/1 of 2` for a work queue). Duration of a Job that has not finished counts: a new cell kind `elapsed` and a span formatter (`spanSince`) on the kit's age clock, one timer for all.
4. **The tail of a name** (Pods and Jobs only), **the sort value** of each field, **the widths**: a Status column holds the longest word of its rule (150 px for the three workloads, 107 for Jobs: the mock's worksheet formula, 7.2 px a character plus 42), because a fixed column keeps its declared width here while the mock fits to the words its data holds (measured at 1440: 113, 95, 95, 100).
5. **Not expressed at all, because the list page's contract has no place for it:** the wide set (the columns the mock adds while the list's box has room: Deployments Available and Images, DaemonSets Available, Current and Images, Jobs Images and Owner, StatefulSets Images; the mock shows them at 1440), the Columns chooser (hidden columns exist in the definitions of Pods only), facets (Pods Node and Jobs Owner: Pods has one in its definition, nobody draws it), sort state, the selection column and its commands, the primary `Create <Kind>`, and a count on a sidebar entry.
