## Decisions and findings for the lead

- **N3 against the count lane.** The assignment asks for a count lane inside `SearchField`; N3 says the toolbar carries no count text and N1 puts the count in the footer. The lane exists for a search in content (the mock's find bars, PN-07) and is absent unless `count` is passed; the list page does not pass it.
- **E6 against the hidden-columns note.** `CollectionFooter` supports the note (the mock's healthy footer carries it); the Pods page should leave it out (E6, ch13 G5/FT1) until the lead decides.
- **Refresh feedback.** The utility's disabled reason (`Refreshing`) is not written in the identity line (the mock does the same: it would add a 28 px line when it comes and goes); it is written in the footer as `Refreshing…`, which is the visible reason of P2.
- **List headers have no tile.** The mock's list header passes none (the `Math.min(size, 20)` tile is a detail-page element); the definition's `tile` is optional.
- **Create Pod and the overflow are not drawn on the Pods page (PX1, plan 1.2 tier C).** The mock's title is 918 px wide beside its Create + Refresh + overflow lane; with only Refresh it is 1077. The probe compares the full lane in the header fixture and the title's x, y and height on the page.
- **Tooltips.** Icon-only controls and clipped text carry `data-ov-tip` and `data-ov-clip` (the contract of PR #519, not merged); nothing shows until it lands. No `title` attribute anywhere.
- **Tooling traps found.** (1) The kit's tsconfig has `noUncheckedIndexedAccess` but ESLint's `no-unnecessary-type-assertion` says the opposite for `array[i]!`: write tests without indexing. (2) Stylelint's `no-unknown-custom-properties` needs a fallback on an inline data parameter (`var(--_w, 60%)`), and `background-color` allows no fallback (define the private property on the parent). (3) jsdom hides every `[popover]` that is not open: a test that opens `RowMenu` needs the `[popover] { display: block }` rule as `RowMenu.test.tsx` does. (4) `declarationsOf` merges rules inside `@container` into the base rule: read container rules through `cssRules` (see `PageHeader.test.tsx`). (5) The vocabulary guard scans comments and tests: no Pod, namespace or the like in the kit (13 hits were fixed).
- **What the mock reference measured that the parts must reconcile in the probe round.** (1) An error with no rows: the mock draws NO footer and the pane is 12 px shorter (759 against 771: the pane keeps its bottom padding); `DataView` always draws the footer (`0 items loaded`): decide, and if the mock wins make the footer absent in the `error` state. (2) Search: no hover paint; focus darkens the border and adds a 2 px ring (the part copies it); Escape clears natively in Chromium and does nothing in WebKit, the part clears in both on purpose; no native clear button in either engine. (3) The operation slot: paused shows Cancel plus an overflow with Resume inside, cancelled shows Retry and Dismiss; the presenter draws the record's own commands (cancel-kind while active, the first one after), so a caller gives a cancelled record a Retry. (4) h-detail-long at 1030: the mock's facts box (585 px) hard-clips the third fact with no ellipsis and gives the fourth no width; the part clips with `overflow: clip` and an ellipsis on the last fact only, so it may differ there. (5) The mock logs a 404 for `/native/host.js` on every load (its own). (6) At 1030 the default column set has no CPU and Memory, and the footer says `2 columns hidden at this width` in the mock (E6).
