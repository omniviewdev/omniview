Touches `packages/omniviewdev-runtime/**` and this file only: PR #542 owns `ui-next/**` and `packages/kit/**`, and nothing in the Go host changed.

**State (2026-11-19): the contract is built, tested and measured; the PR is ready for review.** `@omniviewdev/runtime/ui/v1` gains one function, `openLogStream`, and 13 types. A log viewer reads a session through a framework-free store (`subscribe` and `getSnapshot` are the two arguments of `useSyncExternalStore`; lines come out of `read(max)` at the consumer's pace), with a bounded buffer that counts what it drops, a local pause, a state machine with a cause, and a `close()` that releases every listener. Nothing in this step draws a line: the viewer is P1b-2, the host tool and the Kubernetes plugin are P1b-3 (the last section).

## The surface

**Why not re-export `useLogs`.** See section 2: it passes the old-library guard and has the wrong shape, and in the new shell it throws (no drawer provider). The entry is a function, not a hook, because the host owns the stream: a hidden session must keep its lines, and a body that unmounts must not close it.

```ts
const stream = openLogStream({ plugin, connection, resourceKey: 'k8s:/pods', resourceId: 'web-0', resourceData, reference, route, target: 'app' });
const status = useSyncExternalStore(stream.subscribe, stream.getSnapshot);   // state, paused, cause, sources: a new object a few times a session
stream.subscribe(() => requestAnimationFrame(pump));                          // lines: woken at most once between two reads
const { lines, dropped, held } = stream.read(2000);                           // the consumer's pace
stream.pause(); stream.resume(); await stream.close();
```

**The rules** (all in `src/logStream.ts`, tested through the entry):

- **Backpressure is the buffer.** `read(max)` takes at most `max` lines; unread lines are held up to `maxBufferedLines` (default 100,000) and `maxBufferedChars` (default 33,554,432); past either the oldest are dropped, counted (`LogBatch.dropped` in position, `stats().dropped` as a total) and visible as a jump in `LogLine.seq`.
- **No wake-up per line.** `getSnapshot()` changes on status only (state, pause, cause, the list of sources, which is published at most every 50 ms so 500 sources connecting are one render); the counters are not in it. Held lines wake the subscriber once between two reads, with the same snapshot.
- **A pause is local.** `read` returns nothing and the backend is not told (the SDK's pause discards lines). The bound holds while paused and the drops come out with the first read after `resume()`. A session that ends while paused stays paused.
- **State.** `starting` until the backend says the sources are connected or a line arrives; `streaming`; `paused`; `ended`; `failed` with `cause { stage: 'create' | 'session' | 'source', source?, message, error? }`. A source's failure is a state of that source and the stream goes on; every source failed when the session ends is a failure, with the last cause; an error with no source fails the session; the end that follows an error does not undo it. Lines that arrive after `ended` are kept (catalog: the host sends the end ahead of the last batch). When the session ends, and when `close()` ends it, every source still going ends with it; a source that failed or was removed stays what it was, and a source first heard of after the end (a late line, a late answer to the create call) is born ended.
- **Sources.** `sources` lists what the stream has heard of: `connecting` until a first line, then `streaming`, `reconnecting`, `ended`, `failed`, `removed`, with the backend's message, and labels (events carry none) from the answer to `CreateSession` or from the first line that has any, whatever state the source is in by then; once a source has labels they are not read again.
- **Defaults.** `follow` true, `tailLines` 1,000, timestamps and source events always on, `previous` and `sinceSeconds` as given; a request that is not well formed throws, every runtime failure is the state `failed`.
- **Close.** The answer is reserved first, so a subscriber that closes the stream in reply to what it hears (the `ended` it is told, or the last status `close()` publishes) is handed the same promise and starts nothing: one notification more, one `CloseSession`. Then, synchronously: the Wails listeners and the store's listeners are released, the buffer is dropped, the sources end and the last status is published. Then: a call still out is cancelled and awaited, and `CloseSession` follows; a 404 is ignored and any other refusal rejects the returned promise (the stream is closed either way).

Not in the entry, on purpose: enabling and disabling sources (it needs a full-options update first), level detection and ANSI parsing (they are the viewer's, per line, at append), a time parse (`LogLine.timestamp` is the text the backend sent, '' when it sent none), and re-opening a failed session (the host closes the stream and opens another from the same request).

## Decisions to confirm

1. **A function that returns a store, not a hook.** The host owns a stream per panel session (so a hidden session keeps its lines and a body that unmounts does not close the session); the viewer reads it with `useSyncExternalStore` and its own frame loop. The spec's `useLogSession(request)` is not built; a hook over `openLogStream` is a minor addition if a plugin ever needs one.
2. **State names.** `streaming` and `paused` map to the panel's `running` (P1a's `PanelSessionStateV1` has no `paused`); `ended` and `failed` map as they are, with the cause. Written for P1b-3.
3. **Two bounded buffers** (the stream's and the view's) of 100,000 lines each; the stream's is configurable. Measured about 24 MB each for the benchmark's lines.
4. **`close()` can reject** (a refusal other than 404): the host catches and logs it, as it does for a plugin's `open` that throws (P1a).
5. **An older host.** A plugin that imports `openLogStream` from a host whose entry lacks it gets `undefined`; the entry's header (rule 4) says so. The plugin step must state the host version that has it.
