## 0. Summary

**Where Omniview stands.** The foundation is the right shape. Go owns the pty with a typed end state, ordered input with typed refusals, size-before-spawn and opt-in credit flow control (#658); the UI is xterm.js 6 with WebGL while visible, VS Code's Mac key sequences, and a written plan T2-T6 (#660). The distance to "what you expect in an IDE" is in four places: **no shell integration** (no cwd, no command boundaries, so no jump-to-command, exit gutter, copy-output or "busy" for the close question), **no reattach** (a window loss ends the shells; the ring has no offsets), **flow control and the hidden-tab hold are two halves not yet joined**, and **pods are a second-class terminal** (exit flattened to one error string, no initial size, no marks).

**What the best terminals have in common** (sections 3.1-3.16, cited there):
1. The host, not the view, holds the truth about a session (VS Code's pty host and its replay recorder, JetBrains' backend session that owns pty and emulator, tmux, WezTerm's mux, Wave's job manager). The view is disposable and reattaches by offset or snapshot.
2. Shell integration is a protocol, not a feature: OSC 133/633/7 injected by the terminal with a nonce, parsed in the emulator, **tee-parsed in the backend** for agents and notifications, with a quality tier (none, basic, rich) and an opt-out.
3. Flow control is acknowledged from the consumer's *parse* callback, in the producer's unit, and a hidden terminal keeps parsing (VS Code, xterm.js's own guide, Tabby) or stops and resyncs (tmux control mode). "Hold bytes and drop the oldest" is not used by any of them.
4. Agents get **their own** pty or pipes and a typed, bounded result (Codex, Zed, ACP, VS Code's agent host). Scraping the user's terminal is the design VS Code is removing (announced for February 2027), and Warp, which does run agent commands in the user's pty, keeps a recurring bug list around the bootstrap it types into that tty (warp#7099, #15653, #16630).
5. Paste, links and OSC are treated as untrusted input (ESC stripping, bracketed-paste guards, link caps and `stat`, OSC 52 policy, nonces). Warp published 10 advisories on exactly these surfaces in June 2026.

**The 12 adoptions, ranked** (layer, size; full table with dependencies in section 4): 1 shell-start contract fix (Go, S) · 2 shell-integration pipeline with nonce and per-session record (Go+UI, L) · 3 reattach by offset with a mode tracker, detach separated from destroy (Go+UI, M) · 4 flow control and hidden-tab policy decided once (UI+Go, M) · 5 size-before-spawn and a resize policy (UI+Go, S) · 6 input layer: paste sanitising, Shift+Enter, Option-as-Meta, chord arbitration, IME build (UI, S-M) · 7 typed exec-lane contract for pods (SDK, L) · 8 agent `run` with approvals and bounds (Go+SDK, L) · 9 links with cwd, `stat`, open-in-IDE (UI+Go, M) · 10 tab/session model and persistence in Go (UI+Go, M) · 11 Wails GoStream transport spike (Go+UI, M) · 12 search, accessibility, renderer hardening (UI, S-M).

**The five pitfalls most likely to bite** (section 5): (1) the shell is started twice, `-i -l` on an already login-restored environment, so `path_helper` moves the user's PATH behind the system's and bash ignores `--rcfile` (`backend/pkg/terminal/manager.go:321-331`, `internal/shellenv/shell.go:97-98`); (2) the UI's hidden-tab hold and the backend's 1 MiB credit contradict each other (`screen.ts`, `execFeed.ts`, `flow.go`); (3) xterm.js 6.0.0 in WKWebView has paste-injection, IME and WebGL-release gaps fixed only on master (`xtermEngine.ts`); (4) T2 reattach on a ring with no offset, size or modes (`manager.go:605-616`); (5) T5 injection meets `TERM_PROGRAM=Omniview`, copyleft reference scripts and a pod lane with no argv/env control.

**What the SDK exec lane must expose** (section 6): the sibling plan `SDK2-exec-lane.md` already covers most of the parity matrix (initial size, offsets and replay, typed `End`, marks, bounded `Run`). The prior art adds a short delta list: a **LOST** end state that is never exit 0 (Kubernetes returns nil on an empty status), the exit **source**, command id, text and **trust** on marks plus a bootstrap path for pods, target-link **health** and a mode-reset string, a **completeness flag** on `Run` results, the host forwarding `seq` (it drops it today), and `errors.As` mapping with the client-go 0.37 `IsUpgradeFailure` type change.

**Open points the owner may want to decide first:** the xterm.js line (6.0.0 as shipped versus the 6.1 beta that VS Code ships), option A or B of the start contract (pitfall 1), and whether the agent `run` tool lives on the same lane as the terminal (the sibling plan says yes).

### 1.4 The transport between Go and the page (a finding about Wails 3.1.0)

The host pins `github.com/wailsapp/wails/v3 v3.1.0`. Terminal output rides Wails **events** (`Emit` -> JSON -> `evaluateJavaScript` in the native window). The same Wails release ships a second primitive, **GoStream** (`App.HandleStream(name, handler)`; JS `Stream`/`JSONStream`): ordered binary frames, a blocking `Send`/non-blocking `TrySend`, bounded queues (8 MiB per window, 256 MiB global, 256 frames), explicit refusal on a full inbound queue (HTTP 429), and a page-generation rule that closes a window's old stream connections when the page reloads or navigates. Its own header states it exists because event payloads spliced into `evaluateJavaScript` "retain host memory above a platform-specific knee (11.6 GB on macOS ... at 100 events/sec of 1 MB)" and because an event emitted from the main thread once inverted 4.4% of events. Evidence: `$GOMODCACHE/github.com/wailsapp/wails/v3@v3.1.0/pkg/application/stream.go:1-45` (rationale), `:60-120` (bounds), `:234-251` (Send/TrySend), `:800-830` (reload retires old connections), `stream_transport.go:50` (`streamMaxFrameBytes = 64 << 20`); Omniview does not use it today (`git grep HandleStream origin/main` is empty). Consequences for the terminal are in mechanisms 2 and 3 and in the ranked list (item 11).

## 3. The sixteen mechanisms

Each mechanism has the same five parts: **Problem**; **What the best do** (cited); **Here** (what it takes, by layer: **UI** = `ui-next/shell/panel/terminal`, **Go** = `backend/pkg/terminal` + `internal/shellenv` + the exec controller, **SDK** = the plugin-sdk exec lane and the Kubernetes plugin); **Simplest correct version**; **Pitfalls** (issue references). Paths follow the citation form in 2.2. Licences differ per project (section 2): this is behaviour and design only. Names in code font are quoted constants or identifiers, not copied code. "Pitfall N" refers to the five pitfalls of section 5; "item N" to the ranked list of section 4.


### 1. pty hosting and process model

**Problem.** Who owns the pty and the child, what dies with the page (reload), the window, the UI process or the whole app, and how a close becomes a clean end without orphans, zombies or a hung UI.

**What the best do.**
- **VS Code** runs a separate **pty-host utility process**; each renderer talks to it over its own MessagePort, main only manages it. A crash restarts it up to 6 times (`_restartCount <= 5`, never reset) and every pty dies with it ("Restarting the terminal because the connection to the shell process was lost"); a 5 s heartbeat (`BeatInterval 5000`, first wait x1.2, create watchdog 5 s) marks it unresponsive. It exists mainly so a hung ConPTY kill cannot freeze the window (vscode#71966). Close sends `SIGHUP` to the **shell pid only**, then waits for 250 ms of output silence (cap 5 s) so trailing data is flushed before it reports `exitCode || 0`; errors are swallowed and there is **no SIGKILL escalation** (`vscode/src/vs/platform/terminal/node/{ptyHostService.ts:26-28,162-173,386-408; heartbeatService.ts:17-19; terminalProcess.ts:27-44,351-354,385-420,472-493}`; `electronPtyHostStarter.ts:59-66,109-125`).
- **JetBrains** keeps the pty in the IDE JVM (or IJent for WSL/remote), nothing survives IDE exit; close is `SIGHUP`, 1 s, `SIGTERM`, 1 s, `SIGKILL` through `killpg` (`intellij-community/plugins/terminal/src/.../LocalTerminalTtyConnector.kt:123-135`; `pty4j/src/com/pty4j/unix/Pty.java:191-201`). pty4j sets the initial size **after** spawn (retrying `TIOCSWINSZ` up to 1,000 times on `ENOTTY`), so a fast child can see 0x0.
- **Zed, Alacritty, Warp, Ghostty** are in-process: the pty dies with the app. Zed tears down with `SIGTERM` to the shell group and a kill 100 ms later (`zed/crates/terminal/src/terminal.rs:3137-3161`); Alacritty `Pty::drop` = `SIGHUP` + blocking wait; Alacritty and Ghostty both set `IUTF8` on the master and do `setsid` + `TIOCSCTTY` (`alacritty_terminal/src/tty/unix.rs:206-211,251-261`; `ghostty/src/pty.zig:134-179,230-257`). Warp has a separate small "terminal server" process only to spawn shells with clean fds (`warp/crates/warp_terminal/src/local_tty/server/mod.rs:1-19`).
- **WezTerm / tmux / zellij** put the ptys in a **server** that outlives every client (`wezterm-mux-server`, `tmux server`, `zellij --server`); `LocalDomain` in WezTerm's own GUI is explicitly never detachable (`wezterm/mux/src/domain.rs:721-727`).
- **Wave / Tabby**: Wave's Go server hosts local ptys in-process (they die with the app) and spawns the pty **only after the UI reports a measured size**; Tabby runs node-pty in Electron main and re-attaches a live pty after a *renderer* reload (`tabby-local/src/session.ts:62-65`).
- **Agent runners** (Codex, Gemini) make every child a session/group leader and kill the group in 50 ms / 200 ms (`codex-rs/core/src/exec.rs:67-75,1005-1042`; `gemini-cli/packages/core/src/utils/process-utils.ts:11-52`).

**Here.** *Go local backend* (#658): in-process pty, `StartWithSize`, a pollable master, owner-window release and SIGHUP then SIGKILL at 1.5 s are already at or above the field (`manager.go:312-363,136-167`). Gaps: (a) **`IUTF8` is never set** (creack/pty v1.1.24 sets only `Setsid` and `Setctty`; checked in the module cache) while node-pty, Alacritty and Ghostty set it, which matters for cooked-mode erase of multibyte text on macOS; (b) the kill goes to the shell and the foreground group, but a process that left the group survives (Codex #61647); (c) `closed_by: window` conflates **detach** with **destroy**: reattach (T2) needs a lease that outlives the window. *SDK lane*: the pty lives in the plugin process with a local raw-mode pty in front of the remote stream (`terminal_real_unix.go:71-87`), so a pod terminal has two ends to tear down. *UI*: nothing.

**Simplest correct version.** Keep the in-process pty: a separate host process buys ConPTY isolation and survival of a host crash, which VS Code does not even give (all ptys die with its host). Add `IUTF8`, SIGTERM between HUP and KILL, a group kill, and a leak test that opens and closes 1,000 sessions and counts `/dev/ptmx` (Gemini lost every new terminal at `kern.tty.ptmx_max` 511/999, gm#29592).

**Pitfalls.** pty4j#181 (a reaper wrote to a closed fd number reused by a new pty: false EOF on a live child; fix = write only under the close lock); vscode#174956 (shells survived a SIGKILLed main process: a node-pty spawn regression); node-pty#967 (kill fallback to a bare pid, pid reuse measured 196x in 120 s on Windows); zed#58651 (8,652 open fds: a per-terminal sysinfo handle); Windows conpty.dll regressions (zed#61819: 10 MB repaint 23-53 s vs 0.76 s with the system ConPTY).

### 2. Session persistence, reattach, scrollback ownership and serialisation

**Problem.** After a page reload, a new window, or an app restart, get the terminal back; decide who owns the scrollback (the thing that can answer "what was on screen"); replay without duplicating or losing bytes.

**What the best do.**
- **The scrollback owner is never the view.** tmux holds a `grid` per pane; WezTerm's server holds the `Terminal` and clients **pull dirty line ranges since a per-client `seqno`** (`wezterm-mux-server-impl/src/sessionhandler.rs:53-151`); Zellij's own xterm.js web client sets `scrollback: 0` (`zellij-client/assets/app.js:538-543`); JetBrains' `StateAwareTerminalSession` keeps a headless output model and sends a snapshot as the **first event of every output subscription** ("emulation continues even if the client has disconnected", `.../session/StateAwareTerminalSession.kt:68,235-244`); Mosh syncs numbered screen **states**, not bytes.
- **VS Code** feeds every byte into a second, headless emulator inside the pty host (`@xterm/headless` + `@xterm/addon-serialize`, default `persistentSessionScrollback` 100 lines) and replays **one `{cols, rows, data}` event** into a same-size xterm that is then resized (`platform/terminal/node/ptyService.ts:34-40,829-833,1045-1125`; `workbench/contrib/terminal/common/basePty.ts:90-116`). The replay type has **no seq or offset**; ids restart per host, which produced "Reattached to the wrong terminal" (vscode#133542). After a reload shells keep running; after a quit the next start creates NEW shells under the old screen text ("History restored"), persisted as `{shellLaunchConfig, processDetails, replayEvent}` with a 2 s shutdown race (`terminalService.ts:630-672`).
- **Wave** keeps a 2 MiB circular byte store plus UI-side `SerializeAddon` snapshots every 5 s of idle (>=100 KiB new), restores snapshot then fetches the log from `ptyoffset`; live events carry no offset (`waveterm/frontend/app/view/term/termwrap.ts:511-543,580-600`). Its durable SSH sessions use a detached `wsh jobmanager` with byte `seq` (and the stall bug of #3439).
- **Tabby** saves `{profile, live cwd, serialized screen (excludeAltBuffer, excludeModes, 1000 lines), title, icon, colour}` and, on a window reload, re-attaches the live pty by id (`tabby-terminal/src/frontends/xtermFrontend.ts:802-812`).
- **Warp** persists **records, not bytes**: the last 100 blocks per session, 5,000 styled lines each, replayed above a fresh shell (`warp/app/src/persistence/block_list.rs:19,248-330`). **Zed** persists only `{cwd, title, layout}` and starts a new shell (`terminal_view/src/persistence.rs:344-376`). **Zellij** resurrection saves a layout every 60 s with cwd and the foreground command written suspended, and **never auto-runs** it (`zellij-server/src/background_jobs.rs:184,401-411`).
- **iTerm2 `tmux -CC`** is the pure-view model: tmux owns scrollback; on attach iTerm2 `capture-pane`s history, and replays a **whitelist** of GUI-only state (`SetUserVar`, `RemoteHost`, `CurrentDir`, `ShellIntegrationVersion`) that was in output it had discarded (`iTerm2/sources/tmux/TmuxDroppedOutputScanner.swift:7-24`). Ghostty has an unfinished binary snapshot with a **CONTINUATION** record: the minimum bytes to rebuild a half-parsed escape sequence (`ghostty/src/terminal/snapshot/continuation.zig:1-8`).

**Here.** #658's ring is `GetAll()` of the last 1,000,000 bytes with **no offset, no size, no modes** (`manager.go:605-616`); T1.md measured "about 370 lines differed" at the join. *Go local backend* must own the join. *UI* must treat reattach as "new emulator, replay, then live from offset N". *SDK lane*: `StreamOutput.seq` already exists and the host drops it (section 1.3).

**Simplest correct version (three steps, no Go emulator yet; the byte offset and the mode prologue are my recommendation, with Ghostty's CONTINUATION record and iTerm2's whitelist replay as the nearest precedents).**
1. Number the stream: a per-session monotonic **byte offset**; every output event carries `offset`; the ring is addressed by offset; `Attach(id)` returns `{start_offset, end_offset, bytes, cols, rows}` **atomically with respect to the event order** (take the same lock that orders events).
2. Track terminal **modes** in Go with a small byte scanner (alt screen `?1049/?47/?1047`, bracketed paste `?2004`, mouse `?1000/?1002/?1003/?1006`, app cursor `?1`, kitty keyboard stack depth, DECSET 2026) and return them with the snapshot; the UI writes a synthesized prologue (and `ESC c` first) before the ring tail. This is what the ring alone cannot recover when the enter-alt-screen scrolled out of the 1 MB window.
3. UI replay rules (Wave, VS Code): mute `onData` while replaying (xterm answers DA1/DSR queries found in old output and would type those answers into the live shell), never count replay in flow-control acks, apply the saved size first then resize, bounce `SIGWINCH` so TUIs redraw, and key the attach by `{session_id, pid/uuid}` (vscode#133542). Persist **definitions** (shell, cwd, title, colour, icon, layout) for an app restart and start a new shell (Zed, JetBrains, Tabby, Warp all do).
The heavy alternative is a Go VT emulator or libghostty-vt in the backend (JetBrains now runs `libghostty-vt` in its default engine: `plugins/terminal/resources/META-INF/terminal.xml:44-45`); take it only if "restore the screen after an app crash" becomes a requirement.

**Pitfalls.** VS Code serialises without flushing the write queue [INFERENCE: tail output can be missing from the snapshot]; Wave `heldData` is never replayed, so the join depends on subscribe-then-fetch order; wezterm#3539 (an SSH-mux domain silently detached after sleep, tabs vanished); zellij#5762 (a reconnect after laptop sleep judged a live session dead and resurrected it; two servers bound one socket); zellij#5073 (a resurrected command runs outside a shell, so when it exits the pane is dead); tmux#5693 (no persistence across server death, still open).

### 3. Flow control end to end (pty → backend → transport → renderer)

**Problem.** A program can write faster than the chain can parse (the page parses xterm.js at 5-35 MB/s, `xterm.js` docs). Without back-pressure, memory grows in the weakest hop, Ctrl-C arrives behind megabytes of output, and a hidden terminal either stalls the program or loses data.

**What the best do.**
- **VS Code** (the reference): the pty host pauses the pty at `HighWatermarkChars = 100000` unacknowledged and resumes below `LowWatermarkChars = 5000`; the renderer acks `CharCountAckSize = 5000` at a time, coalesced, **from the `xterm.write(data, callback)` callback (parse done, not paint done)**, in the producer's unit (JS string length on both sides). Replay never counts (acks are dropped while `_inReplay`). A hidden terminal still writes, parses and acks; the UI never holds or drops (`vscode/src/vs/platform/terminal/common/terminal.ts:915-936`; `.../terminal/browser/terminalInstance.ts:1687-1727`; `terminalProcessManager.ts:891-906`; `.../node/terminalProcess.ts:333-340,611-625`; `electron-browser/localPty.ts:89-92`). Extension-owned pseudo-terminals have **no** flow control and can reach xterm's 50 MB discard cap (`terminalProcessExtHostProxy.ts:135-137`; vscode#158211, #147406): this is the exec-lane gap.
- **xterm.js' own guide**: ack from the `write` callback; example `HIGH=100000`/`LOW=10000`; "HIGH should not be greater than 500K" so Ctrl-C stays responsive; test with `yes`. `write()` throws (it does not silently drop) when more than `DISCARD_WATERMARK = 50000000` is pending; slices are 12 ms (`WRITE_TIMEOUT_MS`), yielding only between chunks, so one 4 MiB `write` is one long task (`xterm.js-6.0.0/src/common/input/WriteBuffer.ts:20,28,35,104-105,226`; https://xtermjs.org/docs/guides/flowcontrol/). A hidden terminal's *renderer* is paused by an `IntersectionObserver`, but parsing and callbacks continue (`RenderService.ts:127-152`).
- **Tabby**: pty host pauses node-pty above 500 KiB unacked in 100 KiB chunks, but the renderer acks **on receipt**, before xterm parses, so a slow xterm never throttles the pty (and can grow xterm's queue toward the 50 MB throw) (`tabby/app/lib/pty.ts:8-88`; `tabby-local/src/session.ts:151-154`).
- **Wave**: local path has none (read loop never waits, unbounded per-link backlog in its router: `shellcontroller.go:552-568`; `wshrouter.go:316-348`). Its durable remote path is a real window protocol (2 MiB ring, 64 KiB window, 4 KiB packets addressed by byte `seq`, ack on receipt and on consume: `pkg/jobmanager/streammanager.go:16-21`) and shows how it breaks: a send blocked more than 5 s is dropped, nothing retransmits, the window fills and the stream freezes **while the UI still says Attached** (waveterm#3439, root cause traced at this commit).
- **JetBrains**: no byte marks at all: one batch in flight, the emulator thread sleeps 1 ms while the previous batch is unconsumed, state diffs coalesced every 20 ms but flushed at once on alt-screen/mode/bell/shell events, and a consumer that takes more than 3 s to accept a batch is cut loose and re-subscribes to a **snapshot** instead of buffering (`.../session/jediterm/TerminalSessionOutput.kt:42,108-114,127-133`; `TerminalSession.kt:43-45`).
- **tmux control mode**: write buffer low/high `512`/`8192`; `refresh-client -f pause-after=<s>` emits `%pause` and drops what was queued; a client that is `CONTROL_MAXIMUM_AGE 300000` ms behind and not in pause mode is dropped; replies capped at 64 MiB after tmux#5553 (`tmux/control.c:126-137,583-615`). Resume is "from now" and the client resyncs with `capture-pane`.
- **Ghostty/kitty/Alacritty/WezTerm/Warp** are single-process: a bounded ring or 1 MiB buffer, a parse lock released every 65,535 bytes (`MAX_LOCKED_READ`), no acks, and DECSET 2026 synchronized output forced to flush after 150 ms (Alacritty/Warp/Zed, with a 2 MiB cap) or 1 s (Ghostty) so a stuck `?2026h` cannot freeze the UI (`alacritty_terminal/src/event_loop.rs:24-27,160-168`; `ghostty/src/termio/Thread.zig:38`; `warp/.../ansi/mod.rs:62,69`).
- **iTerm2's remote framer** shows the exec-lane shape: credit-based (`FLOW_INITIAL_CREDIT 8192`, `FLOW_READ_SIZE 4096`, `FLOW_DRAIN_TIMEOUT 10.0 s`, a "valve" that trickles `4096 B/s` after `5 s` of controller silence), so a backlog waits in the remote pty where Ctrl-C can discard it (`iTerm2/OtherResources/framer.py:155-181`).

**Here.**
- *Go local backend* (#658 `flow.go:11-67`, marks `types.go:253-254`): the mechanism is right (stop reading at 1 MiB, resume at 256 KiB, bounded by one 20,480-byte read). Missing: (a) a **stall timer** (Wave #3439: when nothing is acked for N seconds, resync from the ring by offset rather than wait; JetBrains' 3 s); (b) the marks are 2-10x VS Code's and above xterm's 500K Ctrl-C advice, so measure Ctrl-C under `yes` before shipping; (c) a place for the pending count that survives `AckTerminal` arriving before the bytes it acks (it handles this by counting before delivery: `flow.go:22-28`).
- *UI* (#660 `screen.ts:25,185-225`, `execFeed.ts:47`, `heldOutput.ts:29-59`): the hold-while-hidden design is **incompatible** with `launch.flow` (see pitfall 2). Choose one of two consistent designs: **(A) VS Code's**: keep writing hidden output into xterm (renderer paused by xterm; no DOM writes) and ack from the callback; or **(B) tmux/JetBrains'**: pause the shell while hidden and, on show, resync from a backend snapshot. Never "hold bytes, ack on receipt, drop oldest": it breaks the byte stream.
- *Transport*: Wails events carry base64 JSON through `evaluateJavaScript`; GoStream (section 1.4) gives bounded, ordered binary frames and a blocking `Send` that is itself back-pressure, so the ack protocol only has to cover the page's parse queue.
- *SDK exec lane*: no ack path exists; add `seq` + ack (or credit) to the stream, and let the host's flow control throttle the plugin reader so the remote stream (SPDY/WebSocket window) pushes back on the pod.

**Simplest correct version.** (1) UI acks `n` bytes from the `write(data, cb)` callback, batched to 64 KiB or one per frame, and never counts replay. (2) Hidden terminals keep parsing (design A) and the 4 MiB hold goes away, or is only a cap that triggers "reset + resync from ring" (never "drop oldest chunks"). (3) Go adds the 3 s stall resync. (4) Put a hard 1-2 s timeout on DECSET 2026 in the UI. (5) Control-plane calls (input, resize, close, ack) never queue behind output.

**Pitfalls (cited).** Wave #3439/#2985 (stall while "Attached"); zellij#5546 (a client dropped for being 5,000 messages behind is not removed synchronously, its id is reused and the new attach is evicted); tmux#5553 (replies bypassed flow control: server RSS grew); Zed #66503 (cost is per output burst, even minimised); xterm.js #6208 (a hidden `display:none` DOM terminal still re-renders on scroll/blur/focus; 15 hidden terminals stall 3-5 s) and the timer clamping of occluded WebKit windows [INFERENCE] slow parsing while the queue grows toward the 50 MB throw; JetBrains YT-IJPL-198503 (Ctrl+S = XOFF freezes the view).

### 4. Resize (debounce, reflow, in-flight output, alt screen)

**Problem.** The pty (what the program believes) and the emulator (what is drawn) must agree on rows x columns; every resize is a `SIGWINCH` that makes shells redraw prompts the emulator may already have reflowed; output in flight was produced for the old size; and the very first size decides how the first prompt is laid out.

**What the best do.**
- **Initial size before the child exists.** VS Code reads the container's computed size before spawning (`_initDimensions`), waits at most 100 ms (`WaitForContainerThreshold`) and falls back to 80x30 (`workbench/contrib/terminal/browser/terminalInstance.ts:97-108,715-731,1646-1652`). Wave does not spawn on mount: the first `fit` calls `resyncController("initial resize")` with the measured size (`waveterm/frontend/app/view/term/termwrap.ts:559-578`). kitty holds the child in `wait_for_terminal_ready` until the window has a real size (`kitty/kitty/child.c:229`). Zed spawns at a dummy 100x6 (`terminal.rs:642-645`); pty4j sets the size after spawn (above). The remote exec lane has no size at all (section 1.3).
- **Order and debounce.** VS Code resizes xterm first, then the pty (with pixel size); rows apply at once, **columns** are trailing-debounced 100 ms because reflow is the expensive half, and only when the normal buffer holds at least 200 lines (`terminalResizeDebouncer.ts:11-100`; `terminalInstance.ts:840-864,2138-2147`). tmux queues the pty resize on a 250 ms timer; if several resizes end at the original size it sends the first and keeps the last so the app receives at least two `SIGWINCH` (`tmux/server-client.c:2053-2112`). Zellij sends only the last size per pane ("many programs and shells debounce those... glitches and missing redraws", `zellij-server/src/pty_writer.rs:123-136`). kitty sends `SIGWINCH` only on a real change and pauses during interactive drags, then once (`kitty/window.py:1133-1141,1202-1206`). Ghostty coalesces resize messages 25 ms (`ghostty/src/termio/Thread.zig:31`). JetBrains resizes the model at once and **postpones** the pty resize 100 ms in the alt screen and 500 ms on the main screen because ConPTY repaints on resize and the repaint must land on a buffer of the old size (`jediterm/core/.../TerminalStarter.java:125-174`). Warp has no debounce.
- **Prompt redraw after reflow** is the visible bug: the shell redraws the prompt assuming the old row count while the emulator reflowed it, duplicating prompts. Ghostty finds the prompt start before reflow and **blanks the prompt rows** so the shell redraws them (`redraw=true|last|0` carried on OSC 133;A: `ghostty/src/terminal/Screen.zig:2087-2408`); JetBrains fixed YT-IJPL-254160 (diagonal resize duplicates the prompt in zsh/bash/fish, fixed 2026-11-16) with the same `redraw=1|0` marks; kitty blanks all lines below the prompt start at each 133;A. xterm.js does not reflow the cursor line by default (`reflowCursorLine` false, "shells usually handle this"), never reflows the alt buffer, and pulls lines back from scrollback on row growth (`xterm.js-6.0.0/src/common/buffer/Buffer.ts:181-218,296-379`).
- **Multiple clients on one session** need an arbiter: tmux `window-size latest`, Zellij takes the per-tab minimum, WezTerm applies "last writer wins" and thrashes (wezterm#8358: 2,792 `Resize` PDUs in 90 s).

**Here.** *UI* (#660): first size is sent only after `CreateTerminal` returns (`execFeed.ts:229-235`), because the engine measures after the lazy chunk loads; later sizes settle 100 ms with xterm resized immediately (`execFeed.ts:289-310`, `screen.ts:239-258`). #658 can now take `launch.cols/rows` but `localShell.ts:47` passes none, so the first prompt is laid out for 80x24 and then reflowed. *Go*: ordered `TIOCSWINSZ` is done (`pty.go:62-66`); clamp, "resize after exit is a no-op" and de-dup are cheap. *SDK*: add `size` to the open request and a resize that returns when applied.

**Simplest correct version.** (1) Measure, then create: render the empty xterm host (or compute from font metrics) before calling `CreateTerminal`, and pass `launch.cols/rows`. (2) Keep rows immediate and settle only columns; send the pty resize **after** `terminal.resize`; ignore zero sizes (a hidden panel must never reach the pty) and never resize on an alt-screen toggle (Warp #15867: `?1049h` emitted a `SIGWINCH` and a height off by the chrome rows). (3) Treat prompt duplication as a known cost of reflow until OSC 133 `redraw` marks exist (mechanism 6), then clear from the prompt start like Ghostty. (4) Test a diagonal drag in zsh, bash and fish, and `less`/`vim` in the alt screen.

**Pitfalls.** xterm.js 6.0.0 `resize()` does **not** flush queued writes, so bytes queued before a resize parse at the **new** size (`CoreTerminal.ts:170-179`; fixed on master #5599); open crashes #6063 (rows grown with scrollback leave rows without a line) and #6331 (narrowing with scrollback 0 on the last row loses later output, seen first in WKWebView); `MINIMUM_COLS 2` exists because one column plus a wide character panics emulators (zed#2750, alacritty#9112); ConPTY floods newlines after resize (YT-IJPL-236749); tmux#5683 (a resize queued, alt screen entered before the timer, pty left at the old size); the fit addon `parseInt`s fractional pixels and reserves 14 px for the scrollbar (off-by-one at fractional DPR: `addon-fit/src/FitAddon.ts:23-89`).

### 5. Environment, login-shell resolution, default shell, profiles

**Problem.** A GUI app started from the Dock gets launchd's minimal environment. The terminal must hand a shell the environment a Terminal.app window would give, **exactly once**: not minimal, and not computed twice.

**What the best do.**
- **VS Code** resolves the user's environment once per process by running `$SHELL -i -l -c '<node> -p "<marker>"+JSON.stringify(process.env)+"<marker>"'` (detached, stdin ignored, 10 s timeout clamped 1-120 s, cached, skipped when launched from the `code` CLI so it inherits the real env) (`vscode/src/vs/platform/shell/node/shellEnv.ts:32-221`; setting `application.shellEnvironmentResolutionTimeout`). Failure modes it documents: `NODE_OPTIONS` in the rc makes the probe exit 9 (vscode#140591), slow rc files trip the timeout (vscode#112753), a stale `$SHELL` after `chsh` (vscode#156442), env captured once so new tools need a restart (vscode#47816). Terminal env = shell env -> strip `ELECTRON_*`/`VSCODE_*`/`SNAP*` -> `terminal.integrated.env.<os>` -> profile env -> `TERM_PROGRAM=vscode`, `TERM_PROGRAM_VERSION`, `COLORTERM=truecolor`, `LANG` only if missing or not UTF-8 (`terminalEnvironment.ts:62-71,99-184,244-305`). **macOS profiles pass `-l`, Linux profiles do not** (`terminalPlatformConfiguration.ts:228-249,287-313`). Default shell: profile, else `$SHELL`, else `os.userInfo().shell`; login shells come from `/etc/shells` plus the passwd shell because `$SHELL` "can be stale ... from the macOS Dock after chsh" (`platform/terminal/node/terminalProfiles.ts:247-249`). VS Code knows the `path_helper` problem too: the PATH prefixes **that extensions contributed** are re-applied after the profile runs (`VSCODE_PATH_PREFIX`), because "on macOS when the profile calls path_helper" and in fish (`$fish_user_paths`) directories end up in front of or behind where they were put; its own comment admits "this will cause duplication in the PATH but should fix the issue" (`platform/terminal/node/terminalEnvironment.ts:279-314`; `shellIntegration-bash.sh:52-56`; vscode#99878).
- **JetBrains** starts shells on the **raw process environment**, explicitly "non-interactive and non-login ... loading the same configuration file twice might break things", and passes `--login` only on local macOS (and remote POSIX) (`plugins/terminal/src/.../terminalStartup.kt:193-200`; `LocalTerminalStartCommandBuilder.java:60-94`). The login-restored map is used only for non-shell commands. YT-IJPL-200767 (fixed 2025-08): the IDE pre-populated PATH from a login shell **and** started `zsh --login`; `path_helper` reordered it and mise/asdf shims lost precedence.
- **Zed / Ghostty / kitty** on macOS run `/usr/bin/login -flp <user> <shell>` (so `$SHELL`/`getlogin()` are right and the "Last login" line is suppressed via `-q` when `~/.hushlogin` exists) and then re-enter the shell with `argv[0]` set to `-zsh` (Zed's `alacritty_terminal` fork `tty/unix.rs:166-192`; `ghostty/src/termio/Exec.zig:1888-1963`; `kitty/kitty/child.py:496,650-666`). Linux terminals are non-login (Ghostty #1074).
- **Wave** emulates login for bash with `--rcfile`, zsh/sh `-l -i`, and reads the macOS shell with `dscl . -read` on the user's record, key `UserShell` (2 s timeout) (`waveterm/pkg/shellexec/shellexec.go:599-618`; `shellutil.go:87-137`). **Tabby**: `dscl` + `--login` on macOS.
- **Profiles**: VS Code `{path|source, args, env, icon, color, overrideName}` per OS plus a separate automation profile and an **agent profile** (`terminalPlatformConfiguration.ts:135-211,395-400`); JetBrains detects `bash zsh fish pwsh` in `/bin /usr/bin /usr/local/bin /opt/homebrew/bin` (`TerminalShellsDetectionUtil.kt:79-86`); Zed has none (only a `shell` and `env` override).
- **TERM**: everyone sends `xterm-256color` + `COLORTERM=truecolor`; Ghostty's own `xterm-ghostty` needs terminfo on every remote (Ghostty #3335 doubled letters over SSH; fallback to `xterm-256color` when the install fails); Alacritty's own terminfo made Vim mis-handle bracketed paste (alacritty#7678).

**Here.** *Go local backend*: #658 composes **both** halves JetBrains and VS Code had to un-do: the host env is already login-restored (`shellenv/environment.go:19-35`) and the shell is started `-i -l` (`shellenv/shell.go:97-98`, `manager.go:321-331`). See pitfall 1. Also `OMNIVIEW_*` and `GOWORK` leak in (stated open), `PWD` is not set (Ghostty sets it so a symlinked cwd shows unresolved), and `VTE_VERSION`, `TMUX`, `STY`, `COLUMNS`, `LINES` are not stripped. *SDK lane*: a pod exec has no env option in the Kubernetes API; `TERM` must be passed by wrapping the command (`env TERM=xterm-256color ...`) and `LANG`/`TERM_PROGRAM` are best effort; SSH `SendEnv` is commonly refused (RFC 4254 section 6.4).

**Simplest correct version.** Pick **one** of two consistent contracts and test it against the user's real rc files: (A) *JetBrains*: keep the **pre-restore** environment (a copy of `os.Environ()` taken before `shellenv.Restore`, minus host-private keys) and start `-i -l` as Terminal.app does; or (B) *VS Code on Linux*: use the restored environment and start `-i` **without** `-l`, then re-apply PATH prefixes after the profile. Add `IUTF8`, `PWD`, `LANG` only if empty (done), a visible "resolving environment" state after ~1.5 s, and a manual refresh. Surface the login-shell probe's failure (never swallow it) because every later symptom looks like "my tools are missing".

**Pitfalls.** The one above (IJPL-200767), reproduced **here** on macOS: `env -i PATH=$HOME/.local/share/mise/shims:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin /usr/libexec/path_helper -s` prints `PATH="/usr/local/bin:/System/Cryptexes/App/usr/bin:/usr/bin:/bin:/usr/sbin:/sbin:...:<home>/.local/share/mise/shims:/opt/homebrew/bin"`: the user's directories moved **behind** the system ones, and a version manager's "prepend unless already present" snippet then declines to prepend. Zed #21951 (`TERM_PROGRAM` missing when launched from the Dock: the env-capture shell is not a terminal and an `exec tmux` in the rc hijacked it); Zed #45798 (fish exit 127/EBADF on non-tty stdin); Wave #3336 (an empty `XDG_*_HOME` written into every shell); Wave #3481 (POSIX-only env-name validation silently aborted the pwsh integration).

### 6. Shell integration: OSC 7, OSC 133/633, injection, opt-out, and what it unlocks

**Problem.** A terminal sees bytes; only the **shell** knows where the prompt ends, what command was typed, when it finished, with what status and in which directory. Shell integration moves those facts in-band (a few escape sequences printed by hooks in the shell) so the terminal can draw command marks, jump between commands, copy the last output, know "a command is running", resolve relative paths, notify when something long finishes, and give an agent a typed record instead of a screenshot of text.

**What the protocols look like (the superset a host can accept).** OSC 133 (FinalTerm "semantic prompts": `A` prompt start, `B` input start, `C` output start, `D;<exit>` end; options `aid=`, `cl=`, `k=i|s|r|c`, `redraw=`, `click_events`: https://gitlab.freedesktop.org/Per_Bothner/specifications/-/blob/master/proposals/semantic-prompts.md); OSC 7 (`file://host/%-encoded-path`); VS Code's OSC 633 (`A B C D[;code] E;<cmdline>[;nonce] F G H I P;Key=Value SetMark`, `P` keys `Cwd`, `IsWindows`, `HasRichCommandDetection`, `ContinuationPrompt`, `Prompt`, `PromptType`, `Task`; `vscode/src/vs/platform/terminal/common/xterm/shellIntegrationAddon.ts:103-304,473-640`, https://code.visualstudio.com/docs/terminal/shell-integration); iTerm2 OSC 1337 (`CurrentDir=`, `RemoteHost=`, `SetMark`, `SetUserVar=` base64); OSC 9;9 (ConEmu/Windows Terminal cwd); and private ones: JetBrains OSC 1341 with hex-encoded payloads (`command_started`, `command_finished;exit_code=N`, `prompt_started`, `prompt_finished`: `.../shell-integrations/bash/command-block-support-reworked.bash:30-100`), Wave OSC 16162, Warp's DCS `ESC P $ d <hex JSON> ESC \` hooks. **Support is thinner than the specs.** WezTerm parses the exit status and discards it (`wezterm/term/src/terminalstate/performer.rs:904-906`); Ghostty ignores `aid` and keeps no exit code in the grid; iTerm2 ignores `cl`, `redraw`, `click_events`; Ghostty accepts OSC 7 only from the local host, iTerm2 accepts remote hosts (`ghostty/src/termio/stream_handler.zig:1558-1591`). tmux master now parses 133 natively and exposes `pane-command-finished` hooks with status and duration (`tmux/input.c:3616-3693`).

**How the best inject it without breaking user config.**
- **VS Code** (MIT, the safest reference): zsh gets `ZDOTDIR=<tmp>` (owner-only sticky dir `0o1700`) holding copies of `.zshenv .zprofile .zshrc .zlogin`, each of which sources the user's real file with `ZDOTDIR` swapped back (`USER_ZDOTDIR`) and restores it for non-login shells (a missed restore broke zim/z4h and history: vscode#157128); bash uses `--init-file` and **emulates login itself** because `--init-file` cannot take `-l` (`shellIntegration-bash.sh:30-59`); fish `--init-command`; pwsh `-noexit -command`. Injection is skipped, with a typed reason, for a disabled setting, a missing executable, user-supplied args it does not recognise ("prefer launching one without SI than breaking their profile"), unsupported shells and Windows < 18309; a shell that dies within 500 ms is relaunched once without injection (`platform/terminal/node/terminalEnvironment.ts:46-340`; `terminal.ts:1072-1114`; `terminalInstance.ts:1742-1746`). `VSCODE_SHELL_INTEGRATION` is a non-exported shell variable so nested shells do not inherit it and a user rc can opt out.
- **Ghostty/kitty/iTerm2**: zsh `ZDOTDIR` shim; bash `--posix` + `ENV` (Ghostty skips Apple's bash 3.2 because it ignores `ENV`; iTerm2 refuses it too); fish prepends to `XDG_DATA_DIRS`; all skip `-c` and unknown shells; opt-outs `KITTY_SHELL_INTEGRATION=no-rc|no-cursor|no-title|no-cwd|no-prompt-mark|...`, `shell-integration = none` (`ghostty/src/termio/shell_integration.zig:137-167,298-411,921-951`; `kitty/kitty/shell_integration.py:277-334`; `kitty/docs/shell-integration.rst:55-103`).
- **Wave** (Apache-2.0): ZDOTDIR shims, `bash --rcfile` + bundled bash-preexec, `fish -C`, `pwsh -File`; per-block secrets delivered by a **single-use swap token** (5 min), not by env; it switches itself off inside tmux/screen and when bash `extdebug` is on, and reports `M;{"integration":false}` so the UI knows (`waveterm/pkg/util/shellutil/shellintegration/*`, `pkg/blockcontroller/blockcontroller.go:459-494`).
- **JetBrains**: bash `--rcfile`, **drops `--login`**, sets `LOGIN_SHELL=1` and replays `/etc/profile` -> `~/.bash_profile|.bash_login|.profile` inside its script; zsh `ZDOTDIR` proxy files; **zsh integration is skipped when `P9K_VERSION` is set** (`LocalShellIntegrationInjector.java:84-135,246-265`; `zsh/command-block-support-reworked.zsh:6-8`).
- **Warp** is the counter-example: it starts a minimal shell, then **types a bootstrap script into the user's pty** after an `InitShell` hook. That is its top source of bugs: #15653 (a `Precmd` arriving before `Bootstrapped` deadlocks all writes, silently), #7099 (bootstrap bytes echo with vi-mode widgets), #16630 (`^[i^P` leak into the input line) (`warp/crates/warp_terminal/src/local_tty/shell.rs:709-816`; `pty_controller.rs:325-422`).

**Trust.** Any program can print these sequences. VS Code copies `VSCODE_NONCE` into a **non-exported shell variable and unsets the env var** (`shellIntegration-bash.sh:218-220`), and trusts `633;E` only when the nonce matches. Since PR #316474 the parser also treats a `P;Cwd` without a matching nonce as untrusted "to mitigate spoofing via OSC sequences injected through arbitrary terminal output" (`shellIntegrationAddon.ts:583-590`), **but the bundled scripts print `633;P;Cwd=%s` with no nonce** (`shellIntegration-bash.sh:267`, `shellIntegration-rc.zsh:174`, `shellIntegration.ps1:132`), so VS Code's own cwd stays "untrusted": copy the check, then actually send the nonce. Unverified 133/7 may drive gutter marks and navigation only. Warp shipped hook spoofing as a CVE (GHSA-9w2v-jhww-vm85 / CVE-2026-54686: hooks from the pty stream were accepted unauthenticated until a per-session `session_id` was required) and a related cwd-injection (GHSA-qqpc-wvvw-4269: a remote-reported cwd was interpolated into a helper command). Ghostty strips control bytes from cwd/host/command because a directory named with a raw ESC could end an OSC 7 and inject an OSC 52 (`ghostty/.../ghostty.bash:196-201`). iTerm2 #13117: a tokenless third-party OSC 7 (oh-my-zsh's `omz_termsupport_cwd`) turned local tabs "remote".

**What it unlocks, with the marks each needs.** Command gutter (success/error/incomplete), hover "took N s, exit N", rerun, copy command/output/as HTML (VS Code `decorationAddon.ts:430-525`; needs A B C D). Jump to previous/next command and "select command output" (VS Code Cmd/Ctrl+Up/Down, Ghostty `jump_to_prompt`, iTerm2 Cmd-Shift-Up, Windows Terminal `scrollToMark`). Sticky command header (VS Code, needs **rich** detection, caps 40% of rows, off in alt screen and for `clear`, `claude`, `codex`, `gemini`). Run Recent Command / Go to Recent Directory (history + per-session commands). "Command running" for close confirmation (JetBrains asks iff `ExecutingCommand` from integration, else scans children; Ghostty asks iff "not at a prompt"). Cwd for new terminals/splits and for link resolution. Click-to-move-cursor (Ghostty `cl=`/`click_events`). Long-command-finished notification: **VS Code has none** (only screen-reader signals); Ghostty `notify-on-command-finish=never` default, kitty `notify_on_cmd_finish=never`. Agent context (mechanism 15).

**Here.**
- *Go local backend*: owns injection (it already owns argv and env) and the nonce. It does not need to parse output for the UI features, but it should **tee-parse** for the persisted per-session record and for agents, as VS Code's agent host does (`platform/agentHost/node/osc633Parser.ts:152-347`: strips 633 from the stream, chunk-split safe, keeps `{commandId, commandLine (only if the nonce matches), output, exitCode, durationMs, cwd}` capped at 100,000 chars trimmed to 80,000).
- *UI (xterm.js)*: `terminal.parser.registerOscHandler(133|633|7, ...)`; create the marker **inside the handler** (a marker created after `write()` reads line 0: xterm.js #5214); markers die on `clear()` (and Cmd+K clears them) and when scrolled out of scrollback; decorations are a proposed API (`allowProposedApi`, which #660 already sets) with one DOM node each, hidden in the alt buffer; do not take durations from UI `Date.now()` (hidden-panel holds delay parsing: use timestamps from the producer).
- *SDK exec lane*: **no injection path into a pod shell** (no args or env control, the user's image may not even have bash). Options in increasing cost: Partial detection (an Enter-marker, VS Code's `PartialCommandDetection`) + naive cwd; a user-run "enable integration" snippet; an stdin-bootstrapped script with a version handshake (iTerm2 `ShellIntegrationVersion`, scripts older than the app prompt an upgrade); a helper binary in the pod (iTerm2 conductor, Wave `wsh`, Warp's SSH wrapper) with explicit consent. Show the quality tier None/Basic/Rich like VS Code.

**Simplest correct version.**
1. Pick the contract: emit **OSC 133 A/B/C/D;exit, OSC 7, and 633 `E;<escaped cmdline>;<nonce>` + `P;Cwd=<path>;<nonce>`** from clean-room scripts (the licence note in section 2 matters: Ghostty's bash/zsh scripts and iTerm2's are copyleft; VS Code's and Wave's are permissive). Parse 133/7/633 in the UI with two trust tiers; accept foreign 133/7 at low trust.
2. Fix the shell start contract first (pitfall 1): `shellenv.Resolve` hard-codes `-i -l`; with `-l` bash **ignores `--rcfile`** (run here: `bash --rcfile rc -i -l -c ...` ran the profile and never the rcfile, bash 5.3.0 on macOS), so use VS Code's or JetBrains' approach (own the login emulation in the script) or Ghostty's `ENV` + `--posix`.
3. Inject by env/args only; never type scripts into the user's tty; skip on `-c`, `--posix`, unknown args, macOS system bash 3.2 and a detected `P9K_VERSION`; add an opt-out env var and a setting; relaunch without integration if the shell dies within 500 ms; report `integration: on|off|failed` to the UI (Wave).
4. The UI state machine must tolerate: `D` without `C` (Ctrl-C at an empty prompt), repeated `A`, `C` without `B`, foreign 133 from p10k/starship/fish-native, `D` with no code (pwsh reports only 0/1).
5. Ship the cheap unlocks first: jump, copy last output, exit gutter, "busy" for close, cwd for new terminal and links.

**Pitfalls (cited).** p10k: vscode#146587 (p10k disables integration itself, command text cannot be derived from cells: VS Code added 133 and kept `E`), powerlevel10k#2954/#2959 (133 `k=r/k=s` marks cause input-line flicker with widgets that `zle reset-prompt`), JetBrains YT-IJPL-178955 (p10k gets no integration), starship#5463 (no semantic-prompt support), #4642 (DEBUG-trap clash). bash: vscode#150241/#201184 (bash-preexec/DEBUG coexistence, `[[ =~ ]]` clobbering `BASH_REMATCH`), #221393 (user `PROMPT_COMMAND` saw `$?`=0), #156385/#143766 (`$BASH_COMMAND` has aliases resolved, so VS Code reads `history 1`, which breaks under `HISTCONTROL=ignoredups`), Ghostty #14247 (133;D always 0 on bash >=4.4), #11259 (`PROMPT_COMMAND` ending in `;`), #10953 (vi-mode redraw printed on the previous line: put 133;P in PS1), #1961 (multi-line PS1 vanished on resize). Cost: wezterm#8278 (the prompt hook forked `id`, `hostname` and 4x `base64`: 68.5 ms per prompt), #7980 (unquoted base64 word-splitting). fish: vscode#245607/#319058 (order-dependent clobber with starship; `printf` resets `$status`), Ghostty #10544. Multiplexers: vscode#233074 (tmux drops unknown OSC; needs DCS passthrough + `allow-passthrough`), wezterm#7168 (133 jumps fail inside tmux), vscode#268528 (`ssh` inside an integrated shell is one endless command). Pods: nothing injects; do not promise marks.

### 7. Links: URLs, `file:line[:col]` with cwd resolution, open in the IDE

**Problem.** Compiler and test output is full of paths; clicking one should open the file at the line, resolved against the directory the command ran in, without freezing the terminal on a pathological line.

**What the best do.**
- **VS Code** computes links lazily per hovered line through xterm `ILinkProvider`s (priority: extension, multi-line, local file/folder, URI, word), joining wrapped rows with context capped at `max(maxLinkLength, cols)/cols` rows. Parsing is pure regex with 12 suffix shapes (`foo:339[:12[-789]]`, `foo 339`, `foo#339:12`, `foo, 339`, `"foo", line 339, col 12`, `foo(339,12)`, ...), path characters exclude `\` after catastrophic backtracking on a unicode `cat` (vscode#24795), git-diff prefixes `a/ b/ 1/ 2/` are stripped; **relative paths resolve against the cwd of the command that produced that row** (`getCwdForLine`) else the terminal's initial cwd; every candidate is `stat`ed sequentially with a 10 s per-terminal cache (reset on every write); click needs Cmd/Ctrl and opens at row/col (`terminalContrib/links/browser/{terminalLinkParsing.ts:44-135,212,270-417; terminalLocalLinkDetector.ts:22-158; terminalLinkResolver.ts:49-195; terminalLinkOpeners.ts:51-69}`). Caps: line > 2,000 chars no file links, <= 10 resolved links per line, path > 1,024 not resolved, `maxLinkLength` 500 (uri 2,048, word 100); `enableFileLinks` = `on|off|notRemote` because each link is a stat (a remote stat is slow).
- **Zed**: path regexes in settings with a **1 ms** soft budget (`path_hyperlink_timeout_ms`), only under the modifier, async existence check, underline only if the file exists; resolution order cwd, worktrees by proximity, background `canonicalize`, suffix scan; the Rust `fancy_regex` default beachballed the UI on a long dotted line (zed#44510, fixed with a linear engine); its tests list 20 formats (Python tracebacks, cargo, Ruby `a.rb:20:in`, Elixir, grep `0:`, box-drawing prefixes, quoted names with spaces) (`zed/crates/terminal/src/terminal_hyperlinks.rs` tests; `terminal_view/src/terminal_path_like_target.rs:16-156`).
- **JetBrains** reuses the IDE console filter framework plus a character state machine, **no regex**, a link exists only if the file exists, positions `path:line[:col]`, `path:a-b`, `path: (line, col)`, numbers under 7 digits, `/dev /proc /sys` ignored; lookups only for the hovered line (`terminal.hyperlinks.on.hover`); a URL's every `/` once started a path probe and a UNC probe could hang on SMB (YT-IJPL-258860) (`TerminalGenericFileFilter.kt:24-72`).
- **iTerm2** brute-forces candidates around the click against the working directory (`iTermPathFinder.m:70-166`); **Warp** resolves against the hovered *block's* pwd and skips remote blocks (`link_detection.rs:566-626`) and had an OS command injection when opening links from WSL (GHSA-xmw3-wj6r-48m4); **Wave** has URLs only and a `wsh view|edit <path>` helper; **Tabby** excludes `:` so no line/col; **WezTerm** ships no file rule.
- xterm.js gives `registerLinkProvider`, OSC 8 via `linkHandler` (default `confirm()` + `window.open`, which WKWebView may block; non-http schemes are ignored unless `allowNonHttpProtocols`), and `addon-web-links` (http/https only, 2,048-char window).

**Here.** *UI*: a lazy link provider with VS Code's caps and suffix set, a linear-time matcher, active only under the modifier. *Go local backend*: the **stat** and cwd belong here (one bounded RPC: `ResolveLink(session, row_cwd, text) -> {path, kind, line, col}` with cwd-first, then workspace roots, then suffix scan); `GetCwd` is per session, not per command, so per-command cwd needs the 633 `P;Cwd` / OSC 7 record from mechanism 6. *IDE*: a host action `openFile(path, line, col)` the terminal can call (JetBrains' lesson: "open" is a host action). *SDK lane*: a pod path is a container path; without a plugin file-stat/open API show URLs and absolute paths only, or offer copy-path / download (iTerm2 falls back to SCP; VS Code's `notRemote` setting exists for this reason).

**Simplest correct version.** URLs first (`addon-web-links` with a `handler`, never default `window.open`); then `path[:line[:col]]` with the 6 most common shapes, resolved against the last known cwd (OSC 7 or `GetCwd`), `stat` in Go on hover only, cache 10 s, never probe inside a URL, never shell out to open (Warp GHSA).

**Pitfalls.** The four above (backtracking, SMB hang, cwd-less resolution opening the wrong same-named file: zed#28407/#34027, trailing period `file:12.` vscode#200257, spaces in MSVC/Clang paths vscode#178584).

### 8. Search in scrollback

**Problem.** Find text in what scrolled by, fast, without blocking output.

**What the best do.** xterm.js `addon-search` 0.16 (`findNext/Previous` with `regex`, `wholeWord`, `caseSensitive`, `incremental`, theme `decorations`; matching per logical line with wrapped rows joined; invalid regex throws; `highlightLimit` default 1,000; re-runs 200 ms after `onWriteParsed`/`onResize` while decorations are on) (`xterm.js/addons/addon-search/src/SearchAddon.ts:30,57-77,223-237`; `SearchEngine.ts:254-313`). VS Code raises the limit to **20,000**, searches the whole active buffer (alt screen = alt buffer only), Enter = find **previous** (newest first), suppresses copy-on-select while searching, seeds from a one-line selection (`terminalFindWidget.ts:115-188`; `xtermTerminal.ts:700-705`). Zed's scan holds the fair emulator lock for the whole search and stalls the reader on a flooding terminal; its regex is the only mode (`terminal.rs:2948-2954`). Wave and Tabby both use the addon with the same toggles; neither searches the persisted log.

**Here.** *UI only*, plus one decision: if the Go ring or a persisted log is larger than xterm's scrollback (5,000 lines), say so or search it in Go. **Simplest correct version:** the addon, `allowProposedApi` (already set), `highlightLimit` 20,000, a try/catch for invalid regex, debounce typing, show "1000+" when capped, Cmd+F. **Pitfalls:** vscode#67468 (matches wrong after resize: stale line cache), #253544 (a wrapped match counted several times), xterm.js scrollback-only; Cmd+K `clear()` disposes markers and decorations.

### 9. Selection, copy, paste and paste safety

**Problem.** Text crosses the clipboard in both directions; paste is also an injection channel (a pasted `ESC[201~` ends bracketed mode and what follows runs), and a multi-line paste at a prompt runs every line.

**What the best do.**
- **Sanitise inside the bracket.** xterm.js 6.0.0 does **not**: an `ESC[201~` in pasted text ends the bracket early (`xterm.js-6.0.0/src/browser/Clipboard.ts:21-26`); master replaces ESC with U+241B when bracketed (xterm.js #5716, commit 898c0d91, 2026-02-17). iTerm2 strips C0 controls except TAB/LF/CR before bracketing (`iTermPasteHelper.m:136-142,338-343`); Zed strips ESC, Alacritty also ETX (`terminal.rs:2479-2481`); Warp strips ESC in its command path but **not** in its raw pty paste path (`pty_controller.rs:811-822` vs `view.rs:17466-17477`); Tabby does not strip (`baseTerminalTab.component.ts:545-595`).
- **Multi-line warning.** VS Code `enableMultiLinePasteWarning` = `auto` (default: skipped when bracketed mode is on; one trailing newline stripped as an anti-clipboard-hijack measure) | `always` | `never`; the dialog shows 3 lines x 30 chars with Paste / Paste as one line / Cancel (`terminalContrib/clipboard/browser/terminalClipboard.ts:13-110`). iTerm2 warns on any newline and "at shell prompt" is a **shell-integration state**; it also offers Paste Slowly (16 B / 125 ms) and "Wait for shell prompt before pasting each line" (which hangs inside psql: iTerm2 #5749). Tabby warns outside the alt screen (first 1,000 chars). Zed, Alacritty, Ghostty (`clipboard-paste-protection=true`), JetBrains and Wave have none or only for unsafe content (alacritty#8692 closed "terminal is the wrong place").
- **Large pastes.** macOS caps a canonical-mode line at `MAX_CANON`/`MAX_INPUT` 1,024 bytes: multi-line input over ~1 KiB corrupted for months in VS Code (vscode#296955, #38137/#283056); node-pty's non-blocking write fix landed in PR #831 (2025-12), VS Code's chunked-write PR was reverted, and the shipped mitigation is bracketed paste for agent commands (#304268).
- **Selection/copy.** Shift forces selection under mouse reporting (Option with `macOptionClickForcesSelection`); copy-on-select needs a 2 px click-vs-drag threshold (zed#58970); Cmd+C on a Mac, Ctrl+Shift+C elsewhere, Windows Ctrl+C copies only with a selection; wrapped rows join without a newline and rows are right-trimmed (`SelectionService.ts:203-260`).
- **OSC 52** (clipboard): xterm's clipboard addon and VS Code's wiring answer a `?` read with the system clipboard **without a prompt**; iTerm2 defaults it off; Warp shipped a CVE for it (GHSA-wgqj-4c26-7c4g, default now deny); Wave defaults to `always` with size caps.
- **Drops and images.** File drops are typed as shell-quoted paths with control characters stripped (VS Code `terminalEnvironment.ts:14-81`; Tabby `pathDrop.ts:23-73`); a drop bypasses bracketed paste (vscode#347647). Zed/Warp send a raw Ctrl+V for a clipboard image so TUI agents read the OS clipboard; JetBrains saves a `pasted-image-*.png` in the **shell's** environment and pastes the path.

**Here.** *UI*: ONE paste path (Tabby #11706: a hotkey paste raced xterm's native `paste` event and pasted twice); sanitise ESC (and ETX) before `terminal.paste()` on 6.0.0; strip one trailing newline; warn on multi-line only when bracketed mode is off or the shell is not at a prompt (needs the 133 state); subscribe `onBinary` (#660 subscribes `onData` only, `ui-next/shell/panel/terminal/xtermEngine.ts:131-136`, and `grep onBinary` over the tool is empty, so legacy X10 mouse reports are dropped); quote drops per shell. *Go*: macOS writes over ~1 KiB need bracketed paste or paced chunks; make `INPUT_BACKLOG` a retry (pitfall 3). *SDK lane*: the SDK's local pty has the same 1 KiB limit; bridge a paste as one bracketed unit. **Simplest correct version:** sanitise + bracket + auto multi-line guard + OSC 52 write-only (size-capped, opt-in) + no clipboard-addon read.

**Pitfalls.** xterm.js #6322 (kitty keyboard mode swallows Shift+Insert paste), #6181 (trackpad: one wheel report per ~50 px), Tabby #11706 (double paste), vscode#141879 (`1~`/`[201~` leaked into Git Bash: a shell that enables bracketed paste but mishandles it; VS Code added `ignoreBracketedPasteMode`).

### 10. Keyboard: Option-as-Meta, kitty protocol, IDE chords vs shell chords

**Problem.** Every chord belongs to either the shell/TUI (Ctrl+R, Ctrl+W, Alt+B, Esc, Shift+Enter in an agent CLI) or the IDE (Cmd+P, Cmd+K, Cmd+W). A terminal inside an IDE must decide per key, in a webview where the menu accelerators may run before the DOM, and must encode keys the way programs expect.

**What the best do.**
- **Arbitration.** VS Code: xterm's custom handler runs first; a pending or valid keybinding chord is swallowed (so Cmd+K chords break); a resolved keybinding goes to the workbench if its command is in the skip set **or `metaKey` is down**, unless `sendKeybindingsToShell`; `commandsToSkipShell` has ~100 default ids (copy, paste, kill, new, focus*, resizePane*, runSelectedText, ...) and `-id` removes one; `allowChords` and `allowMnemonics` toggles (`workbench/contrib/terminal/browser/terminalInstance.ts:1169-1228`; `common/terminal.ts:508-671`). JetBrains: "Override IDE shortcuts" default **true**: every key goes to the shell **except** an allow-list of ~85 action ids, and a `SendShortcutToTerminalAction` forces a chord back to the shell when all allowed actions are disabled in context (`TerminalEventDispatcher.kt:82-286`; `TerminalAllowedActionsProvider.kt:6-26`). Ghostty: keybind first, then encode, with flags `consumed` (default), `unconsumed:`, `performable:` (copy only consumes with a selection, so Ctrl+C stays SIGINT), `global:`, key tables and a `keyEventIsBinding` query the macOS host asks **before** its menu equivalents (`ghostty/src/Surface.zig:2740-2982`; `SurfaceView_AppKit.swift:1297-1447`). kitty: `kitty_mod` chords, a `map kitty_mod+x` with no action passes the key through, and a running program can unmap chords via `OSC 1337;SetUserVar` (`kitty/docs/mapping.rst:165-263`). Zed: context keys (`screen=alt`, `bracketed_paste`, `mouse_reporting`) and per-platform forward lists (`assets/keymaps/default-macos.json:1378-1435`). Wave: terminal-local chords, then two-key chords (2 s), then global, then the block. **No product ships a literal one-shot "send the next chord to the shell"**; the nearest are JetBrains' forced-send action, kitty's pass-through mapping and Ghostty's `unconsumed:` prefix.
- **Option as Meta.** Default **off** in VS Code, JetBrains, Zed, Wave, Tabby, kitty, Warp; Ghostty decides **by layout** (true for US/US-International, else false) (`ghostty/src/input/keyboard.zig:10-57`). With it off xterm leaves Option to the browser to compose (é, ˜), which is why every product hard-codes the Mac editing sequences. The third-party Claude Code JetBrains plugin flips the setting on (YT-IJPL-193787).
- **Mac editing sequences** (already adopted in #660 `keys.ts:105-130`): Option+Left/Right `ESC b`/`ESC f`, Cmd+Left/Right `^A`/`^E`, Cmd/Option+Backspace `^U`/`^W`, Alt+Delete `ESC d` (VS Code `terminalContrib/sendSequence/browser/terminal.sendSequence.contribution.ts:107-263`; JetBrains `TerminalKeyEncoder.java:63-86`). xterm.js 6.0.0 sends `CSI 1;3D` for Alt+Left, and Cmd+arrows send nothing (`Keyboard.ts:113-164`), so waveterm#3193 (Option+Arrow printed `;3D` after the xterm 6 upgrade) is the same trap.
- **Shift+Enter / Ctrl+Enter.** xterm.js 6.0.0 sends plain `\r` for both (`Keyboard.ts:100-104`); agent TUIs (Claude Code, Codex) need a newline chord. Zed sends LF (zed#33858), JetBrains `ESC CR` (setting `terminal.shift.enter.sends.esc.cr`, default true), Wave `\n`, VS Code plain Enter unless the app negotiates the kitty protocol; Alt+Enter is `ESC \r` everywhere.
- **Kitty keyboard protocol** (flags 1 disambiguate, 2 event types, 4 alternates, 8 all keys as escapes, 16 associated text; push `CSI > f u`, pop `CSI < n u`, query `CSI ? u`, **separate stacks for main and alt screen**). xterm.js 6.0.0: absent; master/6.1 beta: opt-in `vtExtensions.kittyKeyboard` (typings `xterm.d.ts:465-474`). **VS Code turned it on by default on 2026-02-11 and paid for it**: fish 4.x printed `^[[99;5u` and Ctrl+C stopped interrupting (vscode#295372), Textual ignored Space (#299822), Caps Lock typed `[57358u` (#304679), Neovim 0.12 `CSI > 3 u` made Shift+digit type digits (#311252, xterm.js #5823), numpad (#299374), a bare modifier cleared the selection (#336506), fish password prompts locked input (#300131). The stack **leaks if a remote session dies mid-mode** (kitty #7603): reset on session end. Zed (#29654) and Wave (#2359, #3355) still do not support it; Warp does (`mode.rs:36-89`).
- **IME and AltGr.** xterm.js 6.0.0 on **macOS WKWebView** drops the first IME character (#6144: WebKit fires `beforeinput/input` before `keydown`; fixed on master in #6200, not in 6.0.0), loses the second after keyCode 229 (#5887), duplicates dead keys (`~/` becomes `~~`, #5894), and drops `insertReplacementText` for Korean (#6284). AltGr (Ctrl+Alt) must never be encoded as Meta (zed#63703).
- **Escape.** VS Code and JetBrains (since 2024) send Esc to the shell; #660 follows (Escape stays, F6 leaves).

**Here.** *UI only*, plus a decision. #660's rule (every Cmd chord to the app except copy/paste/select-all/clear on a Mac; Ctrl without Shift to the shell elsewhere) is a **blanket rule**, the inverse of VS Code's per-command skip list. It will need an allow-list and a "send this chord to the shell" action the first time a user binds Cmd+Shift+something the terminal wants. **Simplest correct version:** keep `macOptionIsMeta:false` but make it a setting with Ghostty's by-layout default; add Shift+Enter -> `ESC CR` (as JetBrains) behind a setting; keep the Mac sequence table; do **not** enable kitty keyboard until an xterm.js containing #6200 and the 6.1 line is pinned, and when you do, ship it behind a kill switch with a reset (`CSI < u` x stack depth) on session end and on reconnect; ask a "would the terminal consume this chord?" question before the host acts on a chord (Ghostty's `keyEventIsBinding`).

**Pitfalls (cited).** vscode#127764 (Esc+ for Option), waveterm#3193, xterm.js #5894/#6144/#6284, kitty #7603 (stack leak), Ghostty #2981 (AltGr + kitty protocol on non-US layouts duplicates characters in nvim), #7110 (alt+é on AZERTY), Warp #14835 (macOS editing shortcuts silently dropped in non-kitty alt-screen TUIs: a context predicate bug).

### 11. Rendering: GPU with fallback, ligatures, unicode/grapheme width, images

**Problem.** Fast, correct text on a webview: GPU when it works, a fallback when it does not, the right cell width for emoji and CJK, and a decision about inline images.

**What the best do.**
- **Renderer policy.** xterm.js 6.0.0 has the DOM renderer and a WebGL2 addon only (canvas is gone). VS Code: `gpuAcceleration` `auto|on|off`; a load failure sets a **process-wide** DOM flag, a context loss waits 3 s for `webglcontextrestored` then falls back to DOM **without** setting the flag (so a later attach retries); no failure counter and no driver blocklist; **WebGL is not disposed on hide** (`xtermTerminal.ts:937-1008`; xterm `WebglRenderer.ts:110-131`). Tabby retries WebGL 3 times then stays DOM forever (tabby#11837) and rejects SwiftShader as "no WebGL"; Wave added `term:disablewebgl` for GPU-less Linux (waveterm#2352) and suspects WebGL context loss after sleep/wake (#2895).
- **WebKit limits.** WebKit caps live WebGL contexts at 16 per page and recycles the oldest with a non-restorable loss; in xterm 6.0.0/addon-webgl 0.19.0 `dispose()` does **not** release the GL context (xterm.js #6068, fixed on master by #6069 on 2026-10-29), and the leak of `_cursorBlinkStateManager` (#5818/#5817, 2026-04-21) is also master-only. Also open on 6.0.0: #6239 (blank frame when the renderer is set while paused), #6015 (the WebGL addon floors the character width, DOM does not, so a renderer swap reflows the grid), #6208 (a hidden `display:none` DOM terminal re-renders every row on each scroll), #6258 (white box during context loss). npm: `latest` is still 6.0.0 / addon-webgl 0.19.0, both published 2025-12-22 (`npm` registry, run here); VS Code itself ships `@xterm/xterm ^6.1.0-beta.337` (`vscode/package.json:147-156`).
- **Fonts and ligatures.** `customGlyphs` (box drawing), `rescaleOverlappingGlyphs` (VS Code true), `minimumContrastRatio` 4.5 in VS Code and APCA 45 in Zed; the ligatures addon parses the **font file from disk** (Node APIs), so in WKWebView only a fallback list of ~55 sequences applies [INFERENCE: not run]; web fonts must be loaded before `open()` or metrics use the fallback (`addon-web-fonts` `relayout()`).
- **Unicode.** VS Code `unicodeVersion` `6|11`, default **11**, applied to the renderer and to the headless xterm that serialises, and kept identical (`xtermTerminal.ts:1211-1220`; `ptyService.ts:1127-1135`); `addon-unicode-graphemes` is unpublished ("experimental"); DECRQM 2027 (grapheme mode) is not implemented so apps cannot detect it; Ghostty defaults to `grapheme-width-method=unicode` and mode 2027; JetBrains has open reports of FE0F/ZWJ over-counting (YT-IJPL-255452). #660 already activates v11 and measured the cursor column against the shell's count (seam `r2`: 17 = 16 + 1).
- **Images.** xterm.js `addon-image` 0.9 (sixel + iTerm OSC 1337; defaults `pixelLimit 16,777,216`, `storageLimit 128 MB`, `sixelSizeLimit 25,000,000`); kitty graphics only on master (`kittySupport` default true); VS Code `enableImages` default **false** and WebGL-only; Zed ships none; JetBrains **disables** the Kitty graphics protocol and answers `XTVERSION` "JetBrains Terminal" so tools like yazi do not send images; Ghostty `image-storage-limit` 320 MB per screen. Image media (file/shm) only work on the local machine, so remote targets get the direct medium only.

**Here.** *UI*: keep the two-tier policy but **stop creating and disposing the addon on every show/hide** on 0.19.0 (pitfall 5): create once per terminal, dispose only on context loss and terminal dispose, cap live contexts, add a failure counter with a sticky DOM fallback and a settings kill switch, and test 40 create/dispose cycles in the real WKWebView. Ship a preloaded monospace + symbol font. **Simplest correct version:** WebGL while visible and focused, DOM otherwise, one addon instance per terminal, `unicode11`, no images, no ligature parsing. **Images are not worth it for v1** (preview TUIs only); if added later, behind a setting with the storage caps above and an honest `XTVERSION`.

### 12. Accessibility (screen-reader mode)

**Problem.** A canvas or a grid of spans is invisible to a screen reader; terminals also produce unbounded output.

**What the best do.** xterm.js `screenReaderMode` (default false, no OS auto-detect) builds an `AccessibilityManager`: a `role=list` row mirror plus an `aria-live=assertive` region fed by per-character events, typed echo suppressed, and "Too much output to announce, navigate to rows manually" beyond `MAX_ROWS_TO_READ = 20` (`xterm.js-6.0.0/src/browser/AccessibilityManager.ts:15-17,83-160`); it stops cancelling key events so the hidden textarea changes. VS Code sets it from `isScreenReaderOptimized()` at creation and on change, adds an **accessible view** (Alt+F2, or Ctrl/Cmd+Up) that shows cached scrollback + viewport as text with command-to-command navigation (Alt+Up/Down), a `TextAreaSyncAddon` that mirrors prompt input into the textarea when shell integration exists, `accessibility.signals.terminalCommandSucceeded/Failed` on each command end, and `VSCODE_A11Y_MODE` for pwsh (`terminalContrib/accessibility/browser/*`; `decorationAddon.ts:233-253`). Zed has no screen-reader code in its terminal crates.
**Here.** *UI*: wire `screenReaderMode` to the OS setting, keep the `aria-label` #660 already sets (`xtermEngine.ts:205-208`), and provide a **read-only text view of the scrollback** as the main path (the live region is noisy). Command-finish announcements need 133 (mechanism 6). **Simplest:** setting + OS detection + a "Terminal output" read-only view; test VoiceOver in WKWebView. **Pitfalls:** xterm.js #5382 (content read twice, the tree duplicates every viewport row: cost on large output); vscode#95441 (output announced twice), #164684 (NVDA read only "list item 13 of 15" after an Electron bump), #95530 (pwsh paste broke with a screen reader: PSReadLine disabled), #270158 (IME broken in screen-reader mode).

### 13. Splits, tabs, rename, colour/icon, drag between

**Problem.** Many terminals per window, each with an identity (title, icon, colour, cwd), moved and restored without losing the session.

**What the best do.**
- **VS Code**: groups (tabs) hold instances (split panes); only the active group is visible; equal distribution, sash double-click re-equalises, min pane 80 px, ratios persisted; a new split goes after its parent and its cwd is `splitCwd=inherited` (shell-integration cwd, else a naive cwd refreshed on Enter, else the initial cwd); tab title template `${process}` and description `${task}${separator}${local}${separator}${host}${separator}${cwdFolder}` with variables for cwd, process, sequence, progress, shellType, shellPromptInput; a user rename pins the title and detaches the OSC title listener; icon = codicon or URI, colour = one of the 8 ANSI colours; a status list (bell, disconnected, relaunch-needed, shell-integration-attention); terminals can live in the editor area and move between windows (a dropped terminal is detached from its pty host and re-attached) (`terminalGroup.ts:21-624`; `terminalTabsList.ts:569-741`; `terminalInstance.ts:2184-2896`; `terminalStatusList.ts:23-153`; `common/terminalConfiguration.ts:21-143,357-371`).
- **JetBrains**: a split is a **new shell in the original's current cwd**, not a clone; the tab shows the OSC 0/2 title only while a command runs (decided by shell-integration status); tab options persisted `{name, userDefined, cwd, shell command, env, process type}` and restored as a **new** shell on a 300 ms-sampled write; per-tab `restoreOnProjectReopen` opt-out (`TerminalToolWindowSplitContentProvider.kt:27-36`; `TerminalTitleUpdating.kt:42-101`; `TerminalSessionPersistedTab.kt:9-22`).
- **Zed**: pane tree with split/move/zoom/pin, rename to `custom_title`, SQLite `terminals(workspace_id, item_id, working_directory, custom_title)`, no per-terminal colour or icon (requested: zed#64357); remote splits start in home because the remote cwd is unknown (zed#36184, #65810). **Wave**: a split clones connection + last cwd, badges (icon/colour/priority) set by `wsh badge` roll up to the tab, a bell becomes a badge. **Tabby** persists title/icon/colour/pinned in its recovery token, keeps a closed-tab stack of 5, and marks activity on unfocused tabs.
- **Confirm on kill.** VS Code `confirmOnKill` `editor` by default (panel tabs never ask), `confirmOnExit` `never`; "has child processes" is a `ps -ax` poll (1 s after input, 5 s after output) ignoring `starship, oh-my-posh, bash, zsh` (`childProcessMonitor.ts:14-136`; vscode#129583: `sleep 60` in a panel tab did not prompt). JetBrains asks iff shell integration says a command is executing, else it scans child processes (any child, background jobs included). Ghostty `confirm-close-surface=true` uses "not at a prompt" from OSC 133.

**Here.** *UI*: the panel model already has session identity; add `rename` (pins the title), `colour`/`icon` from a closed palette, and activity/bell/exited statuses. *Go*: keep the tab record (title, colour, icon, shell, cwd, order) **with the session**, so a reload or a second window sees it (WezTerm lesson: tab/window titles synced to the server with a 1 s debounce to break a ping-pong). Split = new session in the tracked cwd (`GetCwd` or OSC 7), never a copy of the process. *SDK lane*: a split of a pod terminal is a new exec into the same pod/container. **Simplest correct version:** per-session `{title, titlePinned, colour, icon, cwd}` in Go; title from OSC 0/2 only while a command runs; split inherits `GetCwd`; confirm-close = `IsBusy` (done) upgraded by 133 "command running" and, later, a close-time descendant scan for background jobs. **Pitfalls:** vscode#239917 (dragging a tab to split rendered two terminals merged), zed#65810 (a local terminal restored as a remote one: the saved record has no kind), vscode#131386 (tcsh showed as `-csh` and kept editor tabs dirty).

### 14. Remote targets (pods, containers, SSH): size, exit, signal, reconnect, file transfer

**Problem.** A pod terminal must look and behave like a local one while the transport is a different protocol per target, each reporting size, exit and failure differently (or not at all). This is what the SDK exec lane has to model.

**What the protocols actually do** (all cited in `_notes/J-remote-exec.md` with file:line; the table is the primary deliverable of that pass):

| | local pty (Omniview #658) | k8s exec | k8s attach | docker exec | ssh |
|---|---|---|---|---|---|
| initial size | `launch.cols/rows` | none in `PodExecOptions`; kubectl **primes** the first frame on channel 4 (`kubectl/pkg/cmd/exec/exec.go:399-409`) | same; sends size+1 then size to force a redraw | `ConsoleSize` since API 1.42 (`moby/api/docs/CHANGELOG.md:564`) | in `pty-req` (chars win over pixels, RFC 4254 6.2) |
| resize | ordered `TIOCSWINSZ` | JSON `{Width,Height}` u16 on ch 4, no reply (`client-go/tools/remotecommand/v3.go:66-84`) | same | `POST /exec/{id}/resize?h&w`; the CLI retries 10x (n+1)*10 ms; the daemon holds a resize up to 10 s for exec start (`moby/daemon/resize.go:46-60`) | `window-change`, want_reply FALSE |
| exit code | typed `End{exited, exit_code}` | error channel `metav1.Status` -> `exec.CodeExitError{Code}` (`client-go/tools/remotecommand/v4.go:88-117`) | **none** (Success or InternalError: `cri-streaming/.../attach.go:46-55`) | `ExecInspect` **after** the stream ends; a nil `ExitCode` is flattened to 0 (`moby/client/container_exec.go:186-189`) | `exit-status` u32 (`golang-crypto/ssh/session.go:425-429`); may arrive before data/EOF |

**What the SDK lane loses today** (all verified in the notes; mechanism numbers in section 1.3): (1) the **exit code**: `k8s-plugin register.go:253-255,266-347` string-matches `err.Error()`; no pattern fits `command terminated with exit code 3`, so any non-zero exit, including a normal Ctrl-D after a failed command, becomes `ExecError{Title: "Exec failed", Retryable: true, RetryCommands: [sh, /bin/sh]}`; no `errors.As` anywhere. (2) `cleanupSession` emits ERROR (text duplicated into STDERR data) then CLOSE carrying the English `"\nSession closed\n"` as data, both with `Seq` 0 (`sdk manager.go:544-594`). (3) A clean exit, a cancel, a pty EOF and a dropped connection with an empty status are all the **same bare CLOSE**. (4) Attach skips classification and hard-codes `TTY:true`. (5) **No initial size**: the `terminalSizeQueue` is fed only by UI resizes (`pod_attach.go:17-37`); the SDK's 27x72 sizes only the local pty; the resize path is an unbuffered channel with a 500 ms drop inside the loop that also handles every session's stdin, and the queue is read only after the WebSocket handshake, so the first immediate resize is likely dropped [inference from code]. (6) `NewFallbackExecutor(ws, spdy, httpstream.IsUpgradeFailure)` imports apimachinery's type; client-go 0.37 returns the `k8s.io/streaming` error type, so on that upgrade the fallback would silently stop (verified in the 0.37.2 module sources; the plugin is on 0.35 today). (7) `cleanupSession` closes the slave then the master before the master is read dry: the last bytes can be lost [inference].

**Other products.** Zed's remote terminal is a **local pty running a client** (`ssh -t`, `docker exec -it`, `wsl.exe`): resize, exit and signals ride the client, and a dropped ssh kills the shell (`zed/crates/remote/src/transport/ssh.rs:2092-2223`, `docker.rs:780-846`). WezTerm's own SSH client polls the exit status and treats a dropped channel as exit 1; its keepalive is one 128-byte IGNORE packet (`wezterm-ssh/src/pty.rs:229-311`, `sessioninner.rs:416-445`). **Wave's SSH health monitor is the model to copy**: `keepalive@openssh.com` after 10 s idle (1 s after typing), stalled if unanswered for 10 s (5 s if the user just typed), states good/degraded/stalled with an overlay offering Reconnect/Disconnect, dial errors classified into code + subcode (dns/refused/no-route/reset/perm/timeout), a reset string (alt screen off, mouse modes off, bracketed paste off, sync output off) written after any drop (`waveterm/pkg/remote/conncontroller/connmonitor.go:73-186`, `sshclient.go:143-247`, `shellutil.go:625-644`). Tabby retries on drop but has no exit-status handling and guesses an "explicit exit" from the typed `exit` (`sshTab.component.ts:250-254`). kitty's `kitten ssh` ships terminfo and shell integration over the TTY with a one-time password, sets `ServerAliveInterval=60`, `ServerAliveCountMax=5` (`kitty/kittens/ssh/main.go:123-147`); Ghostty's `+ssh` installs terminfo over a throw-away ControlMaster and falls back to `xterm-256color` on any failure; iTerm2's conductor + `framer.py` gives file transfer and credit-based flow control on a second channel. **VS Code's predictive local echo** (`localEchoEnabled` off, `auto` = remote only, threshold 30 ms, excluded `vim vi nano tmux`) is the only latency mask in the field.

**Here.** *SDK exec lane*: this is a contract problem, not a rendering one: section 6 lists the typed fields. *Plugin (kubernetes)*: map `*StatusError`, `UpgradeFailureError`, `CodeExitError` with `errors.As`; prime the `TerminalSizeQueue` with the creation size; prefer WS v5 and keep the fallback; decide per capability what "close" means (cancel = detach; the process may survive, so the UI's "Terminate session?" text must say so for pods). *UI*: reset input modes (mouse, bracketed paste, application cursor, the kitty stack) when a remote session ends or drops, because nothing remote restores them (Wave, Tabby, kitty #7603). *Host*: file transfer hooks (upload/download/open) belong to a plugin-facing file service (tar over exec for k8s, SFTP for ssh); until it exists links and drops must degrade to copy-path.

**Simplest correct version.** `ExecStarted`/`ExecEnd`/`ExecFailure` as typed events (section 6); **LOST** is an end state (never exit 0); size in the open request and a latest-wins resize slot that never blocks the input loop; drain the remote read side eagerly into a bounded ring and put the host's ack watermarks on that ring, never on the remote socket (a hidden-tab pause must not stop reading the pod: k/k#142376); label pod terminals non-persistent; reconnect = new exec with a visible separator; keepalive/health states from Wave's monitor.

**Pitfalls (cited).** The k/k, kubectl, moby and golang/go issues in the table; plus k/k#44371 (a background child holds the pipe so the call never returns: containerd's `drainExecSyncIO` has no timeout), k/k#129144 (a removed pod leaves running execs open but frozen), k/k#96339 (a consumer that stops draining blocks the server and the error stream is never read: the plugin's bridge has the same shape), moby#31223/#35561/#33794 (resize before the exec exists: exec_resize 500, `stty size` = `0 0`), testcontainers-go (an exit code read before the stream drained returned 0 for a failing command).

### 15. AI and agent integration: context, safe command running, and what the producer must expose

**Problem.** Four separate things hide under "AI in the terminal": (a) giving a model the **context** of the user's terminal (last command, its output, exit code, cwd); (b) letting an agent **run** commands, which needs approval, sandboxing, output bounds, timeouts and a kill; (c) "explain this error" and command suggestion; (d) doing all of it **reliably**, which is a producer problem: a model that has to guess where a command ended from rendered rows will hang or lie.

**What the best do.**
- **Agents do not scrape the user's terminal.** Codex, Gemini, Zed and the Agent Client Protocol run each command on their **own** pty or pipes and return a typed result. Codex: `exec_command{cmd, workdir, tty (default false = pipes), yield_time_ms, max_output_tokens, sandbox_permissions, justification, prefix_rule}` and `write_stdin{session_id, chars}` (empty = poll); result `{chunk_id, wall_time_seconds, exit_code, session_id, original_token_count, output}`, with a separate UI event stream (`ExecCommandBegin/OutputDelta/End`) (`codex-rs/core/src/tools/handlers/shell_spec.rs:9-210`; `protocol/src/protocol.rs:4033-4169`). Its **remote lane** is the nearest template for the SDK exec lane: `process/start{process_id, argv, cwd, env_policy, tty, sandbox}`, `process/read{after_seq, max_bytes, wait_ms} -> {chunks[{seq, stream, bytes}], next_seq, exited, exit_code, closed, failure, sandbox_denied}`, `process/write{chunk, write_id}` (idempotent), `process/signal`, `process/terminate`, typed start errors `SpawnNotFound|SpawnPermissionDenied|SpawnFailed|SandboxUnavailable` (`exec-server-protocol/src/protocol.rs:27-34,378-418,517-636`). ACP's `terminal/create{command, args, env, cwd, outputByteLimit}`, `terminal/output -> {output, truncated, exitStatus{exitCode, signal}}`, `wait_for_exit`, `kill`, `release` (https://agentclientprotocol.com/protocol/v1/terminals.md). Claude Code (doc only): a separate process per call, `cd` persists only inside the project, background commands with an output file and a task list, `PreToolUse`/`PostToolUse` hooks on Bash, `CwdChanged` (https://code.claude.com/docs/en/tools-reference.md).
- **VS Code has two designs, and the older one is the lesson.** The Local harness drives a **hidden xterm.js terminal** and picks a strategy by shell-integration quality: *rich* (OSC 633 `A B E C D` in order: done = `onCommandFinished`), *basic* (idle poll then regex), *none* (1,000 ms idle then a prompt regex, no exit code); it is deprecated ("will be removed by February 2027") (`chatAgentTools/browser/executeStrategy/*.ts`; docs `code.visualstudio.com/docs/agents/run/tools`). Its failure history is the argument against scraping: #254447 "Agent mode hangs when running terminal command" (custom prompts broke integration), #313074 (integration stops mid-session; 42% of eval failures), #313412 (an unconditional Ctrl+C produced 42 fake `exit 130`), #316222 (a stale `^C` empty command won the race), #321667 (the start marker scrolled out of the 1,000-line scrollback). The successor, the **Agent Host Protocol** (MIT, https://github.com/microsoft/agent-host-protocol/blob/main/docs/guide/terminals.md; protocol 1.2.0 with a version handshake), makes the terminal a typed, subscribable resource: `TerminalState{title, cwd, cols, rows, content[], lifecycle, claim, supportsCommandDetection}`, `content` = `unclassified{value}` | `command{commandId, commandLine, output, timestamp, isComplete, exitCode, durationMs}`, actions `terminal/data` (server only), `input`, `resized`, `claimed`, `titleChanged`, `cwdChanged`, `exited{exitCode?}`, `commandExecuted{commandId, commandLine, timestamp}`, `commandFinished{commandId, exitCode, durationMs}`; "the server MUST NOT include shell integration escape sequences in `terminal/data`"; `terminal/input` and `terminal/data` are separate because write-ahead reconciliation is unsafe for a pty (`vscode/src/vs/platform/agentHost/common/state/protocol/channels-terminal/{state,actions,commands}.ts`). Its Node side runs a chunk-split-safe `Osc633Parser`, keeps 100,000 chars trimmed to 80,000, trusts `633;E` only with the nonce, and a headless xterm that **answers cursor-position queries itself** because "late replies from a UI that holds output would stall TUIs" (`agentHost/node/{osc633Parser.ts:152-347, agentHostTerminalManager.ts:33-56,690-806, agentHostHeadlessTerminal.ts:51-58}`).
- **Warp** runs agent commands as ordinary blocks **in the user's pty** (`warp/app/src/terminal/writeable_pty/pty_controller.rs:496-499`, `CommandExecutionSource::AI`); the wire contract is public in `warpdotdev/warp-proto-apis` (AGPL-3.0, `LICENSE.md`; pinned at `warp/Cargo.toml:356`, rev `9c9bad2`): `ExecutedShellCommand{command, output, exit_code, command_id, started_ts, finished_ts, is_auto_attached}` (`apis/multi_agent/v1/attachment.proto:33-46`), `LongRunningShellCommandSnapshot{output, cursor, command_id, is_alt_screen_active, is_preempted}` (`:54-85`), tools `RunShellCommand{command, is_read_only, uses_pager, is_risky, wait_until_complete}`, `WriteToLongRunningShellCommand{input, mode raw|line|block}`, `TransferShellCommandControlToUser` (`task.proto:657-717`); a command is rejected with `TerminalBusy` while another block runs (`warp/app/src/ai/blocklist/action_model/execute/shell_command.rs:342-354`), the default wait is 2 s and an agent may ask for up to 120 s (`:84,88`), output is 50 rows or 2,500 head + 2,500 tail rows (`block.rs:111,116,1800-1822`). Warp also had to ship advisories for exactly these surfaces (mechanisms 6, 7, 9 and 15).
- **Bounds belong in the producer**, as head + tail + an omitted counter: Codex 1 MiB per process, 50%/50%, `... N bytes omitted ...`, then a second cut to ~10,000 tokens (`unified_exec/process.rs:43-56`; `utils/head-tail-buffer/src/lib.rs:6-19`); Claude Code inlines 30,000 chars and spills the rest to a file with a 2,000-char preview; VS Code 20,000 chars with a spill file (500-char head + tail) and 8,000 for `get_terminal_output`; Zed 16 KiB, head kept; ACP keeps the tail with `truncated`. VS Code's output comes from re-reading xterm **rows**, so it lost the start when scrollback rolled (#321667) and inserted a space where a wide character did not fit (#343642): never derive agent text from rendered rows.
- **"Waiting for input" is not detected by any producer.** Codex has none (the model polls with an empty `write_stdin`); Gemini only runs UI timers (5 s focus hint, 30 s "action required", 60 s "silent working") and had a 5-minute hang on a prompt (gm#24707); VS Code uses a last-line regex gated by `isActive()` with false positives on `Status: ` and tqdm (#315476, #330790) and misses on `needrestart` (#321444). Nobody uses the foreground process group or the slave termios (ICANON/ECHO off), which Omniview already half has (`IsBusy`).
- **Anti-hang environment** on agent runs: Codex `NO_COLOR=1`, `TERM=dumb`, `PAGER/GIT_PAGER/GH_PAGER=cat`, `LANG=C.UTF-8`, `CODEX_CI=1` and stdin `/dev/null` for pipes; Gemini `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=''`, `SSH_ASKPASS=''`, `GCM_INTERACTIVE=never`; VS Code `AI_AGENT`, `GIT_PAGER=cat`, `GIT_EDITOR=:`, `DEBIAN_FRONTEND=noninteractive`, `VSCODE_PREVENT_SHELL_HISTORY`. Headless ptys answer `CSI 5n`, `CSI 6n`, `CSI 18t`, DECRQM themselves (`codex-rs/sandboxing/src/terminal_queries.rs:5-66`).
- **Kill.** Codex: timeout = `SIGKILL` to the whole group (exit 124), cancel = `SIGTERM`, 50 ms, `SIGKILL`; Gemini `SIGTERM` then `SIGKILL` after 200 ms, `taskkill /f /t` on Windows; bound the post-exit pipe drain (2,000 ms) because grandchildren keep pipes open; every child a session leader; `PR_SET_PDEATHSIG` on Linux (`codex-rs/core/src/exec.rs:67-98,1005-1042`; `spawn.rs:100-134`). Omniview's 1.5 s is 30x slower.
- **Approval.** Parse into sub-commands with a real shell parser (tree-sitter-bash in VS Code, Codex, Gemini; brush-parser in Zed; Warp's `decompose_command`); **deny wins if any sub-command matches, allow only if all match**; unparseable or non-POSIX = ask; strip leading `VAR=value` before matching (Warp GHSA-3839-h8jj-ph82: `X=1 rm ...` bypassed the denylist); refuse reusable approval for shells and interpreters (`bash -c`, `python`, `node -e`, `env`: Codex `exec_policy.rs:64-153`); "deny means ask, never block" (VS Code docs); file-write detection (redirects, `sed -i`, `find -exec/-delete`, `sort -o`, `git --output`) and `cmd` delayed expansion (`!VAR!`) hiding a path (VS Code `platform/terminal/common/autoApprove/*`). Open holes show why rules are not a boundary: vscode#328107 (assignments), #318347 (wrappers `timeout`/`bash -c`/`env` hide the inner command), #319856 (a session approval of `pwsh -NoLogo` let `send_to_terminal` run `Remove-Item`). Defaults worth copying as *shape*: VS Code allow `cd echo ls cat grep find rg sed tree`, `git status|log|diff|show`; deny/ask `rm dd kill ps curl wget chmod chown jq xargs eval`; Warp's 18-entry denylist (`bash fish pwsh sh zsh curl eval exec source wget dig nslookup host ssh scp rsync telnet rm`).
- **Sandbox.** Codex: macOS `/usr/bin/sandbox-exec` with a generated profile (absolute path to defeat PATH hijack), Linux bubblewrap + seccomp, protected names `.git .agents .codex .aws`, a `TIOCSTI` deny so a child cannot inject keystrokes into the parent shell; Anthropic's `sandbox-runtime` (Apache-2.0): allow-only writes, deny-then-allow reads, network only through local HTTP/SOCKS proxies with domain allow-lists, mandatory write-deny for `.bashrc .zshrc .gitconfig .git/hooks .mcp.json .vscode .idea`; VS Code wraps each command with it and auto-approves sandboxed ones. **Sandbox + pty is a known sharp edge**: Seatbelt must allow `pseudo-tty`, `/dev/ptmx` and tty ioctls (sandbox-runtime #419/#721: `allowPty` opens every `/dev/ttys*`), bubblewrap `--new-session` removes the controlling tty so SIGWINCH never arrives (#642), and a PTY per command leaked until `kern.tty.ptmx_max` (gm#29592).
- **Terminal context for assistants.** VS Code `terminal_last_command` = command (or "currently executing"), cwd, exit code, output from the **active** terminal, no cap found; `terminal_selection`; attachment `terminalCommand{command, output, exitCode, resource}` (`chatAgentTools/browser/tools/getTerminalLastCommandTool.ts:40-122`; `chat/browser/actions/chatContext.ts:472-537`); the extension-API path (explain/fix) reads the last 40 write events, 16,000 chars, ANSI-stripped, **without an exit code** (`extensions/copilot/.../terminalBufferListener.ts:14-103`); quick fixes send a command regex plus the last N output lines. Zed gives the assistant only the user's selection or the last 50 non-empty lines (it has no marks). JetBrains' block model offers `getOutputText`, `getTypedCommandText`, cwd, exit code to any plugin but ships no LLM code. kitty's remote control is a typed API (`kitten @ ls` JSON with `last_cmd_exit_status`, `at_prompt`, `foreground_processes`; `get-text --extent=last_cmd_output`; `send-text --bracketed-paste`) behind `allow_remote_control` (default no) with per-command passwords. **Wave cannot run commands at all**; its `term_get_scrollback` reads the xterm.js buffer over RPC and fails on bottom-indexed ranges with blank padding rows (waveterm#3587).

**Here.**
- *Go local backend*: owns (1) a typed **run** API on its own pty or pipes, (2) the host-side approval engine on parsed commands, (3) the per-session command record (tee-parsed OSC, mechanism 6) behind "last command", (4) group kill, the anti-hang env and a cap on concurrent ptys. The UI's 4 MiB hold and the 1,000,000-byte ring are **display** buffers and cannot serve agent reads (they have no offsets).
- *UI*: renders agent runs read-only (a detached xterm fed from the producer, as VS Code's `chatTerminalCommandMirror.ts`), shows approvals, and offers takeover; it is never the source of truth.
- *SDK exec lane*: a non-TTY `Run` for pods with separate stdout/stderr, the exit code from the error channel, `output: COMPLETE|TRUNCATED|UNKNOWN`, cancel = detach (the process may survive), and a sentinel-echo fallback for TTY sessions with no integration (VS Code's agent host appends `echo "<<<SENTINEL_<uuid>_EXIT_$?>>>"` and scans, `agentHost/node/shared/shellCommandExecution.ts:98-132,289-372`).

**The producer contract that makes this reliable** (synthesis of D, K, I, J):

| Need | Who does it | Omniview today |
|---|---|---|
| unique `run_id`/`command_id`, caller-supplied and bound before start | Codex `process_id`+`call_id`, ACP `terminalId`, VS Code `setNextCommandId` | none |
| typed start and end events | Codex Begin/End, AHP `commandExecuted/Finished`, Claude Pre/PostToolUse | local `End` only |
| exit code **or** signal **or** lost | Codex int (124 timeout, 128+n), ACP `{exitCode, signal}`, ssh `exit-status`/`exit-signal` | local yes; SDK lane no |
| wall time, `started_at`/`ended_at` | Codex `Wall time`, Claude `duration_ms` | none |

| stdout/stderr tag when no tty | Codex exec-server `stream`, ACP none | SDK `target` exists |
| output cursor: absolute byte offset | Codex `after_seq/next_seq`, AHP `seq` | none (ring has no offset) |
| bounded buffer + `omitted_bytes` + spill | Codex head+tail, VS Code spill file, Claude spill file | none |

**Simplest correct version.** (1) Agent commands never type into the user's shell: `Run{argv|script, cwd, env, timeout, max_output_bytes, stdin}` on a fresh pty or pipes; the result is `{run_id, status: exited|signaled|timeout|killed|denied|lost, exit_code, signal, duration_ms, output{head, tail, omitted_bytes, total_bytes}, cwd_end?}`. (2) For user terminals, `LastCommand(session_id)` from the mark record with `{command_id, command, trusted, cwd, exit_code, output_range{start_offset, end_offset}}`, never from the focused tab or the last N rows. (3) Approvals host-side, deny-first, unparseable = ask, canonicalise leading assignments, never persist a bare interpreter prefix, stdin writes are a separate approval class, record the decision on the run. (4) Group kill with SIGTERM + 50-200 ms + SIGKILL, bound the post-exit drain (2 s), cap concurrent ptys (Codex 64). (5) If the headless text is wanted (cursor moves, `\r` progress bars), render it where the bytes already pass: Go has no xterm-headless, so the options are a Node sidecar, a Go VT library, or pipes with `TERM=dumb` [inference].

**Pitfalls (cited).** Cursor forum threads: a user's `agent shell-integration zsh` line in `.zshrc` deadlocked the agent's fresh non-TTY zsh; `createSession timeout after 15000ms` from zsh plugins; Codex cx#57413 (empty output, exit 0: a 50 ms post-exit wait lost bytes), cx#37207 (output omitted when a listener lagged), cx#62488 (stdout/stderr interleaved mid-line), cx#61647 (group kill missed a sandboxed child in a new session), gm#30007 (a SIGTERM in headless left the command running and exit 0); zed#64701 (an interactive `-i` agent shell prints the pyenv warning before every command); Warp #14324/#11706 (agent heredocs leave zsh stuck at `dquote>`), #15855 (on wake Warp wrote commands carrying the local cwd into a dead remote session).

### 16. Warp-style blocks and a rich input editor

**Problem.** Draw each command and its output as a unit (collapse, copy, rerun, filter, sticky header) and edit the command line in a real editor (multi-line, selection, completion) instead of the shell's line editor. What does that need from the shell, and can xterm.js host it?

**What they do.** *Warp* builds a **separate grid set per command** (header = prompt + command, rprompt, output) from shell hooks, never from heuristics ("a single grid lets output overwrite earlier commands"), with a lifecycle state machine (AwaitingPrecmd, AtPrompt, Submitted, Executing, ...); the input editor is **native** (an op-based CRDT text buffer, Fig-derived completion signatures, history autosuggest, a natural-language classifier), and the shell's own line editor is reduced to a submit path: `^P` kill-line, then the command as a bracketed paste with every ESC byte stripped, then `\n`; writes are **gated** until the line editor is judged active (50 ms after precmd, or OSC 133;B in zsh), a command alive for >= 50 ms hides the editor and sends keys to the pty (`warp/app/src/terminal/model/block.rs:297-439,1706-1740`; `writeable_pty/pty_controller.rs:776-827`; `line_editor_status.rs:11-98`). What it **requires from the shell**: precmd + preexec hooks with a per-session id, OSC 133 A/B around the prompt, line-editor binds (`^P`, `ESC i` to dump the buffer), bracketed paste (without it multi-line commands split: Warp #16680 on PowerShell), the ability to inject a script, and a hidden prompt grid for the user's own prompt. It has **no raw-terminal fallback** if the bootstrap fails (a banner after 7 s; #14484: the editor stays visible but unusable) and its top bugs are the typed bootstrap and the input gating. *VS Code* makes blocks only as **chrome on one xterm buffer** (marker-anchored decorations, a hover guide, a sticky overlay that is a second xterm filled by the serialize addon) and **reconstructs the input line by scanning xterm cells** between the `B` marker and the cursor (`PromptInputModel`), which is brittle with right prompts and ghost text (vscode#282541, #245970). *Ghostty/kitty* only mark `B` (the editable region) and never replace the line editor. *JetBrains*' Gen1 block terminal had a prompt editor; the reworked terminal is one terminal with decorations over OSC 133 ranges.

**Can xterm.js host it?** *Blocks as chrome: yes* (markers + decorations + sticky header + jump + copy-output), with limits: one buffer so no overwrite isolation, no row hide/fold API (searched the typings), decorations are DOM nodes (cap them), markers die on `clear()`, are hidden in the alt buffer and need their lines kept in sync with trim and reflow. *A rich input editor: yes, as a DOM editor above the terminal*, with a mode switch (prompt vs raw/alt-screen/long-running), write gating on OSC 133;B, kill-line + bracketed-paste submit, and a typeahead capture. It works **only for local shells that run Omniview's integration**; pods and any shell without it are raw only.

**Simplest correct version.** Ship marks, gutter, jump, copy-output and the sticky header first (mechanism 6); keep the shell's own line editor; add the editor later as an opt-in per shell with a permanent raw path. **Do not** type bootstrap into the user's tty, do not hide the user's prompt by default, and do not promise blocks or exit codes for pod terminals.

## 5. The five pitfalls most likely to bite this codebase

Ordered by likelihood times damage, given what #658 (`398a83a7`) and #660 (`873d7a53`) already do. Each names the file, the mechanism, and a guard.

**1. The shell-start contract starts the user's shell twice and reorders PATH (and blocks bash integration).**
*Files:* `backend/pkg/terminal/manager.go:321-331` (env from `RestoreNativeChildEnvironment(os.Environ())`, then `terminalEnvironment`, then `pty.StartWithSize`); `internal/shellenv/shell.go:97-98` (`-i -l` for bash, zsh, fish, sh, dash, ksh, nu, xonsh); `internal/shellenv/environment.go:19-35,106-111` (on macOS `Restore` runs `$SHELL -i -l -c 'printf marker; env -0'` at start and `os.Setenv`s the result into **the host process**, keeping `HOME`, `SHELL`, `PWD`, `XDG_*`, `OMNIVIEW_*`).
*Why it bites:* by the time a terminal starts, the host's `PATH` already holds the user's directories **in front** (Homebrew, mise/asdf shims, nvm). The shell then runs as a login shell, `/etc/zprofile` runs `path_helper`, and with a pre-populated `PATH` it moves the system directories to the front and the user's to the **back**. Reproduced here: `env -i PATH=$HOME/.local/share/mise/shims:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin /usr/libexec/path_helper -s` prints `PATH="/usr/local/bin:/System/Cryptexes/App/usr/bin:/usr/bin:/bin:/usr/sbin:/sbin:...:<home>/.local/share/mise/shims:/opt/homebrew/bin"`. Version-manager snippets of the form "prepend unless already present" then decline to prepend, so `python`, `node`, `kubectl` resolve to the system copy. JetBrains shipped exactly this (YT-IJPL-200767, fixed 2025-08) and now documents that the shell's base env "should be non-interactive and non-login ... loading the same configuration file twice might break things" (`terminalStartup.kt:193-200`); VS Code re-applies PATH prefixes after the profile because of `path_helper` (`terminalEnvironment.ts:279-314`). #658's own test starts with `PATH=/usr/bin:/bin:/usr/sbin:/sbin` and a `.profile`, so the double run is never exercised (`T1-go.md` 2.8.1). **Second effect:** with `-l` bash **ignores `--rcfile`** (run here: bash 5.3.0, the profile ran and the rcfile did not), so the T5 plan "the host injects the integration for bash" cannot use the obvious flag.
*Guard:* decide A (pre-restore env + `-l`) or B (restored env + `-i`, no `-l`, PATH prefixes re-applied) and add a test that compares `zsh -ilc 'print -l $path'` from a pristine launchd-like environment with the terminal's, using a `.zshrc` that has a mise-style "prepend if absent" line.

**2. Hidden-tab flow control: the UI's hold and the backend's credit cannot both be right.**
*Files:* `ui-next/shell/panel/terminal/screen.ts:185-225` (the pump runs only while visible), `:402-425` (`hide()` detaches the feed and swaps to DOM), `execFeed.ts:47` (`HELD_BYTES = 4 << 20`), `heldOutput.ts:49-55` (drop whole oldest chunks), against `backend/pkg/terminal/flow.go:47-66` and `types.go:253-254` (stop reading at 1 MiB unacked); `T1-go.md` decision 8 says "the new UI turns it on and acknowledges as it writes into the emulator".
*Why it bites:* acks tied to the emulator's parse never come while the panel is hidden, so the shell blocks in its own `write` at 1 MiB: `npm run dev` or a build in a hidden terminal stops. Acks tied to receipt remove the stall but make the 4 MiB drop-oldest policy the only bound, and dropping whole pty reads can cut an escape sequence in half or lose an alt-screen/bracketed-paste/mouse mode toggle (the emulator "cannot recover from a sequence cut inside one" read, as `heldOutput.ts` itself says). A held, unparsed stream also **cannot answer** DA1/CPR/XTVERSION/OSC 10/11 queries: fish waited 10 s for a DA1 reply while Wave dropped `onData` until loaded (waveterm#3162, cause unproven), and VS Code's agent host answers CPR itself in a headless terminal precisely because "late replies from a UI that holds output would stall TUIs". VS Code and Tabby both keep parsing and acking while hidden and rely on xterm's paused renderer; xterm.js' own guide acks from the write callback. T1.md measured 29,524 DOM mutations for a hidden `display:none` DOM terminal, which is xterm.js #6208; the fix is not "hold" but "parse without rendering" (create the emulator at session start, `open()` it on first show).
*Guard:* pick design A or B of mechanism 3 before flipping `launch.flow`; add a probe that floods a hidden terminal and asserts the shell keeps running, the bytes are complete, and a DA1 query is answered.

**3. xterm.js 6.0.0 in WKWebView: the paste, IME and WebGL gaps that are fixed only on master.**
*Files:* `ui-next/shell/panel/terminal/xtermEngine.ts:44-67` (no paste handling beyond xterm's own), `:131-136` (`onData` only), `:168-200` and `screen.ts:313,415-425` (a WebGL addon created on every show and disposed on every hide).
*Why it bites:* (a) **paste injection**: 6.0.0's `bracketTextForPaste` wraps text without sanitising, so a pasted `ESC[201~` ends the bracket and what follows runs (`xterm.js-6.0.0/src/browser/Clipboard.ts:21-26`; fixed on master by #5716); iTerm2, Zed, Alacritty and Warp's command path all strip. (b) **IME on macOS WKWebView**: the first IME character is dropped (#6144, fixed on master by #6200), dead keys duplicate (`~/` becomes `~~`, #5894), Korean `insertReplacementText` is lost (#6284). (c) **WebGL**: in 0.19.0 `dispose()` does not release the GL context (#6068, fixed on master by #6069, 2026-10-29; `latest` on npm is still 0.19.0 from 2025-12-22) and WebKit caps live contexts at 16 per page, recycling the oldest with a non-restorable loss; with one visible terminal the recycled context is a lingering dead one, but the first split (T6) puts two live contexts on a page and a long-lived live one becomes "the oldest". The cursor-blink leak (#5818, fixed by #5817, master only) needs a blinking cursor: `cursorBlink: false` starts without one, but 6.0.0 honours DECSET 12 and DECSCUSR blink from programs (`xterm.js-6.0.0/src/common/InputHandler.ts:1908-1909,2765-2782`; `addons/addon-webgl/src/WebglRenderer.ts:363-364`), so vim or tmux can switch it on and open the leak. (d) legacy mouse reports go to `onBinary`, which the engine never subscribes to.
*Guard:* decide on the 6.1 beta line (VS Code ships `@xterm/xterm ^6.1.0-beta.337`) versus backports; sanitise paste yourself; create the WebGL addon once per terminal; run 40 show/hide cycles in the real WKWebView and count contexts.

**4. Reload and reattach (T2) on a ring that has no offset, no modes and no size.**
*Files:* `backend/pkg/terminal/manager.go:605-616` (`AttachSession` returns `buffer.GetAll()`), `backend/pkg/plugin/exec/service_wrapper.go` and `docs/ui-next/status/T1-go.md` 2.6 (a window's shells are **ended** when it is retired, so there is nothing to reattach to), `ui-next/shell/panel/terminal/localShell.ts:47-50` (a restored session is "ended"), `execFeed.ts:249-251`.
*Why it bites:* T2 needs the opposite of rule (a). Replaying a 1,000,000-byte ring is not a restore: it can begin inside an escape sequence, has lost the alt-screen/bracketed-paste/mouse state if their enter-sequences scrolled out, has no width to wrap at, races the live events (T1.md measured "about 370 lines differed"), and, replayed through xterm.js, makes the emulator **answer the old queries again into the live shell**. VS Code needed a headless emulator, same-size replay and `_inReplay` ack suppression; Wave needed an offset and still has a race; JetBrains re-sends a snapshot on every subscribe.
*Guard:* build mechanism 2's offset + modes + muted replay before the UI starts treating a window loss as "detach".

**5. The shell-integration plan meets `TERM_PROGRAM=Omniview`, the copyleft scripts and the pod lane.**
*Files:* `backend/pkg/terminal/env.go:31-37` (`TERM_PROGRAM=Omniview`), `internal/shellenv/shell.go:82-112` (the shell contract in pitfall 1), `T-terminal-bar.md` (T5: "the host injects the integration for bash, zsh, fish and pwsh").
*Why it bites:* iTerm2's own zsh script is **inert** unless `TERM_PROGRAM` is empty, `iTerm.app` or tmux ("Don't run in IDE terminals", `iterm2_shell_integration.zsh:15-26`), so users who source it by hand get nothing; prompt frameworks decide by `TERM_PROGRAM`; Ghostty's bash/zsh scripts and kitty's/iTerm2's are copyleft and cannot be copied (section 2); a nonce that the scripts do not actually send leaves cwd untrusted even in VS Code (`shellIntegration-bash.sh:267`); `p10k`/starship/`oh-my-zsh` emit their own 133/7 and cause duplicates or flicker (powerlevel10k#2959, iTerm2 #13117); and **pods get nothing**: the SDK lane has no argv/env control on a pod shell, so T5 delivers marks for local terminals only unless the lane gains a bootstrap path (section 6).
*Guard:* write the scripts clean-room from the protocol; keep the two trust tiers; test against p10k, starship, oh-my-zsh and bash-preexec; show the quality tier (None/Basic/Rich) per terminal.

*Honourable mentions (not in the top five because they need a trigger that is not here yet):* `execFeed.ts:172-194` maps **any** non-"gone" write error to a `failed` session, so the first time `INPUT_BACKLOG` (429, "send it again") or `SEQUENCE_STALE` reaches the UI through `WriteTerminal(seq)` it will kill a live shell's UI (with one write in flight today it is rare); a multi-line paste over ~1 KiB into a cooked-mode program on macOS corrupts (MAX_CANON 1,024: vscode#296955); the per-read Wails event path has no bound for sessions without `flow` and the SDK lane has none at all.

### 6.2 What the plan already gets right (confirmed by the prior art)

One stream per session with its own window (VS Code's extension terminals bypass flow control and hit xterm's 50 MB throw: `terminalProcessExtHostProxy.ts:135-137`); offsets on output and a replay ring (JetBrains snapshots, tmux per-consumer offsets, WezTerm `seqno`, Wave `seq`); **no local pty in front of the remote stream** (the SDK's raw pty adds a 4,096-byte read loop and the master-closes-before-drained race that loses the last bytes in 22-54 of 60 runs: SDK2 section 2.3 R5 and section 3.4, measured there); a typed `End` that is the last frame; facts stated once by the party that knows them, `unknown` meaning "ask"; the host builds the agent tool, enforces consent and audit and fails closed (4.6); the local terminal as a provider of the same contract so the UI has one feed (SDK2 section 5), which is what Zed, VS Code's agent host and Warp each had to converge on.

### 6.3 The contract, as one checklist (what a pod terminal needs to be "the same as local")

1. **Open**: client-chosen id; `size`, `tty`, `argv` (never a shell string), `env`/`cwd` as best effort with a typed `Notice` for what was ignored, `features` (marks, replay), `integration` mode (off, argv-wrapper, helper) and its nonce handling.
2. **Opened/Started facts**: the program that actually ran (shell path and name), transport (`k8s-ws-v5`, `k8s-spdy`, `docker`, `ssh`), the size actually granted, effective `TERM`, `capabilities` (tty, separate_stderr, resize, initial_size, stdin_eof, signals, kill behaviour, env, cwd, marks, exit_status_report, signal_report, health, file_ops, survival) and limits. The UI branches on capabilities, never on strings.
3. **Output**: `{offset, stream, bytes}` with raw bytes untouched and no English text in the data stream; `Dropped{from_offset, bytes, reason}`; a snapshot carries `{start_offset, end_offset, cols, rows, modes}`.
4. **Marks** (typed, trusted flag, command id and line, exit, cwd, duration), with the same scanner as the local provider; **quality tier** (None/Basic/Rich) in the facts.
5. **Input**: one oneof `data | resize | eof | signal | close`, ordered, with a typed refusal for a full queue; `eof` on a TTY sends `^D`, on a pipe half-closes; `signal` only when `capabilities.signals` lists it.
6. **Facts on request**: `Query(cwd|foreground)` answered with `unknown{unsupported|query-failed|remote}`; pushed when the lane knows.
7. **Health and lifecycle**: `state` good/degraded/stalled; `End` with `LOST`, `resume_hint`, `remote_may_survive`, `output` completeness, `exit_source`, the last offset; a mode-reset string for the UI to write.
8. **Run**: typed `RunResult` with `outcome` (adding LOST), exit/signal, `OutputAccount`, duration, `remote_may_survive`, no free text; refusals as typed families, never "tool invocation failed".
9. **Files** (stat/read/write) or an explicit "not supported" capability.

### 6.4 What the host's local provider must expose identically

The same `Mark` scanner and the same offset, `Opened`, `Attach`, `Dropped` and `End` semantics, so the UI has one code path (SDK2 section 5); plus what is local-only and stated as capabilities: pull-mode cwd and foreground, all signals, kill terminates, `host_restart = none`. **#658's `End`, `Foreground` and `Directory` JSON names are the ones SDK2 adopts** (section 5, "What moves"), so merge order does not matter; the one open point is `closed_by`, which SDK2 extends with values only a plugin can know and requires consumers to treat unknown values as "closed". Line numbers into SDK2 in the table above are from the 15:51 version (137,319 bytes) of a file its author is still editing; the section numbers are the stable references (wire = 4.3, session semantics = 4.5, bounded run = 4.6, IDE expectations = 4.9, local provider = 5, steps = 7).
