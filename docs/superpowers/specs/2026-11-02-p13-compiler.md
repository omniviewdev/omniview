## Boundary and ownership

P07 owns catalog, schema normalization, value admission and the CEL adapter; P12 owns acquisition interests and revision-consistent snapshots; P13 owns compilation, planner, finite evaluation and host window semantics; P14 owns authorization at its lease boundary, lease sharing, result generations, event wire, and delivery. P15 is a passive observer. No spike data structure, independent schema model, custom evaluator, client planner, or old Find fallback is introduced.

P13 uses Go module `cel.dev/cel-go v0.33.1` with `replace cel.dev/cel-go => github.com/omniviewdev/cel-go v0.33.2-0.20261028172556-d7bb038d8c7b`. P01's immutable profile manifest, optimization and cross-type numeric settings, profile implementation revision and finite policy apply. The fork does not authorize new operators or public value tags. Replacing it requires P01 profile/conformance review. P01 historical numeric hold is superseded only by its accepted fork-first receipt, not by this specification.

## Go consumer interface

These are host-internal APIs, not Wails or provider wire DTOs. Named value types below are P13-owned immutable host values; P01 `QuerySpec`, `QueryScope`, `BoundValue`, resource identity and C02 `AppError` retain their existing canonical definitions. Implementations must use their actual package names rather than introducing parallel domain aliases. Signatures below identify ownership and behavior; no stub implementation may land to satisfy them.

```go
// package query
// QuerySpec is the canonical P01 request, not a replacement domain type.
// Principal is an opaque, host-created authenticated access context, not client input.
type Compiler interface {
    Compile(ctx context.Context, spec QuerySpec, principal Principal) (*CompiledQuery, error)
}
type Executor interface {
    Open(ctx context.Context, query *CompiledQuery, principal Principal) (Execution, error)
}
type Execution interface {
    Initial(ctx context.Context) (Window, error)
    Changes() <-chan Window
    Done() <-chan error
    Close() error
}
```

`CompiledQuery` is opaque and immutable. Compilation validates request, declarations, bindings, profile and host-resolved catalog/access metadata; it holds no mutable source snapshot. `Open` independently reauthorizes the current principal and epochs, admits cost and acquires only necessary interests. A compiled object never grants access by possession. On changed access, catalog, representation, capability or scope epoch, it returns `RESET_REQUIRED` or the appropriate C02 access error rather than executing stale authorization. `Open` returns an execution only after its initial attachment and any change observation are established atomically. It must release every acquired interest on failure.

`Window` is an immutable host value with `Rows []Row`, `Coverage resourcev2.Coverage` per target, `Freshness` per target, `Watermark` per target, `Count resourcev2.Count`, and optional opaque host `Continuation`. `Row` contains target membership, canonical resource reference, representation and source provenance, and P01 projected values with absent/null/value states. `Rows` is in final deterministic order. Counts are exact only when proven, otherwise estimate or unknown. Watermarks are P12 host snapshot watermarks, never source revisions or P14 generations. All integer values retain P45 tagged exactness; transport serialization belongs to C08.

Each `Changes` value is an atomic complete replacement of the current bounded window, including coverage, freshness, watermark, count and continuation metadata. Updates are ordered after `Initial`. `Done` is a separate buffered terminal lane: it yields exactly one error, or nil for normal completion, then closes. On termination queued changes become invalid and must not be applied. `Initial` is called once; `Changes` and `Done` each have one consumer, and no update may be lost between attachment and initial delivery. `Close` is idempotent, cancels pending work, releases interests, and closes the stream; it must not block on a stalled consumer. Execution owns a bounded internal data queue; overflow terminates that execution with `RESET_REQUIRED` on `Done` independent of the data queue. P14 may reopen its consumer without reopening unrelated source interests. No claim of replay or gap-free provider updates follows from this host attachment guarantee. `once` completes after its initial image; `follow` is admitted only for a supported bounded window and actual update capability. Snapshot-only sources return `UNSUPPORTED` for follow rather than fabricating a watch.

P14 computes its authorized lease-sharing key inside the host from the effective compiled query, all targets and scopes, representations, typed bindings, projection, ordering, relevant delivery semantics, principal/access epoch and source/catalog validity. P13 supplies canonical effective compilation identity and admitted execution context through the opaque `CompiledQuery`; neither the client nor a provider supplies authority or the hash. Implementations may share a P13 execution only when P14's key and authorization match. A P13 window replacement is not a result frame: P14 derives enter/update/leave/delete/move where provable, assigns its own result generation/sequence and owns resets, batching and terminal control. Source and result generations are independent.

## Compilation and admission

1. Strictly decode and bound P01 `QuerySpec`; normalize explicit targets/scopes, identifiers, typed declarations and values. Targets remain distinct union memberships. Reject duplicates, unknown fields, invalid scopes and missing/extra/reserved bindings. Bind values as native CEL activations, never source interpolation. Lower Builder v1 to the accepted CEL grammar, preserving lexical array-element correlation and guard/negation semantics; use the same evaluator as text CEL.
2. Resolve each host-authorized target, effective route, representation, catalog snapshot and capability before checking. Resolve P07 `Snapshot.Entry` and `Entry.Resolve`; unavailable schema is an error, absent schema is bounded dynamic admission. Obtain `celtypes.NewEnvironment(snapshot.Revision(), entry, schema)` and key checking by its `Revision`, not `ContentKey`. No schema existence implies query or native execution authority.
3. Parse, resolve and check against the selected P01 environment. Known non-Boolean result rejects; `dyn` must evaluate to actual Boolean. Compile checked native CEL with pinned profile and immutable environment. Compilation identity includes normalized source/profile, declaration types, environment and schema revisions and implementation revision, not binding values. Runtime sharing identity additionally includes values and effective access/target/window context; do not log sensitive values.
4. For each candidate row, validate through P07 `resourcecatalog.Admit(ctx, schema, value, coverage, policy)` and `celtypes.ToCEL`; honor its validation capability and unvalidated constraints. Admission and required field coverage, acquisition and authorization resolve independently before CEL, text, ordering and projection. Permission denial cannot become partial success. Unavailable is never absent, null, default or false; hydrate only by a supported admitted plan, otherwise reject or return explicitly permitted partial coverage. CEL Boolean/error masking must never suppress those failures.

The profile uses native standard operators and `has`, `all`, `exists`, `exists_one`, `map`, `filter`, with no host callbacks, I/O, extensions, alternate equality or custom numeric engine. Preserve exact tagged int64/uint64, finite double, timestamps, lists and maps. Static mixed equality remains a checker error; dynamic mixed comparisons and optimized membership use the pinned fork. Explicit numeric conversions can be lossy. Correlated predicates over one array element use one lexical binding; separate existential tests are not equivalent. P01 text ANY, missing/null and conditional union rules remain normative.

## Planning and finite result

Select local, native or hybrid per target from authorized capability, native language/input descriptor, scope, schema/representation and bounded available work. P45 `NativeQueryDescriptor` declares only language and input schema; it does not prove filtering equivalence, pushdown, ordering, projection, limits, or permission. An adapter may push a predicate only with an explicit reviewed semantic capability and a proof that candidate rows are a superset under admitted scope, values, null/missing/numeric semantics and representation coverage. Without such proof enumerate locally within budgets, or reject `UNSUPPORTED`/`RESOURCE_LIMIT`; never infer proof from a descriptor or provider name. Any new SDK descriptor is additive, separately reviewed and pinned, and Kubernetes adoption is owned by its designated later PR.

Keep the original predicate as residual unless the proof establishes exact equivalence; preserve every unsupported clause and required field. Native page size bounds transport, not final host cardinality. Native projection, limit, ordering or cursor must not discard rows or fields needed for residual, global sorting or projection. Continue all necessary source pages within explicit acquisition/time/byte/item budgets; never silently crawl broader scopes, treat the first source page as a result, or truncate exact output. Native-only sources reject unsupported subsets; no-native sources use bounded local execution when possible. Partial/unknown source replacement and stale P12 rows retain provenance; they never prove deletion or exact membership.

After full admitted scope, text and predicate/residual membership, apply P01 global order including missing/null placement and canonical target/address/incarnation tie-break, then projection and final page. Source order and revision are not result order or recency. Host opaque continuation binds effective query/order/profile, bindings, schema/access, result generation, consistency and expiry; it is never a source cursor. Invalid or expired continuation returns `CONTINUATION_EXPIRED` or `RESET_REQUIRED`. Count is unknown unless exactness is actually established. `allowPartial` defaults false; true permits only policy-authorized partial results carrying explicit coverage and limitations, never forbidden acquisition.

## P12 integration and lifecycle

P12's proposed `readmodel.Manager.Acquire(ctx, Binding, InterestKind) (Interest, error)` yields independently refcounted interests; `Interest.View(ctx, func(Snapshot) error) error`, `Refresh(ctx) error`, and `Close() error` own their source lifecycle. A snapshot exposes `Revision() Watermark`, `Coverage() Coverage`, `Freshness() Freshness`, and `Range(ctx, func(Row) error) error`. Bindings include exact source selection, representation and access epoch. A view is one bounded consistent published revision; callback rows cannot be retained as mutable references. Read and copy only the projected data needed after the callback. Range errors, stale rows, provenance and cancellation remain explicit. P13 owns exactness and window policy, not P12 storage or a new interest registry.

P12 proposes `Interest.Changes() <-chan struct{}`, a stable channel per interest with one coalesced pending invalidation. Obtain the channel before the first `View`, then re-view after every notification. A change concurrent with `View` must be reflected in that coherent view or remain pending, so no wakeup is lost. Closing the interest or invalidating access closes the channel; after access invalidation `View` returns `ErrDenied`. Source refresh and generation retirement cannot overwrite newer work; changed coverage/access must invalidate or recompute with a truthful control outcome. These signatures and semantics still require independent P12 review and an immutable candidate pin.

C04 document coverage's typed `knownAbsent` paths and C05 `resourcev2.Coverage` limitation paths are distinct and cannot be converted losslessly. P12 preserves the C04 observation and enumeration coverage separately. P13 must not pass `knownAbsent` as limitation paths or discard either fact. Until C04/C05 owners approve a lossless admission interface or mapping, reject admission where those facts are needed and cannot be represented safely; never invent known absence or complete coverage. This unresolved cross-contract seam blocks dependent behavior requiring it.

Host policy bounds source, decoded document and output bytes, nodes/depth, parse work, acquisitions, candidate/evaluated rows, concurrent operations, runtime CEL cost, memory and deadline. Apply P01 policy limits and P07 catalog policy at their owners; hosts may lower, not silently raise them. P01 reference limits are not a claim of production measurements. `RESOURCE_LIMIT` reports exhausted work, `INVALID_REQUEST` malformed/type/non-Boolean input, `UNSUPPORTED` unavailable semantics, C02 access/source errors preserve safe codes, `CANCELLED` and `TIMEOUT` represent actual lifecycle termination. Cancellation is checked before admission, during source paging and native `ContextEval`, before output, and propagates to all acquired work. No failed or cancelled result is emitted as success.

## Independent behavior PRs and gates

- Compiler owner: real parse/resolve/check/compile, canonical typed bindings, P07 admission and bounded profile, with direct exercised behavior and tests; no fake planner or evaluator.
- Planner owner: capability-qualified native/local/hybrid acquisition and residual preservation, integrating the reviewed compiler and P12 candidate. Any SDK capability extension has its own reviewed additive PR and exact candidate pin.
- Finite execution owner: real admitted execution, global order/window/host cursors and lifecycle integration against pinned prior candidates. C08 integrates only after P13 interface review and C08 user approval; no placeholder follow stream.

These are ownership locks, not permission to implement before reviewer-approved P12/P13 interfaces and user-approved C05. Each behavior PR must have real useful behavior, tests and an executable smoke, independent review before expensive CI, exact reviewed candidate revisions, and no shims. The integration owner coordinates shared files and rebases after predecessor merges. Final packet acceptance still requires merged predecessors, required CI and live evidence.

Review must challenge candidate-superset proofs, masking/coverage ordering, cross-epoch access isolation, P12 observation atomicity, bounded stalled-consumer termination, exact numeric/correlation behavior, global paging across source pages and stale-row treatment. Required acceptance includes the independent P44 matrix and actual source→admission→CEL→window integration, cancellation, partial/denial and 300/3000/30000 acquired/evaluated/delivered work and memory measurements. No such verification is claimed by this specification.
