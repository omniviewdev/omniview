# P12 active-scope read model contract

Status: proposed for independent review; not approved or implemented. This contract depends on the C04 user-approved source wire and P12 independent interface review. Candidate source types below are C04-owned and must be reconciled with its approved revision before implementation. Issue: https://github.com/omniviewdev/omniview/issues/86.

## Ownership and existing boundary

P12 owns `backend/pkg/plugin/resource/readmodel` and the one host object store and source-interest coordinator behind it. P13 consumes snapshots; P14 consumes interests and revision invalidations. Neither owns another object store or acquisition coordinator. C04 owns source transport, wire types, admission and terminal delivery. P12 owns application, staging, membership and lifecycle. The accepted source-session contract sections 3–6 controls source semantics; P45 `resource/v2` supplies address, reference, route and normalized scope types.

Today `controller` constructs `registry.MemoryStore` and the graph indexer and dispatcher. Registry keys are plugin, connection and `CanonicalAddressKey`; entries contain reference and metadata, not a bounded object body. `engineWatchSink` validates plugin generation under `pluginsMu` before registry mutation and dispatches graph events. The dispatcher is a shared sequential queue. P12 extends/replaces this ownership, reuses applicable registry metadata indexes, and migrates the sink and callers; it must not build expensive indexes on that dispatcher. Controller plugin `generationID` and `sourceEpoch` are not source sequence or query-result generation.

## Exported host contract

The following is the proposed complete cross-packet Go interface, not a second wire ABI. `resourcev2` denotes `github.com/omniviewdev/plugin-sdk/pkg/resource/v2`. C04 owns `SourceOpen`, `SourceFrame`, `SourceObservation`, and `SourceChange`. In particular, no caller constructs an alternative frame or converts JSON numbers through float64.

```go
package readmodel

import (
    "context"
    "errors"
    "time"

    resourcev2 "github.com/omniviewdev/plugin-sdk/pkg/resource/v2"
)

type InterestKind string
const (
    InterestQuery   InterestKind = "query"
    InterestGraph   InterestKind = "graph"
    InterestSearch  InterestKind = "search"
    InterestUtility InterestKind = "utility"
)

// BindingID is a host-issued opaque identity for one admitted acquisition.
// It is not a client-supplied authorization assertion or a hash supplied by UI.
type BindingID string
type Binding struct {
    ID          BindingID
    Open        resourcev2.SourceOpen
    AccessEpoch string
}
type Attempt struct {
    BindingID  BindingID
    SessionID  string
    Generation string
    AccessEpoch string
}

type CoverageState string
const (
    CoverageComplete CoverageState = "complete"
    CoveragePartial  CoverageState = "partial"
    CoverageUnknown  CoverageState = "unknown"
)
type Coverage struct {
    State       CoverageState
    Consistency string // C04 source consistency, not inferred from State
    Continuity  string // C04 continuity, not inferred from sequence
    Limitations []string
}
type Freshness struct {
    Mode          string // snapshot or snapshotAndUpdates
    ObservedAt    time.Time // host boundary time, not provider ordering
    LastRefreshAt time.Time // zero until a successful snapshot boundary
    Synchronized  bool
}
type Watermark struct {
    Epoch    string // host-issued, changes on invalidation/eviction/recreation
    Revision uint64 // monotonic within Epoch; never compared across epochs
}
type Provenance struct {
    BindingID   BindingID
    SessionID   string
    Generation  string
    SourceRevision *string // opaque; never ordered
}
type Row struct {
    AddressKey  string // registry.CanonicalAddressKey(address)
    Observation resourcev2.SourceObservation
    Provenance  Provenance
    Stale       bool
}

type Snapshot interface {
    Revision() Watermark
    Coverage() Coverage
    Freshness() Freshness
    Range(context.Context, func(Row) error) error
}

type Interest interface {
    View(context.Context, func(Snapshot) error) error
    Changes() <-chan struct{}
    Refresh(context.Context) error
    Close() error
}

type Manager interface {
    Acquire(context.Context, Binding, InterestKind) (Interest, error)
    Begin(context.Context, Binding, Attempt) error
    Apply(context.Context, Attempt, resourcev2.SourceFrame) error
    End(context.Context, Attempt, error) error
    InvalidateAccess(context.Context, BindingID, string) error
}

var (
    ErrInvalid       = errors.New("readmodel: invalid input")
    ErrDenied        = errors.New("readmodel: access denied or invalidated")
    ErrStaleAttempt  = errors.New("readmodel: stale attempt")
    ErrLimit         = errors.New("readmodel: capacity exceeded")
    ErrClosed        = errors.New("readmodel: interest closed")
    ErrUnavailable   = errors.New("readmodel: source unavailable")
    ErrResetRequired = errors.New("readmodel: source reset required")
)
```

The controller constructs `Binding` only after authority, operation, effective selection, representation/schema and credentials are admitted. `ID` identifies that exact immutable binding, including native request, plugin and route, effective normalized scope, representation/schema, access/visibility epoch and required source guarantees. The same ID must never identify different bindings; the manager rejects collisions. No selection-subsumption or cross-credential sharing is implied. The caller must not mutate `Open` while retained; the manager owns immutable admitted data. `AccessEpoch` is an opaque host-issued value, not a provider field or client authority. `Attempt` must match `Binding.Open` session/generation and access epoch exactly. The coordinator issues a fresh attempt for every restart; no generation is reused.

`Acquire` reserves one independently closeable interest, starts or joins only the exact compatible binding, and rolls back the reservation on failure or cancellation. The acquire context bounds the call, not the lifetime of a successful interest. `Close` is idempotent and releases exactly one reservation, including a pending open; a closed interest cannot be used. The final close atomically retires the binding, cancels acquisition, removes staging, rows and membership, and advances its host epoch before any late callback can mutate state. Other kinds and other bindings remain live. The coordinator owns provider handles; an interest is not a provider handle. An acquired interest can observe a pending acquisition with unknown coverage and unsynchronized freshness.

`View` supplies a coherent published revision, coverage, freshness and row set for the binding. `Range` propagates callback and context errors. Rows and nested data are immutable borrowed values valid only during the callback; consumers copy only what they explicitly retain. The implementation must enforce that callers cannot mutate published state. `View` must not hold a global lock across arbitrary callbacks or block unrelated bindings; use bounded revision pinning or equivalent. Pins, concurrent views, staging, current and stale rows all count toward explicit byte and item budgets. A caller that cannot obtain a bounded coherent view receives `ErrLimit`; no full-map cloning or unbounded retained revision history is allowed. One callback sees no half-applied batch or cutover. `Watermark.Revision` advances for every visible row, coverage, freshness or synchronization change; overflow retires the epoch rather than wrapping.

`Changes` returns the same interest-owned channel on each call. It is an edge-triggered invalidation, not a delta stream: at most one notification is pending, and notifications may coalesce. Subscribe by obtaining the channel before the first `View`, then re-read a coherent view after every notification. A change concurrent with a view must leave a notification pending or be reflected in that view; no lost wakeup. `Close` closes the channel. Access invalidation also closes affected channels after clearing protected material; a subsequent view returns `ErrDenied`. P14 produces its own result sequence and consumer-local recovery; a P12 watermark or source generation is never a result generation.

`Refresh` requests a new host-issued generation for this binding. For snapshot-only sources, successful snapshot end is the last refresh time; freshness is explicitly snapshot-only and becomes unsynchronized on invalidation. There is no automatic generic poller. Concurrent refreshes may join the same in-flight attempt; cancellation of one waiter must not cancel work held by other interests. A canceled waiter receives its context error. Provider-specific managed polling may exist behind a C04 adapter and is not represented as a host freshness guarantee. No automatic retries without a bounded explicit policy.

## Ingress, cutover and isolation

C04 validates transport framing, encoding and limits before ingress. The coordinator calls `Begin` with the admitted immutable `SourceOpen` and fresh attempt, then `Apply` for each C04 `SourceFrame`, and `End` on transport completion, cancellation or failure. `End` is idempotent for the same retired attempt and does not signal success after unexpected EOF. Snapshot-mode `snapshotEnd` completes normally; update mode remains active after its boundary. Reset or failed is terminal. `Apply` independently checks current binding, access epoch, session, generation, contiguous sequence and legal phase before mutation. A gap, duplicate, invalid phase, malformed scope/representation, unsupported binding, overflow or unexpected EOF discards staging, marks the published source unsynchronized and requires a fresh attempt. A late callback returns `ErrStaleAttempt` and has no effects. Terminal/control delivery must not depend on available data-queue space. C04 owns its wire and preallocation limits; P12 independently enforces finite configured positive limits for active bindings, retained and staging bytes and items, pins, and pending work. Exceeding a limit fails or resets explicitly, never silently drops a row.

Stage snapshot observations by canonical address within the exact binding and attempt. Repeated snapshot addresses replace only that attempt's staged entry in delivered order. No staging row is current before successful `snapshotEnd`. At the boundary publish one atomic replacement. Map C04 exhausted enumeration to complete, partial to partial, and unknown to unknown; do not infer point-in-time consistency from exhaustion or gap-free continuity from sequence. Coverage applies only to this exact acquisition, including native selector and visibility. Document completeness remains per observation, independent of source coverage.

For a complete replacement, retire unseen membership only for this bound source; do not delete another binding's membership or body. For partial or unknown replacement, retain unseen old observations only as separately stale rows with their original source provenance. Do not promote them to current, assign them the new generation, or claim deletion. Current and stale rows must be distinguishable even when another source has the same address. A subsequently observed address replaces its own old membership; preserve other source memberships. There is no global last-arrival-wins across streams and no sorting opaque source revisions or timestamps. When a consumer needs a single compatible row and different sources disagree without proven ordering, report unavailable/reset rather than silently select a newer value. Change batches are atomic in source order. Remove affects only that binding's membership; an incarnation-qualified remove cannot remove a known different incarnation. No invented recreation identity.

`Begin`, `Apply`, `End`, refresh, final close and invalidation serialize their commit checks with the relevant binding mutation. Validation done outside the lock is rechecked at commit. New generation publication cannot be overwritten by old callbacks or delayed refreshes. Cancellation before commit has no effects; after a committed batch the batch remains atomic and cancellation terminates subsequent work. `InvalidateAccess(ctx, id, oldEpoch)` invalidates only the matching epoch, atomically retires all attempts and interests for it, clears current/stale/staging bodies and metadata that disclose protected data, then notifies/terminates consumers. A stale invalidation cannot clear a newer access epoch. Known access revocation never retains stale rows. Disconnect, binding/schema change and provider failure mark affected state unsynchronized or invalidate it according to the source contract; unrelated interests remain intact.

Errors use the sentinels above with `errors.Is`; operation cancellation and deadline return the original `context` errors. Invalid input includes invalid identity, malformed frame or mismatched immutable binding; rejected access uses `ErrDenied`; stale attempt uses `ErrStaleAttempt`; bounded capacity uses `ErrLimit`; source continuity loss uses `ErrResetRequired`; unavailable provider uses `ErrUnavailable`. The coordinator maps C04 failures without erasing their reviewed error category. Failed staging never publishes partial state as complete. No raw-object disk persistence, permanent all-provider replication, mandatory watch, generic poller, full-map snapshot clone, or production transcript history is permitted.

## Behavior PRs and locks

All work starts only after independent review of this interface and explicit C04 user approval. Pin the exact reviewed C04 SDK/host candidate and P12 contract commit in every PR. Integrate and rebase candidates after predecessor merges; only the user merges.

1. **Store and staging:** owner locks `backend/pkg/plugin/resource/readmodel` store/staging files and associated tests, plus `registry` changes it needs. Deliver real bounded stage, atomic cutover, metadata-index reuse, provenance and complete/partial/unknown behavior using the approved ingress. Tests cover scope isolation, limits, concurrent views, replacement, incarnation and stale attempts. This PR must have executable behavior, not placeholder methods.
2. **Interest coordination:** separate owner locks coordinator/interest files and tests in `readmodel`, using the frozen API and pinned store candidate. Deliver real acquisition reservations, refresh, notifications, last-interest eviction, access invalidation and independent consumer lifecycle. Race tests cover pending open cancellation, refresh/close/invalidation, no lost notifications and generation rejection. Coordinate file ownership; do not create a second store.
3. **Live integration:** integration owner alone locks `controller.go`, `sink.go`, `indexer`, graph/consumer wiring and integration tests, using both pinned candidates and the C04 candidate. Route real C04 sessions through the manager; migrate existing registry/indexer callers without a duplicate event path. Prove complete, partial and unknown P44 finite/event profiles, snapshot-only freshness, disconnect/reload, independent interests, and current/stale provenance through the real path. No fixture-only or forwarding mock proof. Existing graph behavior remains useful and no expensive index construction runs on the sequential dispatcher.

Each behavior PR includes focused tests and an executable smoke, reviewed before expensive CI. Integration ownership resolves shared files and final candidate pins. Packet acceptance additionally requires race tests, heap/retention/update measurements at 300/3000/30000 against P02, and native/source evidence as required by issue #86. No such evidence or approval is claimed by this spec.
