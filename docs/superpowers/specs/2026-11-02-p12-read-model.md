The user-approved [C04 freeze at 3607fe1fd162159c67457abd71ee61d64de6a2fa](https://github.com/omniviewdev/omniview/blob/3607fe1fd162159c67457abd71ee61d64de6a2fa/docs/superpowers/specs/2026-11-02-c04-source-session-wire.md) supersedes the earlier C04 candidate `28aba733f2ec2768d501e920925bc8cdae02e2a9`. P05 was subsequently integrated in host PR #350 and bounded in [host PR #383](https://github.com/omniviewdev/omniview/pull/383), merged at `66853ab7ff2e65114c80231a1cce1afc6d97832f`; its old candidate pins are historical, not the integration baseline. ## Ownership and existing boundary

P12 owns the one host object store and source-interest coordinator. Evolve or extract the existing P05 `sourceCoordinator` in `backend/pkg/plugin/resource/source_coordinator.go` and its `sourceSession`, rather than instantiate a parallel coordinator or store. `readmodel.Manager` below is the consumer-facing facade or extracted ownership of that same coordinator, not another acquisition lifecycle. P13 consumes snapshots; P14 consumes interests and revision invalidations. C04 owns source transport, wire types, admission and terminal delivery. P12 owns application, staging, membership and lifecycle. The accepted source-session contract sections 3–6 controls source semantics; P45 `resource/v2` supplies address, reference, route and normalized scope types.

The host controller constructs `registry.MemoryStore`, the graph indexer and dispatcher. Registry keys are plugin, connection and `CanonicalAddressKey`; entries contain reference and metadata, not a bounded object body. The old `engineWatchSink` and `sink.go` no longer exist. Existing source application and registry/indexer paths are the migration boundary, including their generation and epoch fencing; do not restore the obsolete sink. The dispatcher is a shared sequential queue. P12 reuses applicable registry metadata indexes and must not build expensive indexes on that dispatcher. Controller plugin `generationID` and `sourceEpoch` are not source sequence or query-result generation.
The P05 candidate's `source_session.go` already holds bounded canonical-key `members` and generation `staging`, while `source_coordinator.go` holds shared sessions, reservations and views. Reuse and evolve those mechanisms under the existing owner's handoff. Its current snapshot cutover replaces `members` even for partial/unknown coverage, and its `source_apply.go` deletes from the shared registry without source-membership isolation: neither behavior can remain in the P12 cutover. Its renderer-facing `source_view.go` creates a per-view full snapshot slice; it is not the P12 bounded coherent view. Its timed retries must be reconciled with the P12 recovery policy below. Existing state/status and generation checks are starting points, not proof of P12 acceptance.
Until P15 migration, `sourceView` and `HostSourceViewEvent` remain only the existing runtime bridge required by C04, owned by the P12 integration slice; P15 removes that bridge. They are not the P12 consumer interface or a second result wire. P12 query/graph/search/utility consumers use `Manager`/`Interest`. Existing source-state events and their aggregate ranks may report honest session and interest status; they must never reconstruct the removed per-type ADD/UPDATE/DELETE events. Existing timed backoff is replaced, not layered alongside P12 recovery.

## Exported host contract

The following is the proposed complete cross-packet Go interface, not a second wire ABI. `resourcev2` denotes `github.com/omniviewdev/plugin-sdk/pkg/resource/v2`. C04 owns `SourceOpenRequest`, `SourceFrame`, `SourceObservation`, and `SourceChange`. In particular, no caller constructs an alternative frame or converts JSON numbers through float64.
P12 preserves the C04 tagged `resourcev2.Value` document, original P45 record `Coverage`, and independent typed `knownAbsent` facts without conflating either with source enumeration coverage. The P13/C05 admission mapping consumes those facts under their own reviewed contracts.

```go
package readmodel

import (
    "context"
    "errors"
    "time"

    resourcev2 "github.com/omniviewdev/plugin-sdk/pkg/resource/v2"
)

type InterestKind string
const (
    InterestQuery   InterestKind = "query"
    InterestGraph   InterestKind = "graph"
    InterestSearch  InterestKind = "search"
    InterestUtility InterestKind = "utility"
)

// BindingID is a host-issued opaque identity for one admitted acquisition.
// It is not a client-supplied authorization assertion or a hash supplied by UI.
type BindingID string
type Binding struct {
    ID          BindingID
    Selection   resourcev2.SourceOpenRequest
    Owner       string
    AccessEpoch string
}
// NewBinding validates the admitted selection and computes its host-only identity.
func NewBinding(selection resourcev2.SourceOpenRequest, owner, accessEpoch string) (Binding, error)

type Limits struct {
    ActiveBindings, ActiveInterests, RetainedItems, StagingItems, PendingItems int
    RetainedBytes, StagingBytes, PendingBytes int64
    ConcurrentViews, DirtyKeys int
}
// SourceOpener is the host controller's admitted-route port, not a provider ABI.
type SourceOpener interface {
    OpenSource(context.Context, Binding, resourcev2.SourceOpenRequest) (resourcev2.SourceStream, error)
}
func NewManager(SourceOpener, Limits) (Manager, error)

type CoverageState string
const (
    CoverageComplete CoverageState = "complete"
    CoveragePartial  CoverageState = "partial"
    CoverageUnknown  CoverageState = "unknown"
)
type Coverage struct {
    State       CoverageState
    Consistency string // C04 source consistency, not inferred from State
    Continuity  string // C04 continuity, not inferred from sequence
    Limitations []string
}
type Freshness struct {
    Mode          string // snapshot or snapshotAndUpdates
    ObservedAt    time.Time // host boundary time, not provider ordering
    LastRefreshAt time.Time // zero until a successful snapshot boundary
    Synchronized  bool
}
type Watermark struct {
    Epoch    string // host-issued, changes on invalidation/eviction/recreation
    Revision uint64 // monotonic within Epoch; never compared across epochs
}
type Provenance struct {
    BindingID   BindingID
    SessionID   string
    Generation  string
    SourceRevision *string // opaque; never ordered
}
type Row struct {
    AddressKey  string // registry.CanonicalAddressKey(address)
    Observation resourcev2.SourceObservation
    Provenance  Provenance
    Stale       bool
}
type ChangeCause string
const (
    ChangeUpsert ChangeCause = "upsert"
    ChangeStaled ChangeCause = "staled"
    ChangeRemoved ChangeCause = "removed"
    ChangeRetired ChangeCause = "retired"
)
type Change struct {
    AddressKey string
    Cause ChangeCause
    Provenance Provenance
    IncarnationChanged bool
}

type Snapshot interface {
    Revision() Watermark
    Coverage() Coverage
    Freshness() Freshness
    Err() error
    Get(addressKey string) (Row, bool)
    Changed(since Watermark, visit func(Change) error) error
    Range(context.Context, func(Row) error) error
}

type Interest interface {
    View(context.Context, func(Snapshot) error) error
    Changes() <-chan struct{}
    Refresh(context.Context) error
    Close() error
}

type EpochRetirement string
const (
    EpochRevoked EpochRetirement = "revoked"
    EpochTransitioned EpochRetirement = "transitioned"
)
type Manager interface {
    Acquire(context.Context, Binding, InterestKind) (Interest, error)
    InvalidateEpoch(context.Context, string, EpochRetirement) error
}

var (
    ErrInvalid       = errors.New("readmodel: invalid input")
    ErrUnsupported   = errors.New("readmodel: unsupported")
    ErrDenied        = errors.New("readmodel: access denied or invalidated")
    ErrStaleAttempt  = errors.New("readmodel: stale attempt")
    ErrLimit         = errors.New("readmodel: capacity exceeded")
    ErrClosed        = errors.New("readmodel: interest closed")
    ErrUnavailable   = errors.New("readmodel: source unavailable")
    ErrResetRequired = errors.New("readmodel: source reset required")
)
```

The host resource controller implements P13's `SourceBinder`, binding an admitted `resourcev2.ReadTarget`, principal and acquisition to a P12 `Binding` after authority, operation, effective selection, representation/schema and credentials are admitted. `Selection` is the admitted C04 `SourceOpenRequest` with `SessionID` and `Generation` empty; it retains selection, acquisition, representation binding and wire limits. It has no request ID. `Owner` is `invocation.Principal.Owner()` derived by the controller, never a client claim. `NewBinding` rejects nonempty attempt tokens and computes `ID` from a collision-resistant canonical encoding of owner, the complete selection, access epoch and guarantees. The manager validates the binding again and rejects ID collisions; IDs do not grant authorization. Exact compatible bindings share, never across principals or credentials. The host uses one process-wide `TrustedUI` realm, so UI tabs and windows share that principal and may share one source; C08 independently owns per-window lease lifetime. The coordinator retains immutable selection, mints fresh session and generation tokens per attempt and assembles the actual `SourceOpenRequest`; restart and refresh preserve binding and interests. `AccessEpoch` is the canonical, unambiguous text encoding of controller `catalogAdmission`'s `{PluginID, Generation, Connection, Epoch}` route identity, also used by C05; it is host-issued, never supplied by clients. Controller route epoch retirement, including `connection_change.go` and `invalidateProfileRoutes`, invokes `InvalidateEpoch` for the retired value.

`Acquire` atomically reserves one independently closeable interest against the finite `ActiveInterests` budget before starting or joining only the exact compatible binding. Every pending or live interest consumes one reservation, including interests sharing a binding and those with empty dirty sets; exhaustion returns `ErrLimit`. Failed or cancelled acquisition rolls back its reservation. The acquire context bounds the call, not the lifetime of a successful interest. `Close` is idempotent and releases exactly one reservation, including a pending open; a closed interest cannot be used. The final close atomically retires the binding, cancels acquisition, removes staging, rows and membership, and advances its host epoch before any late callback can mutate state. Other kinds and other bindings remain live. The coordinator owns provider handles; an interest is not a provider handle. An acquired interest can observe a pending acquisition with unknown coverage and unsynchronized freshness.

`View` supplies a coherent published revision, coverage, freshness and row set for the binding. `Range` propagates callback and context errors. Rows and nested data are immutable borrowed values valid only during the callback; consumers copy only what they explicitly retain. The implementation must enforce that callers cannot mutate published state. `View` must not hold a global lock across arbitrary callbacks or block unrelated bindings; use bounded revision pinning or equivalent. Pins, concurrent views, staging, current and stale rows all count toward explicit byte and item budgets. A caller that cannot obtain a bounded coherent view receives `ErrLimit`; no full-map cloning or unbounded retained revision history is allowed. One callback sees no half-applied batch or cutover. `Watermark.Revision` advances for every visible row, coverage, freshness or synchronization change; overflow retires the epoch rather than wrapping.
`Get` retrieves a current or explicitly stale row for one canonical address in the same snapshot. `Changed` is valid inside `View` and reports the final change per address since that interest's last acknowledged revision: `upsert` means current membership, `staled` means partial/unknown replacement left the original row unseen or continuity loss marked it stale, `removed` means an explicit source remove, and `retired` means complete replacement omitted the membership. Neither removed nor retired proves infrastructure deletion. Provenance belongs to the affected membership; `IncarnationChanged` is true only when both old and new incarnations are known and unequal. Last cause wins: upsert then staled is staled; staled then upsert is upsert; staled then removed/retired is that absent cause; removed/retired then upsert is upsert. An already absent key cannot become staled or change between removed and retired. An incarnation-qualified remove naming a different known incarnation has no effect or change. Epoch invalidation does not produce these change causes. Callback errors propagate.

Each interest owns a bounded dirty-key set charged to its budgets. A new interest starts reset-required without an acknowledged revision; a complete `Range` and successful enclosing `View` establish its initial baseline. `since` must equal the interest's last acknowledged revision, not merely its last viewed revision. A successful `Changed` and successful enclosing `View` acknowledge only changes through that snapshot's revision; later concurrent changes remain dirty and notified. On epoch mismatch, an invalid `since`, overflow or an oversized cutover, `Changed` returns `ErrResetRequired`. A complete `Range` and successful enclosing `View` establish that snapshot's revision as the new baseline and clear dirty state only through that revision. If overflow or an oversized cutover occurs after that snapshot's revision, the interest remains reset-required: the successful older range cannot acknowledge lost later changes. A failed callback, failed range or failed view acknowledges nothing. Serialize concurrent views on one interest or provide equivalent ordered acknowledgements so an older view cannot erase newer state. Coverage/freshness-only revisions still notify even when `Changed` returns no keys. No raw bodies or unbounded history are retained.

`Changes` returns the same interest-owned channel on each call. It is an edge-triggered invalidation, not a delta stream: at most one notification is pending, and notifications may coalesce. Subscribe by obtaining the channel before the first `View`, then re-read a coherent view after every notification. A change concurrent with a view must leave a notification pending or be reflected in that view; no lost wakeup. `Close` closes the channel. Epoch invalidation also closes affected channels after clearing protected material; subsequent `View` returns `ErrDenied` for revocation or `ErrResetRequired` for transition requiring rebind. P14 produces its own result sequence and consumer-local recovery; a P12 watermark or source generation is never a result generation.

`Refresh` requests a new host-issued generation for this binding. For snapshot-only sources, successful snapshot end is the last refresh time; freshness is explicitly snapshot-only and becomes unsynchronized on invalidation. There is no automatic generic poller. Concurrent refreshes may join the same in-flight attempt; cancellation of one waiter must not cancel work held by other interests. A canceled waiter receives its context error. Provider-specific managed polling may exist behind a C04 adapter and is not represented as a host freshness guarantee. With live interests, P12 starts at most one automatic fresh attempt per unhealthy episode after a successful snapshot end, for actual source continuity loss: recoverable reset, locally detected gap, duplicate or queue overflow, or unexpected EOF while following. Failures before snapshot end, including recovery-attempt failure, are sticky until explicit `Refresh` or rebind. Binding-change reset requires rebind; denied, unsupported, invalid and limit failures are not automatically retried. The automatic-recovery allowance resets only on explicit refresh/rebind or when a generation has stayed synchronized for at least 30 seconds, checked using a monotonic clock on the next failure. There is no timer, backoff loop or poller. Result-consumer overflow never reopens a healthy source. All limits must be positive and finite and must not exceed the final C04 ceiling. The 30,000 ConfigMap fixture also contains `kube-root-ca.crt`, so its 30,001 objects require a suitably raised approved cap or a synthetic fallback; do not silently truncate.

## Ingress, cutover and isolation

C04's existing `resourcev2.SourceStreamOpener` exposes `OpenSourceStream(context.Context, SourceOpenRequest) (SourceStream, error)`; `SourceStream` exposes `Recv() (SourceFrame, error)` and `Close()`. C04 validates transport framing, encoding and limits before returning frames. P12 evolves the existing host coordinator, privately beginning an attempt, receiving and applying frames, and ending it on stream completion, cancellation or failure. Snapshot-mode `snapshotEnd` completes normally; update mode remains active after its boundary. Reset or failed is terminal. P12 independently checks current binding, access epoch, session, generation, contiguous sequence and legal phase before mutation. A gap, duplicate, invalid phase, malformed scope/representation, unsupported binding, overflow or unexpected EOF discards staging and marks the published source unsynchronized; recovery follows the bounded policy above. Late callbacks have no effects. Terminal/control delivery does not depend on data-queue space. Every opener, including an approved old-SDK adapter, passes the same C04 validator and limits; the coordinator revalidates every frame regardless of producer.
The process-wide manager calls the host-owned `SourceOpener` with the admitted `Binding` and attempt request, not a plugin-specific opener. The controller resolves `Binding.AccessEpoch` as its host-issued `{PluginID, Generation, Connection, Epoch}` route identity, validates the binding and request against that route and selection, selects the negotiated native source or supported legacy adapter, and fences plugin generation, catalog and access epoch before opening. The selected provider's C04 `SourceStreamOpener` receives the request only after that admission. It must not route solely by a client-supplied target or silently fall back across providers. The existing coordinator's `prepare` path is the integration starting point.
P12 independently enforces finite configured positive limits for active bindings, retained and staging bytes and items, pins, dirty keys and pending work. Exceeding a limit fails or resets explicitly, never silently drops a row. `Close()` must unblock a concurrently blocked `Recv()`, and canceling the `OpenSourceStream` context must end `Recv`; final close and eviction obey C04's five-second cleanup bound.
Locally detected representation-reference mismatch against the admitted binding, including schema-revision presence, is `bindingChanged`: `ErrResetRequired` with rebind-required cause, never an automatic retry or `ErrInvalid`. Structurally malformed references remain `ErrInvalid`.

Stage snapshot observations by canonical address within the exact binding and attempt. Repeated snapshot addresses replace only that attempt's staged entry in delivered order. No staging row is current before successful `snapshotEnd`. At the boundary publish one atomic replacement. Map C04 exhausted enumeration to complete, partial to partial, and unknown to unknown; do not infer point-in-time consistency from exhaustion or gap-free continuity from sequence. Coverage applies only to this exact acquisition, including native selector and visibility. Document completeness remains per observation, independent of source coverage.

For a complete replacement, retire unseen membership only for this bound source; do not delete another binding's membership or body. For partial or unknown replacement, retain unseen old observations only as separately stale rows with their original source provenance. Do not promote them to current, assign them the new generation, or claim deletion. Current and stale rows must be distinguishable even when another source has the same address. A subsequently observed address replaces its own old membership; preserve other source memberships. There is no global last-arrival-wins across streams and no sorting opaque source revisions or timestamps. When a consumer needs a single compatible row and different sources disagree without proven ordering, report unavailable/reset rather than silently select a newer value. Change batches are atomic in source order. Remove affects only that binding's membership; an incarnation-qualified remove cannot remove a known different incarnation. No invented recreation identity.

Attempt begin, apply, end, refresh, final close and invalidation serialize their commit checks with the relevant binding mutation. Validation done outside the lock is rechecked at commit. New generation publication cannot be overwritten by old callbacks or delayed refreshes. Cancellation before commit has no effects; after a committed batch the batch remains atomic and cancellation terminates subsequent work. `InvalidateEpoch(ctx, oldEpoch, reason)` atomically retires every binding and attempt with that exact route epoch, clears current/stale/staging bodies and protected metadata, then closes notifications. It cannot clear a newer epoch. For `revoked`, `View` returns `ErrDenied`; for `transitioned`, it returns `ErrResetRequired` with a rebind-required cause and consumers rebind through the controller. Credential/profile revocation is revoked; plugin reload, reconnect or another route change is transitioned; uncertainty defaults to revoked. Neither retains stale rows nor produces membership changes. Unrelated interests remain intact.

Errors use the sentinels above with `errors.Is`; operation cancellation and deadline return the original `context` errors. Invalid input includes invalid identity, malformed frame or mismatched immutable binding; rejected access uses `ErrDenied`; stale attempt uses `ErrStaleAttempt`; bounded capacity uses `ErrLimit`; source continuity loss uses `ErrResetRequired`; unavailable provider uses `ErrUnavailable`. The coordinator maps C04 failures without erasing their reviewed error category. Failed staging never publishes partial state as complete. No raw-object disk persistence, permanent all-provider replication, mandatory watch, generic poller, full-map snapshot clone, or production transcript history is permitted.
Except epoch invalidation, closed interests and context errors, `View` returns a snapshot even when acquisition failed: `Snapshot.Err()` is nil while healthy or pending (unknown coverage and unsynchronized freshness), otherwise it returns the sticky mapped terminal acquisition error. On continuity loss retained rows are marked stale and unsynchronized; revocation or transition clears them and `View` returns its corresponding terminal error. Closed interests return `ErrClosed`. Changes to error, coverage or freshness notify `Changes`.

C04 `SourceFailure.code` uses SDK/C02 codes. `INVALID_REQUEST`, `INVALID_INPUT`, `FILTER_UNKNOWN_FIELD` and `FILTER_INVALID_OPERATOR` map to `ErrInvalid`; `UNSUPPORTED` to `ErrUnsupported`; `FORBIDDEN`, `PERMISSION_DENIED`, `UNAUTHORIZED`, `GRANT_DENIED` and `DELEGATION_NOT_ACTIVE` to `ErrDenied`; `RESOURCE_LIMIT` to `ErrLimit`; `RESET_REQUIRED` to `ErrResetRequired`; and `UNAVAILABLE`, `CONNECTION_ERROR`, `CONNECTION_NOT_STARTED`, `OWNER_UNAVAILABLE`, `PROVIDER_ERROR` and `INTERNAL` to `ErrUnavailable`. For `NOT_FOUND`, `ALREADY_EXISTS`, `CONFLICT`, `TIMEOUT`, `CERTIFICATE_ERROR`, `CANCELLED`, `CONTINUATION_EXPIRED` and `PARTIAL_RESULT`, preserve the original classified C02 error without assigning a misleading P12 sentinel; consumers propagate its C02 code and recovery rather than converting it to `UNAVAILABLE`. Preserve the original C02 AppError for `errors.As`, including its code and recovery, for every mapping. A failed frame with an unknown code is invalid framing. Local context cancellation and deadline return their original context errors. C04 reset reasons `continuityLost`, `overflow`, `sourceInvalidated` and `bindingChanged`, locally detected continuity loss and unexpected EOF map to `ErrResetRequired`; `bindingChanged` additionally requires rebind. A failure code `RESOURCE_LIMIT` is not a reset reason `overflow`.

## Behavior PRs and locks

All dependent work starts only after independent review of this interface and final frozen-set review. C04 user approval is recorded in PR #346; it does not approve this revised P12 contract. C08 and P13 pin the independently approved `9fa5a527` candidate, not this proposal. Their owners must review compatibility and update their pins only after independent delta review; do not silently rewrite approved contracts or represent the new revision as approved. Pin the exact reviewed C04 SDK/host cohort and P12 contract commit in every behavior PR. Integrate and rebase candidates after predecessor merges; only the user merges.

1. **Store and staging:** after existing P05 ownership handoff, a store owner locks new extracted store/staging files and tests, plus agreed registry files. Build on the pinned P05 candidate's real members/staging semantics, with bounded storage, atomic cutover, metadata-index reuse, provenance and complete/partial/unknown behavior. Tests cover scope isolation, limits, concurrent views, replacement, incarnation and stale attempts. Deliver real executable behavior; no placeholder or second production store.
2. **Interest coordination:** after the store handoff, the coordinator owner locks `source_coordinator.go`, `source_session.go`, their binding/recovery helpers and associated tests. Evolve the existing coordinator to provide the approved interests, bounded dirty sets, refresh, notification, last-interest eviction, access invalidation and recovery. Use the actual C04 transport port and pinned store candidate; never add a second coordinator.
3. **Live integration:** integration owner coordinates those locks and alone owns `controller.go`, `source_apply.go`, `source_view.go`, `indexer`, graph/consumer wiring and integration tests. Cut over real C04 sessions through the evolved coordinator and migrate registry/indexer callers without a duplicate event path. Prove complete, partial and unknown P44 finite/event profiles, snapshot-only freshness, disconnect/reload, independent interests, and current/stale provenance through the real path. No fixture-only or forwarding mock proof. Existing graph behavior remains useful and no expensive index construction runs on the sequential dispatcher.

Each behavior PR includes focused tests and an executable smoke, reviewed before expensive CI. Integration ownership resolves shared files and final candidate pins. Packet acceptance additionally requires race tests, heap/retention/update measurements at 300/3000/30000 against P02, and native/source evidence as required by issue #86. No such evidence or approval is claimed by this spec.
