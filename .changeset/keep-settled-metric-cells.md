A metric cell that already settled without a sample no longer shows its loading placeholder again when its table's set of targets changes. `useTableMetricObservation` used to forget every answer whenever another row joined, so with a provider that returned nothing for a row, or was unreachable, each empty cell flipped from a gap to a placeholder and back on every growth or scroll step. `isLoadingFor` and the cells' `isLoading` now remember the request that completed last as the targets it asked for under each metric, whatever it answered. A cell stays settled while other targets are requested, a newly admitted row or metric still loads until a request that includes it answers, and a row that left the table loads again when it returns. An answer never crosses a change of plugin, connection, resource type, binding or source, nor a recreated resource that keeps its host token with a new incarnation. The table-level `isLoading` follows the same answers. Samples, and the invalidation and failure fences that clear them, are unchanged, and no export or signature changes.

`useMetricObservation` keeps one `Error` object while the host repeats the same failure under the same owner, binding and source, so a table's cells no longer all re-render for every repeated error frame. A frame without a failure still clears `error`, and a different message still replaces it.
